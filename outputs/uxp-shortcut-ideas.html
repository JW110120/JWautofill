UXP 快捷键与笔刷绑定：方案对比

针对「总开关全局快捷键 + 调整面板笔刷自定义绑定」的可行路径梳理。结论：UXP 无全局快捷键 API，但「画布焦点下触发」与「强制默认组合键」需分开处理。

问题拆解

UXP 插件的 DOM 键盘事件（keydown）只在插件面板获得焦点时生效，你说的「ctrl/shift/alt 修饰键只有在面板聚焦时才被识别」正是这个限制。而用户画图时焦点在画布（宿主），面板事件收不到。所以：

  • 目标一：总开关能在画布/面板任意焦点下触发 → 需要「宿主级」触发，而非面板 DOM 事件。
  • 目标二：调整面板里让用户把「笔刷 + 自定义快捷键」绑定 → 绑定配置本身在面板内完成即可，难点仍在「如何捕获全局按键」。

三条可行路线

官方·推荐先用

A. Manifest 命令 + 手动绑定

在 manifest.json 的 entrypoints 里用 type:"command" 注册命令，它会出现在「插件」菜单。用户在 编辑 > 键盘快捷键 > 插件 里手动把它绑到 Ctrl+Shift+R。

⚠️ manifest 的 shortcut 字段并未实现（官方文档原话：Shortcuts are not yet available for plugins）——写在 JSON 里不会生效，这正是你之前测试失败的原因，不是你写错。

  • 宿主级触发，画布焦点下也能用
  • 零额外二进制，纯 UXP，稳定
  • 无法代码强制默认快捷键，需用户手动绑定一次
  • 组合键受 PS 快捷键体系约束
现状·受限

B. 面板内 DOM 监听

在面板 window.addEventListener('keydown') 监听。即你现在的方案，修饰键仅在面板聚焦时识别。

  • 实现简单，无需额外进程
  • 面板不聚焦（画布/工具激活）时完全失效
  • 无法覆盖「画图途中」的场景
Hybrid·真全局

C. 原生伴生 + 本地通信

一个原生小程序（C++/Rust/Electron）在 OS 层注册全局热键，通过本地 socket/WebSocket 与 UXP 插件通信，触发插件动作。

  • 真正任意默认组合键，完全掌控
  • 不依赖 PS 快捷键体系
  • 需打包/分发原生二进制，维护成本高
  • 跨平台（Win/macOS）需分别实现

「Hybrid Plugin」到底是什么

论坛里说的 Hybrid，通常指 UXP 插件 + 一个原生宿主进程的组合：UXP 负责 UI 与 PS 交互，原生进程负责 UXP 做不到的底层能力（这里是全局热键）。二者通过本地 loopback（HTTP/WebSocket，UXP 自带 require('http') / require('ws')）通信。这不是官方 API，而是「把短板外包给原生代码」的架构模式。除非你必须强制某个默认键位，否则优先用 A。

笔刷绑定面板怎么落地

  • 配置存储：把「快捷键 → 笔刷预设」映射存进插件本地配置（如 localStorage 或项目下的 JSON）。
  • 捕获按键：在面板内让用户「按下组合键」录制；真正触发时仍依赖上面的 A 或 C 通道。
  • 应用笔刷：用 batchPlay 切换当前工具/笔刷预设（设置 current tool + brush，或 app.activeDocument 相关 action），无需视觉识别。

关于「MAA 视觉识别」能否解决

MAA（明日方舟的 MaaAssistantArknight）靠模板匹配/特征识别去「看」界面并自动点击，本质是输出动作（视觉 → 点击）。它并不擅长「捕获全局键盘输入」——它的输入也是模拟点击而非捕获按键。

  • 不适合：视觉识别无法解决「监听全局快捷键」这个输入问题，那是 OS 输入层的活儿。
  • 可借鉴的点：若你需要确认「当前用的是哪支笔刷/哪个工具」，与其截图识别，不如直接读 PS 的 API（action 描述符里的 tool/brush 信息），比视觉更稳更快。
  • 潜在组合：Hybrid 原生进程负责全局热键 + 用截图/视觉做「上下文感知」（例如仅在某一图层类型下触发），但这是锦上添花，不是核心解法。

推荐路径

先用 A（manifest 菜单命令）把总开关做成宿主级命令，引导用户在 PS 快捷键面板里绑 Ctrl+Shift+R——这是成本最低、最稳、能通过审核的方案。笔刷绑定面板的「录制 + 映射存储 + batchPlay 切换」逻辑照常开发。

只有当「必须代码强制默认快捷键、且不能依赖用户手动绑」时，再上 C（原生 Hybrid）。MAA 式视觉识别在这里不是必要能力，PS 自身 API 已经能拿到工具/笔刷状态。

未决风险：A 方案无法强制默认键位，若你的用户重度依赖「开箱即用」的默认键，则需要 C。需要我帮你写 A 的 manifest 片段和 batchPlay 切换笔刷的样例代码吗？
