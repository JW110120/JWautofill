# 笔迹回放：让 PS 的笔刷自己长出「阴影 + 高光」

日期：2026-10-22 ｜ 状态：**已定向，待开工** ｜ 前置：`docs/brush-p3-lightness-2026-10-22.md`

---

## 0. 一句话

用户拍板走「插件回放第二遍」。它要解决的不是画质，是**图层结构**问题：
凡是给用户加图层/加图层样式的做法，在**图层蒙版**上都画不出同样效果。
唯一能在蒙版上成立的方案，是让第二遍也是**真实的笔触**。

---

## 1. 为什么只能是这条路（结论已定，不再重复论证）

PS 的一个笔尖印章 = **一个颜色 × 一个蒙版**：印章内部所有像素颜色完全相同（= 前景色），
笔尖灰度只决定"盖多少"。所以在白底上画白 = 白盖白，物理上看不见。
Krita 的印章 = 「前景色色相 × 笔尖 R 通道亮度」× alpha，能写出暗色。

⇒ 要让同一笔出现两种亮度，只能让同一位置被盖两次、两次颜色不同。
⇒ 两次都必须是真实落笔（脚本画不出自由笔迹），所以第二遍只能**由插件替用户落笔**。

## 2. 现状盘点（2026-10-22 代码侦察，带行号）

### 2.1 已具备：把伪造包喂成真笔触

| 能力 | 位置 |
| --- | --- |
| 控制 `WTPacketsGet` 的返回包数与缓冲内容 | `native/JWautofillHost/smooth_engine.c:4551`（`det_WTPacketsGet`） |
| 按 CALIB 偏移逐字段写 time / changed / serial / buttons / x / y / pressure | `smooth_engine.c:3094-3148`（`penraw_synth`） |
| 单包底本克隆，未知字段保持合法 | `g_tpl`，`smooth_engine.c:2030` |
| 落笔/抬笔判定、buttons 边沿去抖、起笔锚定 | `smooth_engine.c:699` / `3548` / `3589` |
| 代投 `WT_PACKET` 唤醒 PS | `smooth_engine.c:2726` |
| 参数双向通道（WS 18924 + 58 槽共享内存） | `plugin_main.c:472` / `288` |

`pkChanged` / `pkSerialNumber` / `pkTime` 三个坑均已踩平并有注释佐证（`smooth_engine.c:3098-3129`）。

### 2.2 缺失：录制、播放源、压感、时序、协议 —— 四块全空

1. **没有笔迹账本**。`g_riRing` 只有 512 条（≈2 秒）、6 字段，且真机下 `x/y` 是**屏幕光标像素**、
   `p` 恒 0（`smooth_engine.c:2670`）。没有任何"按下开始录 / 抬起结束存一段"的代码。
2. **没有回放源接入点**。`penraw_synth` 唯一输入是 `g_riRing` + `g_synHead` 游标，没有第二数据源。
3. **补流的触发门与回放语义冲突**：只在 `r == 0 && realAge >= 250ms` 时伪造，即"先假装驱动死了"。
4. **压感没有真实数据源**。合成端压力只有 `0 / 1023` 两档硬编码（`smooth_engine.c:3138-3142`）。
5. **没有传序列的通道**。18924 只有扁平 JSON 解析（无数组）× 1MB 帧上限；共享内存只有 58 个 int 槽。

> **一处可以化简的地方**：点序列**不需要从前端传**——录制与回放都在原生侧完成，
> 前端只发"重放一遍"这种指令。这样 5 里的协议问题直接消失。

## 3. 设计

### 3.1 数据流

```
用户画一笔（真实笔）
   │  det_WTPacketsGet 里旁路抄一份
   ▼
g_pen[]  笔迹账本（x/y/pressure/buttons/time，按 buttons 边沿切成一段）
   │
   │  抬笔 → 原生广播 {type:'strokeEnd', id:n} 给 18924
   ▼
前端：切到「暗笔」（SHD 笔尖 + 暗色前景）→ 发 {type:'replay', id:n, offset:(dx,dy)}
   │
   ▼
penraw_synth 从 g_pen 按**录制时间轴**逐包吐给 PS（带原压感）
   │
   ▼
PS 以为用户在画第二遍 → 阴影落在同一个图层/蒙版上
   │
   ▼
回放结束 → 原生置 g_btnResync=1 → 广播 {type:'replayEnd'} → 前端切回原笔原色
```

### 3.2 关键决策

| 问题 | 决定 | 理由 |
| --- | --- | --- |
| 录制在哪 | `det_WTPacketsGet` 内的**旁路**（只读已取的包，不解包则跳过） | 不动真实包处理路径，出问题可整体摘掉 |
| 压感从哪来 | 录制时就按 CALIB 偏移解出 `pkNormalPressure` 原值，回放原样写回 | 合成端现有的 `0/1023` 两档是给断流救援用的，太粗 |
| 时间轴 | 回放时用 `now - playStart` 与录制时长对齐，每次拉取吐"该吐的包" | `penraw_synth` 是 PS 拉取驱动，不能一次吐完 |
| 偏移 | 回放包坐标整体加 `(dx,dy)`，默认 `(2,2)`（右下 = 暗部） | 完全重合没有明暗分界 |
| 互锁 | 回放期间若收到真实非零包 ⇒ 立即终止回放并置 `g_btnResync` | 用户抢笔不能把画面搞乱 |
| 结束 | 回放末包强制 `buttons=0` 并连发 `GREY_ZERO_PKTS` 个零包 | 少于 `BTN_EDGE_MIN_ZERO(16)` 会被判抖动，落笔不锚定 |
| 触发门 | 复用现有 `r==0 && realAge>=250ms`（抬笔后驱动本来就静默） | 不新开一条"随时伪造"的通路，风险最小 |

### 3.3 红线（不许碰）

- `det_WTPacketsGet` 内**零 I/O、零分配、不加锁**（文件头铁律，`smooth_engine.c:20-21`）。
- 不改真实包的任何字段；录制是纯旁路。
- `g_engineOff` / `g_stop` 语义不变：面板一 unload，回放必须立刻透传。
- 共享内存 `CFG_NLONGS` 仍是 58；回放只加**局部静态量**，不加槽位。
- 不改 `smooth_packets` 的平滑/锚定逻辑，回放包与真实包走同一条下游。

## 4. 分阶段实施（每阶段单独可验证、可回退）

### P1 笔迹账本（只录不播）

- 新增 `PEN_PT { u32 t; s16 x, y, p; u8 btn; }` + `g_pen[8192]`（≈30 秒 @250Hz）。
- 起止：`buttons` 0→1（经现有 `BTN_EDGE_MIN_ZERO` 去抖）开始一段，1→0 再连 16 个零包结束一段。
- 一段 = `{ start, count, durMs }`，环形保留最近 8 段（双笔叠加够用）。
- **验证判据**：日志出现 `[pen] rec n=312 dur=1248ms`，且抬笔后能打印首末坐标/压力极值。
- 风险：低。只读旁路，删掉也不影响任何现有功能。

### P2 回放源接入

- `penraw_synth` 增加分支：`if (g_replayOn) { ... 从 g_pen 取 ... }`，与现有 `g_riRing` 分支互斥。
- 压感按录制的原值写（不做 0/1023 兜底）。
- **验证判据**：手工触发一次回放，PS 画布上出现第二笔，形状与第一笔一致、**压力粗细一致**。
- 风险：中。必须保证 `g_synHead` 语义不被污染（另立游标 `g_rpCursor`）。

### P3 时序与门控

- 按 `now - g_rpStart` 与 `g_pen` 的 `t - t0` 对齐，每次拉取最多吐 `min(剩余, maxPkts)`。
- 结束：强制 `buttons=0` + 补足 16 个零包 + 置 `g_btnResync=1`。
- 互锁：回放中收到真实非零包 ⇒ `g_replayOn=0` 并 resync。
- **验证判据**：回放时长与原始笔画时长误差 < 15%；画完 PS 没有"还在画"的假象（HUD/光标正常回落）。

### P4 前端接线（一支笔先跑通）

- 18924 新增入站 `{type:'replay', id, dx, dy}`、出站 `{type:'strokeEnd', id, dur}` / `{type:'replayEnd'}`。
- 面板侧：`brush.json` 增加 `shadow: { color: '#5a5a5a', offset: [2,2], tip: 'SHD-<id>.png' }`。
- 顺序：抬笔 → 前端切暗笔 + 设前景色 → 发 replay → 收 replayEnd → 还原笔与色。
- **验证判据**：一支笔（`impasto-detail`）在白底上画白，自动出现右下方暗边；在**图层蒙版**上同样成立。

## 5. 明确做不出来的部分（写在前面，免得白等）

1. **压力/倾斜/旋转无法 100% 还原**：回放用的是录制值，若录制路径拿不到 HID 原始压力，
   只能退到"按 y 轴速度估压感"。真机 `g_riRing` 的 `p` 恒 0 就是同一问题的历史证据。
2. **撤销会被拆成两步**（真实一笔 + 回放一笔）。可以尝试把回放并入同一个历史状态，
   但没有稳定 API，先按两步交付。
3. **回放期间用户不能抢笔**：抢笔即取消回放（画到一半会缺一截）。
4. **纹理细节不会比原笔更丰富**：回放只是把同一形状换个颜色再盖一遍，它解决"看不见"，
   不解决"更厚"。要更厚得靠多遍叠加，代价线性上升。

---

## 6. 与「手画两遍」的关系

同一套笔尖资源（`BRS-*` 亮 / `SHD-*` 暗）两种用法：
- P1–P3 没做完之前，用户可以手动切「暗笔」描第二遍 —— 效果一样，只是费手。
- P4 做通之后，这支暗笔由插件替你落笔，用户只画一遍。

⇒ 面板上可以同时提供「暗笔」预设与「自动回放」开关，互为退路。
