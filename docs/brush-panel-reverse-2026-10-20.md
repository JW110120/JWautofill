# 水墨类"特制笔刷"面板的净室机制分析（样本 S）

> **分析目标**：一套面向水墨/书法笔刷的第三方面板（下称**样本 S**），已安装于本机。
> **分析方法**：静态文件格式解析 + 字符串解码 + 安装日志回溯。**未运行样本**，未调用其任何可执行文件。
> **合规约定**：本文只描述**机制、数据结构与判据**，不含样本的名称、作者、商标、代码片段与素材。
> 样本的 CEP 扩展目录一律写作 `<CEP>/extensions/<RID>/`。
> **判读标记**：`[观察]` = 文件/日志里直接可见；`[推断]` = 由证据推得，需真机验证；`[待验]` = 未证实。
> 日期：2026-10-20 ｜ 参照版本：样本 S 6.0 ｜ 目标宿主：PS 2026 (27.11.0.26) / 向下至 PS 2022

---

## 0. 一句话结论

**它不是新画笔引擎，是"PS 原生画笔状态的预设库 + 一个把预设塞进 PS 的发射器"。**

你直觉里"它能提供 PS 之外更多画笔参数"——这个判断需要拆成三层，只有中间一层是"真的超出"：

| 层 | 它做了什么 | 是否超出 PS 引擎 |
| --- | --- | --- |
| ① **组合** | 把 1085 套完整画笔状态（含 480×600 的自制笔尖位图）预先配好，一键切换 | ❌ 不超。参数全是 PS 自己的 |
| ② **缺口** | 用"工具录制回放"改**脚本 API 改不到**的项（引擎里本来有，只是没开 API） | ✅ 真超出**脚本 API**，没超出引擎 |
| ③ **变体** | 同一笔刷挂多形态（a/b/e/f/o/r），UI 上一主一副 | ❌ 不超，是打包方式 |

所以真正值得抄的是 **②的"走缝隙"手法** 和 **①的"预设即产品"的数据驱动结构**；
不值得抄的是它的**存放位置**（借系统目录掩护）和**把画笔存成二进制预设**（这正是它在 PS 2026 上失效的结构性原因之一）。

一句话记法：**它卖的不是笔，是"配好的笔 + 会自己伸手去按 PS 内部开关的那只手"。**

## 1. 部署拓扑：一套面板，四个仓库

安装日志（三个安装包）里逐条 `Install archive file:` 可以直接把落点还原出来：

| 落点 | 内容 | 数量 `[观察]` | 掩护手法 |
| --- | --- | --- | --- |
| `<CEP>/extensions/<RID>/`（x64 与 x86 **各一份**） | 面板本体（html/js/css/img） | 1 套 ×2 | 正规 CEP 安装位 |
| `C:\Windows\Performance\WinSAT\DataStore2\` | **笔刷预设** `.tpl` | 1085 个（+`backup\` 子目录再存一份） | 冒充 Windows 磁盘评分数据 |
| `C:\Windows\security\database\gast\` | **笔刷脚本** `.jsx` | 2217 个 | 冒充安全账户数据库 |
| `C:\Documents\Loadfile\` | 材质源文件 `.psd` | 10 个 | 顶级非标准目录，不易被搜 |

几点值得注意 `[观察]`：

- 资源全在 `C:\Windows\` 下 ⇒ 安装包必须**提权**才能写；同时普通用户对该目录**默认可写性被放宽**（否则"保存笔刷"会失败）。
- 面板本体同时装到 `Common Files` 的 x64 与 x86 两份 ⇒ 这是 **CEP 5 时代**兼容 32/64 位宿主的做法，现在早已没有 32 位 PS。
- `.tpl` 目录里有 `backup\` 副本 ⇒ 作者自己也知道这些文件**会被 PS 改写**，先留底。

## 2. 加载链路：面板只干三件事

```
用户点缩略图
   │
   ├─(1) CEP: csInterface.evalScript("$._ext.evalFile('1-1')")
   │        └─ ExtendScript 读 C:\Windows\security\database\gast\1-1.jsx 并 eval
   │
   ├─(2) 该脚本做三步 ActionManager（字符串证据，见附录 A-3）：
   │        delete  toolPreset[name="1-1"]      ← 先删掉同名的旧预设，防重名堆积
   │        load    File("/c/windows/.../1-1.tpl")  ← 把预设文件灌进 PS
   │        slct    toolPreset[name="1-1"]      ← 选中它（此时画笔参数已生效）
   │
   └─(3) CEP: csInterface.evalScript("$._ext.evalFile('zhushou')")
            └─ 助手脚本：回放一段"工具录制"数据（第 4.2 节）
```

面板侧的实现极薄 `[观察]`：

- `js/app.js` 里**没有任何笔刷数据**：启动时 `fs.readdir()` 扫脚本目录，按文件名 `^(\d+)-(\d+)([a-z])?$` 解析出「分类-序号-变体」，再按分类分页。
- 缩略图是预生成 PNG：`img/brush/<name>.png`，**250×55**，共 580 张。
- 收藏 = `USER_DATA/<RID>/favorite.json`；用户改过的笔 = `saved.json`（只存名字数组）。
- 14 个分类页 + 版权页 + 收藏页；分类名是中文水墨术语（枯焦/浓淡/清水/墨晕/勾线/皴擦/书法/毛笔/特效/自然/特笔/涂抹/橡皮/其它）。

**这套结构本身就是最大的可复用资产**：库是**数据驱动**的——加一个 `.tpl` + 一个 `.jsx` + 一张 PNG，面板自动多一支笔，不用改代码。

## 3. 一支"笔"到底是什么：8BTP 解剖

`.tpl` 不是自定义格式，是 **Photoshop 自己的工具预设文件**（签名 `8BTP`）`[观察]`。
一个文件里三个 8BIM 资源块：

| 资源 ID | 实测大小（1-1 / 1-22） | 装什么 `[推断]` |
| --- | --- | --- |
| `tppa` | 6.0 KB ~ 864 KB | **工具预设参数**：完整画笔描述符（含笔尖引用、动力学、混合模式） |
| `tpbd` | 1.8 KB ~ 1.73 MB | **笔尖位图数据**（按尺寸膨胀，150×150 / 128×128 / 480×600 三种量级都实测到） |
| `tptp` | 2 KB | 面板预览用的小图 |

把 `tppa` 里的 4 字符键扫出来（`[观察]`，共 60+ 个可辨识键），都是 PS 画笔描述符的原生键：

| 键 | 含义（PS 内部语义） | 键 | 含义 |
| --- | --- | --- | --- |
| `Brsh` | 画笔对象主体 | `bVTy` / `brVr` | 画笔变体类型 / 版本 |
| `Dmtr` | 直径 | `Angl` | 角度 |
| `Spcn` | 间距 | `flip` | 翻转 |
| `Intr` | 插值（硬度曲线） | `Nm  ` | 名称 |
| `Mnm ` / `mini` | 最小直径 | `useP` | 压力控制开关 |
| `jitt` | 抖动 | `fStp` | 流量步进 |
| `Dyna` / `amic` / `mics` / `sObj` | 动力学组 | `erUn` | 擦除单位 |
| `BlnM` | 混合模式 | `samp` | 取样（湿笔类） |
| `TEXT` `UntF` `Objc` `enum` `long` `bool` | 描述符的值类型标记 | | |

**结论（关键）**`[观察+推断]`：这里面**没有一个键是 PS 画笔面板里没有的**。
它的"丰富"来自 ①笔尖是**自制位图**（不是 PS 自带圆头），②参数是**成套配好的**（用户手工很难复现），③每支笔还有 1~5 个变体（各有自己的 `.tpl`）。
所以它是**内容产品**，不是**引擎产品**。

## 4. 真正"超出"的部分：走脚本 API 的缝隙

### 4.1 缺口在哪

PS 的画笔状态有几百个内部字段，而 **ExtendScript / batchPlay 的公开字典只覆盖一部分**。
典型缺口：笔尖的某些内部标志、工具录制里才有的运行时状态、同一参数在不同工具（画笔/橡皮/涂抹/湿笔）下的耦合项。
这些字段**引擎里存在**，但**没有官方 ActionManager 键**可以写。

样本的做法（`[观察]` 字符串 + `[推断]` 语义）：

### 4.2 助手脚本 = 回放一段"工具录制"

助手脚本只有 5 个可辨识字符串：

```
'handTool'  'null'  'ARBFdA'  'toolRecordingData'  'toolRecording'
```

以及一整段 **十六进制记录体**（约 3000 字符）。把记录体解开 `[观察]`：

- 明文片段：`TPaintbrushTool`、`THandTool`、`<NULL>` ⇒ 这是**画笔工具 + 手型工具的工具会话录制**；
- 数值片段：成对的 float（如 `0x3F6B5632`≈0.919、`0x3F92C6EF`≈1.146、`0x3FA1949E`≈1.26 …）呈**递增梯形**，另有一组固定坐标对重复出现 ⇒ **一段带坐标与参数梯度的录制笔迹/参数变更序列**。

因此 `[推断]`：助手脚本把这段二进制塞进 `toolRecordingData`，让 PS 自己"重放"一遍工具会话——**参数变更由 PS 内部执行，绕过了脚本字典的缺口**；先切 `handTool` 是为了让录制落到一个中性工具上再切回画笔。

> ⚠️ 这是**最脆的一环**：二进制记录体没有版本协商。PS 改了工具会话的内部布局，它就静默失效。
> 这正好是"PS 2026 起效不了"的头号嫌疑（见第 6 节）。

### 4.3 "保存/复位"是怎么做的（说明它把预设当可写文件）

549 个 `S*`（保存）+ 549 个 `R*`（复位）脚本，字符串证据 `[观察]`：

```
'Prpr'  'toolPreset'  'capp'  'Ordn'  'Trgt'  'null'  'T   '  'set'  'make'
'/c/windows/.../TEMP TOOL.tpl'      ← 中转文件
'2nby2lIR2nFc2wQ'                   ← 隐藏标记名（写进预设名里）
'/c/windows/.../1-1.tpl'            ← 写回原位
```

即：当前状态 → 复制到 `TEMP TOOL.tpl` → `make` 成新工具预设（名字里夹一段不可见标记）→ 覆盖回原 `.tpl`。
**注意**：它改的是**共享目录里的原文件**，不是用户目录。多用户/重装即丢，且"标记名"是一种溯源水印。

## 5. 隐蔽性与反侵权手法盘点（我们要**避开**的部分）

| 手法 | 证据 `[观察]` | 评价 |
| --- | --- | --- |
| 资源藏进系统目录 | `C:\Windows\Performance\WinSAT\...`、`C:\Windows\security\database\...` | 卸载不干净、杀软误报、需提权。**不学** |
| 顶级非标准目录 | `C:\Documents\Loadfile\` | 同上 |
| 脚本混淆 | 全部 `.jsx` 为 `@JSXBIN@ES@2.0` 编码 | 拖慢排障、无法静态审计。**不学** |
| 预设名夹水印 | 保存时写入隐藏名串 | 有法律意图，但也是**卸载残留** |
| 版权页 + 作品登记号 | 面板内"版权"页 | 正常商业做法，可学 |
| 双架构重复安装 | x64/x86 各一份 | CEP 5 时代产物，无必要 |

## 6. 为什么在 PS 2026 上起效不了

按"最可能 → 次可能"排序，每条都给验证动作。

### 6.1 注册表那一步根本没打到点上 `[观察，已确认]`

- 你装的 `.reg` 只写了一个键：`HKCU\SOFTWARE\Adobe\CSXS.8` 的 `LogLevel=1`、`PlayerDebugMode=1`。
- `CSXS.8` 对应的 CEP 版本是 **8**（CC2018 时代）。
- 本机 PS 2026 的 CEP 引擎实测 **12.0.0** ⇒ 它只认 `CSXS.12`。
- 清理前注册表实况：`CSXS.5/6/7/8` 都有 `PlayerDebugMode=1`，**唯独 `CSXS.12` 只有 `LogLevel=1`，没有 `PlayerDebugMode`**。

⇒ 该面板是**自签名扩展**，CEP 12 会直接拒绝加载未签名扩展，除非 `CSXS.12\PlayerDebugMode=1`。
**这就是"面板根本进不去"的直接原因，和画笔参数无关。**

### 6.2 就算面板能开，助手脚本那一环大概率也断了 `[推断]`

第 4.2 节的二进制工具录制体，跨 10 个大版本（CEP 5 → PS 27）几乎不可能仍然兼容。
一旦断，表现是：**缩略图能点、画笔能变、但"手感"不对**（丢的就是脚本 API 之外的增量）。

### 6.3 清单文件是 CEP 5 时代写的 `[观察]`

`ExtensionManifest Version="5.0"` / `RequiredRuntime CSXS 5.0` / `Host Version="15.0"`（CC2014）。
版本号是"最低要求"语义，理论上仍可加载；但面板 UI 是 AngularJS 1 + jQuery + Bootstrap 3，
CEP 12 的 Chromium 内核虽有兼容模式，也属于**能开但别指望稳**的区间。

### 6.4 三步诊断法（10 分钟内可做完，建议在动手写代码前先做）

1. **验加载**：把 `PlayerDebugMode` 写到 `CSXS.12`，重启 PS，看窗口菜单里是否出现该面板。
   - 进不去 ⇒ 卡在 6.1/6.3；能进去 ⇒ 继续。
2. **验预设**：在 PS 里**双击** `C:\Windows\Performance\WinSAT\DataStore2\1-1.tpl`。
   - 能加载出画笔 ⇒ PS 2026 仍认这种预设文件 ⇒ "预设即产品"这条路**可以走**。
   - 打不开 ⇒ 连基本假设都不成立，我们的方案必须换（见计划书第 3 节方案 B）。
3. **验缝隙**：面板点一支笔，看画笔是否真的换成自制笔尖；再对比"点之前/之后"的笔触手感是否一致。
   - 参数变了但手感没变 ⇒ 6.2 成立（录制回放失效）。

> 本次会话**只做了清理注册表**这一步，没有替你改 `CSXS.12`，也没有运行样本（净室边界）。

## 7. 结论：该抄什么、别抄什么

| # | 结论 | 用途 |
| --- | --- | --- |
| C1 | 它的"笔"= **PS 原生工具预设**，参数零新增 | 我们不必发明参数格式去兼容引擎，只要**能构造预设**就行 |
| C2 | 它的强项是**数据驱动 + 预设库**（加文件即加笔，代码不动） | 我们的面板也做成纯数据驱动，`brush.json` + 资源 |
| C3 | "超出 PS"的真实含义是**超出脚本 API**，靠工具录制回放补 | 我们要用**可维护的替代品**：能用 batchPlay 键就不用录制体；必须补的缺口单独封装、单独降级 |
| C4 | 二进制预设 + 系统目录 + 混淆 = **升级就死、卸载不净** | 我们的预设用**明文 JSON + PNG**，装在自己插件目录，可 diff、可迁移 |
| C5 | 变体（一主多副）是低成本高感知的设计 | UI 上做成"主笔 + 副形态"两级 |
| C6 | 14 类中文水墨分类法很成熟 | 我们的默认分类直接借用这套**艺术语汇**（不是抄它的实现） |
