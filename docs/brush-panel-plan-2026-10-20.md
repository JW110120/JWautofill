## 0. 先说结论：这个入口要做成什么

**不做"新的画笔引擎"，做三件 PS 自己给不了的事：**

| # | 做什么 | 用户感知 | 难度 |
| --- | --- | --- | --- |
| ① | **预设库**：一套配好的特制笔（自制笔尖 + 成套参数），点一下就是那支笔 | "这面板里的笔，手感跟 PS 自带的不一样" | 中 |
| ② | **参数直给**：PS 面板里要点七八下才能凑出来的组合，这里一键选中、可微调、可存 | "省事，且调出来的东西能存住" | 中 |
| ③ | **越界增强**（可选，靠现有 8li）：压力曲线重映射、多遍叠墨、蓄墨/磨损 | "这个 PS 根本做不到" | 高（独立阶段） |

第 ③ 项才是真正的护城河——因为它在**驱动层**动手，不在 PS 的 API 层排队。你现有的 `JWautofillHost` 已经在做 Wintab 取包、坐标改写、代投，这些能力正好是 ③ 的地基。

**明确不做**：不改 PS 画笔引擎、不注入 PS 内部结构、不复制样本的任何文件/素材/代码、不写进 `C:\Windows`。

## 1. 边界：第三个入口和另外两个的关系

```
com.listen2me.jwautofill      选区填充      （已有）
com.listen2me.pixeladjustment 绘画工具箱    （已有）

        │

        └─ 可选：向 8li 订阅笔迹事件做运行时增强   ← 8li 不在时自动降级
```

**关键约束**：新入口必须能**单独工作**。8li 没装、PS 版本低、用户关了增强——面板照样能选笔、能画、能存。增强是加分项，不是前置条件。

## 2. 技术选型：笔怎么"进"PS

这是整份计划里唯一必须现在拍板的技术点。三种可行路线：

| 方案 | 做法 | 优点 | 缺点 | 判断 |
| --- | --- | --- | --- | --- |
| **A. `.abr` 笔刷包** | 打包时带一个 `.abr`；首次用时 `load` 一次，之后按名字选中 | 一次 load 全库可用；笔尖是一等公民（PS 画笔面板里也能看到）；PS 2022~2026 通吃 | 需要能产出 `.abr`（PS 里手动导出即可）；用户会看到一堆笔刷混进自己的画笔列表 | ✅ **主选** |
| **B. PNG 运行时定义** | 存 `tip.png`；用时开临时文档 → `defineBrush` → 关闭 | 资源全程可读、可 diff；不污染画笔列表（不落盘） | 每次会话首次使用要定义一次（约 0.3~1s/支）；会闪一下文档 | ✅ **兜底**（A 失败时自动切） |
| **C. `.tpl` 工具预设**（样本那条路） | 打包 `.tpl`，`load` + `slct` | 一个文件打包"笔尖+全部参数+工具模式"；一步到位 | 二进制黑盒、无法评审、跨版本极易碎（样本在 2026 失效的结构性原因）、921MB 的教训 | ❌ **不采用** |

**决策建议**：A 为主 + B 兜底；`.abr` 只装一次（记 `sessionStorage` 标记 + 检查画笔是否存在），失败自动走 B。
> 注意：`load` 这个动作对 `.abr` / `.pat` / `.tpl` 是同一个 ActionManager 动作，所以 A 和 C 的"注入"环节代码是同一段，差别只在文件格式与可维护性。

## 3. 数据模型：一支笔就是一个文件夹

```
src/brushes/
  ink-dry-01/                 # 一支笔 = 一个目录
    brush.json                # 全部参数（明文，可 diff）
    tip.png                   # 笔尖位图：8bit 灰度，白=着墨，黑=透明
    preview.png               # 面板缩略图：250×55（与现面板等比）
    pattern.png               # 可选：纹理（皴擦/纸纹类）
  ink-wet-01/
  ...
  library.json                # 分类与排序（分类=水墨语汇，顺序可改）
```

`brush.json` 草案（字段名先按语义写，最终键名以 ScriptListener 录制为准，见 §4.2）：

```jsonc
{
  "id": "ink-dry-01",
  "name": "枯笔·焦墨",
  "category": "枯焦",
  "tip": "tip.png",
  "tipSize": 220,              // 基准直径(px)
  "variantOf": null,           // 有值 = 副形态，挂在主笔下面
  "params": {
    "diameter":   { "base": 220, "pressure": true, "min": 0.12 },
    "spacing":    0.06,
    "angle":      0,
    "roundness":  0.85,
    "flipX":      false,
    "hardnessCurve": "hard",    // 语义化档位，映射到 PS 内部插值
    "flow":       { "base": 0.75, "pressure": true, "min": 0.2 },
    "opacity":    { "base": 0.9,  "pressure": false },
    "scatter":    { "on": true, "amount": 0.12, "count": 2 },
    "colorDyn":   { "on": true, "bgFgJitter": 0.18 },
    "transfer":   { "opacityJitter": 0.1 },
    "noise":      0.05,
    "wetEdges":   false,
    "texture":    { "src": "pattern.png", "scale": 0.7, "mode": "multiply", "depth": 0.35 }
  },
  "engineVersion": 1            // 参数解释器的版本号，升级时可迁移
}
```

设计要点：

- **语义化优先**：`hardnessCurve: "hard"` 而不是直接写内部枚举值 —— 内部值随版本变，语义不变，映射表放代码里。
- **`engineVersion`**：以后如果 PS 改了键名，我们按版本迁移，不让用户的笔"变味"。
- **不存二进制**：任何字段都可读、可审、可 `git diff`。

## 4. 应用链路：点一下到底发生了什么

### 4.1 首次（装库，仅一次）

```
1) batchPlay: [{_obj:"load", null:{_path:"<plugin>/brushes/all.abr", _kind:"local"}}]
2) 校验：读取画笔预设列表，确认 N 支都在
3) 若失败 → 降级 B：对当前要用的那支，按需 defineBrush(tip.png)
```

### 4.2 每次点选（毫秒级）

```
executeAsModal(async () => {
  1) 确保笔尖在会话里（A: 已 load；B: 未定义则先 defineBrush）
  2) 选中笔尖：  slct  { _ref: "brushPreset", _name: "<tip presets 名>" }
  3) 下发参数：  set   { _ref: "brush", _enum: "ordinal", _value: "targetEnum" }  ← 一次 set，整包下发
  4) 确保当前工具是画笔/橡皮（按笔的用途）
})
```

第 3 步是核心：**一次 `set` 把 `brush.json` 里的整包参数写进去**，而不是逐项点 UI。
参数键名对照表（PS 内部键 → 我们的字段）**必须用 ScriptListener 实测生成**，不能照抄网上资料；这张表是 P2 阶段的主要工作量，也是后续每次 PS 大版本升级时唯一需要复核的东西。

### 4.3 与 PS 2022 的差异处理

| 风险点 | 处理 |
| --- | --- |
| 某些参数键在 23.x 不存在 | 写入前按 `app.version` 过滤；不认识的键**跳过而不报错**，并在面板上标"此笔在 23.x 上少 1 项参数" |
| `defineBrush` 需要**活动文档**（不需要选区） | B 路径自带临时文档，用完按 `_id` 精确关闭且不写历史 |
| 一次性 set 整包可能被旧版拒绝 | 整包失败 → 自动**降到逐项 set**，逐项再失败 → 只应用前 N 个关键项（尺寸/间距/流量/不透明度），保证"能用" |
| manifestVersion | 新入口沿用 **manifestVersion 4**（现有 `minVersion 23.0.0` 已覆盖 2022） |

```
├────────────────────────────┤
│   湿笔·淡墨                │
│   ▓▓▓▓▓ 预览条 ▓▓▓▓▓▓▓▓▓  │
```

## 6. 越界增强（P3，可选，依赖 8li）

| 增强 | 用户感知 | 实现位置 | 依赖 |
| --- | --- | --- | --- |
| **压力曲线重映射** | 轻按更"肉"、重按更"爆"，可存曲线 | 8li 包处理里对 `pkNormalPressure` 做查表/样条重映射 | 已有 Wintab 钩子 |
| **多遍叠墨** | 一笔下去像叠了 2~3 层，自动出湿边 | 抬起笔后按记录的路径重放 N 遍，每遍微扰角度/尺寸/透明度 | 需要笔迹记录 + 代投（已有） |
| **蓄墨 / 磨损** | 长笔画越画越干，抬笔回墨 | 运行时对 flow/opacity 施加行程衰减 | 纯计算，无 PS 依赖 |
| **纸纹自适应** | 笔触按纸纹起伏吃墨 | 采样画布纹理 → 调制不透明度 | 像素读取（23.x 能力**待验**） |

**这一层不写进本期交付**。原因：它要改 8li，与你的平滑/补流逻辑同处一条链路，一旦混进去，排障成本会像之前那十次翻车一样高。建议 P3 单独立项，且**默认关闭**，走 `wtctx.ini` 开关（沿用你现有的"缺省=只观测"约定）。

## 12. 落地记录（v1，2026-10-20 22:30）

按你拍板的四项执行：**笔尖 `.abr` 路线 / 参数明文 JSON / 首期 ≤10 支 / P3 后置**。
唯一偏离：`.abr` 改为**运行时生成**，理由见 12.1。

### 12.1 与计划的唯一偏离：`.abr` 不预先生成，改为运行时 `defineBrush`

| | 计划 | 落地 | 为什么改 |
| --- | --- | --- | --- |
| 笔尖注入 | 预打包 `.abr`，`load` 一次 | 首次点笔时 `defineBrush`（开临时文档→定义→关闭），整个 PS 会话只做一次 | 手写 `.abr` 二进制风险高且无法验证；用 PS 自己的 `savB` 导出会把**用户全部画笔**一起写进文件。所以「一次性」的收益保留，`load` 的路径留作后续优化（`ensureTips` 里预留了分支位置） |

成本：6 支笔首次约 2~4 秒，之后同会话内 0 成本；面板重开也只在**首次点击**时补做。

### 12.1.1 真机第一修：`selectAll` 是非法命令名（-25920）

首次真机点笔，PS 弹：`全选: 悦绘: 命令"<未知的>"当前不可用。(-25920)`。

| | 结论 |
| --- | --- |
| 根因 | `_obj: "selectAll"` 不是 PS 认得的 action 命令名 ⇒ PS 解析不到命令（所以错误里命令名是`<未知的>`），直接拒绝执行。 |
| 本项目已验证的正确全选写法 | `{ _obj:'set', _target:[{ _ref:'channel', _property:'selection' }], to:{ _enum:'ordinal', _value:'allEnum' } }`（见 `adjustments/AdjustmentPanel.tsx::selectAllDocument`，那是 Alchemist 录制后跑通的版本）。 |
| 真正的修法 | **这一版干脆不要全选**：`defineBrush` 无选区时取整个图层内容，与全选结果等价。少一步 = 少一个失败点。 |
| 顺带加固的三条 | ① 关闭临时文档改用 `document _id` 精确定位（原来用 `targetEnum`，万一开文档失败会关错用户的稿子）；② 安装前先读画笔预设清单查重，避免重复定义出两套同名 `BRS-*`；③ 定义后**复查清单**，专治"命令返回成功但笔尖没出现"的静默无效。 |

> 教训一句话：**batchPlay 的每个 `_obj` 都必须来自「录到过 / 跑通过」的样本**，凭语义猜名字（selectAll / selectAllDocument 之类）会直接换来 -25920，而且报错信息里连命令名都是"未知的"，极难反推。

### 12.4 当前**未**应用的部分（故意的）

| 项 | 状态 | 原因 |
| --- | --- | --- |
| 压感动力学（尺寸/不透明度/流量的压力曲线） | 不应用 | PS 画笔描述符里这批键名无法靠猜——猜错的表现是「看起来成功、其实没变」，比失败更难查 |
| 纹理（rough-canvas / texture-melt / texture-rock） | 只记录不应用 | 需要先把图案装进图案库再引用，链路未验证 |
| 角度跟随运笔方向 | 只记录 | 同上 |
