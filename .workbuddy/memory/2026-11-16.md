## 「合并图层/合并组/删除图层 仍弹『获取』当前不可用」+ notify 汉化补全

### 问题 1 根因（不是模态碰撞，是 get 目标已失效）

`-25920` 有两个**互不相干**的成因，`executeAsModal` 只挡得住第一个：

| 成因 | 机制 | `executeAsModal` 能否挡 |
|---|---|---|
| ① 模态碰撞 | 宿主握着模态作用域时裸发命令 | 能 |
| ② **get 目标失效** | 拿**已失效的 `layer._id`** 逐条 `get`（合并/合并组/删除一次性让一批 id 失效） | **不能**（我们本来就握着锁） |

三个病灶：
1. `MaskSyncEngine.buildLayerTree` —— `refreshLayerSnapshot()` 读失败时**原样返回旧缓存**，调用方无法区分 ⇒ 拿「结构已变、内容还是旧的」快照去逐 id 发 `get`（40/批，一条失效 id 就是一屏黄条）。
2. 两处 `_options.dialogOptions` 用 `dontDisplay` —— 只挡**对话框**，命令**出错**时仍刷黄色通知；只有 `silent` 才静默（`psBrush.ts` 已踩过同坑）。
3. `LayerInfoHandler.probeChannelState` / `HotkeyBridge` 两条工具探测同样用 `dontDisplay`，且分别是「每条 select/delete/make 后 300ms」与「1s 巡检 + 每条通知」的高频入口。

### 修复（9 处）

- `layerTreeSnapshot.ts`：新增 `refreshLayerSnapshotEx()` → `{ snap, fresh }`；旧接口保持「返回旧缓存」的语义不动（下拉不清空）。
- `MaskSyncEngine.buildLayerTree`：返回类型 `LayerTreeEntry[] | null`；只接受**可信**条目（调用方给条目时要求 `!isLayerSnapshotDirty()`，自取时要求 `ex.fresh`）；不可信/异常一律 `null`，**不再返回 `[]`**（`[]` 与「文档没图层」不可区分）。
- `reconcileTasks`：`if (!entries) return false;` —— 否则一次忙碌窗口会把任务的 sample/target 引用全清空。
- `fetchLayerNamesByIds` / `fillUserMaskFlags`：`dontDisplay`→`silent`（descriptor + batchPlay 两处），命中 `_obj:'error'` ⇒ `invalidateLayerSnapshot()` + `break`（不再把 N/40 批发完）。
- `reconcileStructureIfNeeded`：走 `Ex` + 要求 `fresh`。
- `AdjustmentPanel.refreshMaskSyncOptions` / `refreshMaskSyncAndReconcile`：走 `Ex` + `fresh`；`!tree` 直接返回（不再 `reconcileTasks(undefined)` 二次建树）。
- `psProbe.debouncePsProbe`：忙碌判据 `isPsBusy() || psBusyInProc() === 1`（时间窗是否定式，`'Lvl '` 是宿主自报的肯定式；`-1` 放行，旧 .8li 行为不变）。
- `LayerInfoHandler` 两条通道 get、`HotkeyBridge` 两条工具 get：`silent`。
- 新增 `[蒙版同步] …⇒ 本轮跳过逐 id 查询` 节流日志（1.5s），真机看到它 = 保护生效。
