## 分块平均「加权模式」需求澄清 + 改为自适应对比压缩方案（待用户确认，未改代码）
用户澄清概念：**「分块」= 不连通选区各自独立平均**（因为 PS 原生平均滤镜会把不连通选区的像素混在一起算），
所以普通模式已经正确，不是「按色块分块」。新模式的目标是：各不连通选区**分别减弱自身对比**——
与选区均值接近的大面积像素小幅趋近均值，与均值差距大的小面积特征（细线）大幅趋近均值。

### 关键设计结论
- **判据是「与选区均值的差」，不是面积**。面积只是相关现象（细线既小又偏离大）。面积驱动会反向（大块权重高→被更狠地拉平）。
- 均匀降对比 = 线性缩放（out = m + d·c）**做不到**这个诉求，必须用 |d| 的非线性映射。
- 推荐公式：`k = s·(u/τ)^p/(1+(u/τ)^p)`，`u = |亮度 − 亮度均值|`，`τ = max(σ_L, 6)`，
  `输出 = m + (原值−m)·(1−k)`，k 统一作用于 RGBA（保色相）。移除原 16 簇颜色聚类。
- **单调性约束（重要）**：映射单调 ⟺ `1 − k − u·k' ≥ 0`。p=1 恒单调；p=1.5 仅在 u≈1.59τ 处有 <1.1 级反转；
  **p≥2 会让线条中心反转**（实测最深 -38.3 → -5.7，比邻域 -8.0 还浅 → 线条发虚/空心）。
  p→∞ 的极限（k→1，最远像素完全变均值）必然反转，**「线条完全消失」与「单调无反转」不可兼得**。
- 推荐 **p = 1.5、τ = σ_L**：实测背景段移动 22.8%（绝对约 2 级）、线条段移动 76.3%（绝对约 20 级），
  区分度 3.3×；p=1 只有 2.1×；p=2 达 4.8× 但反转 2.3 级。
- 滑块 s = 强度/10（1–10），建议默认 8 → 背景移动 18%、线条移动 61%。

### 用户这张截图的实测基线
选区均值 RGB(239.2,239.6,242.2)、亮度均值 239.8、σ_L = 15.99；
|d| 分布：<12 占 77%（背景）、>24 占 13.3%（两根粗线）、12–24 仅 9.8%（抗锯齿过渡带）→ 背景/线条在 |d| 上天然可分。
RGB 欧氏 RMS = 26.76 ≈ √3×15.99 → 偏离几乎全在明度轴上，用亮度做判据足够且顺带保色相。

### 实现要点
每分量 2 趟：趟1 求 ΣRGB / ΣL / ΣL²（得均值与 σ），趟2 按 k 写回；`k_eff = (coeff/255) × s × k`。
顺带消灭现有加权分支三个 bug（|0 截断下漂、16 簇封顶丢像素、Uint16 簇计数回卷），且比现方案更快（去掉 O(16N) 内层）。
脚本落在 `outputs/blockAverage-sample-stats.cjs`、`blockAverage-adaptive-eval.cjs`、`blockAverage-profile.cjs`。

## 参数语义定稿：强度 1–10 线性、p 是形状（用户确认需求）
- **k 的语义 = 该像素原始偏离被抹掉的比例**（k=0 不动，k=1 变成选区均值）。`k` 的上界 = `s = 强度/10`
  → 强度10 = 最偏离像素完全贴到均值；强度1 = 最多抹 10%。
  `∂out/∂s = −u·g(u) ≤ 0` ⇒ **强度对每一个像素都严格单调**，1–10 不存在「越调越弱」的像素。
- **强度 1→10 对平均改动幅度严格线性**（本图实测）：每升一级线条段多压 2.82 级（36.37→33.55→…→8.17）、
  背景段多压 0.20 级（7.15→6.95→…→5.15）。
- ⚠️ **严格单调的解析界：`s ≤ 4p/(p+1)²`**（由 `1 − s·(g + u·g') ≥ 0` 推得）。
  p=1→1.000、1.25→0.988、**1.5→0.960**、1.75→0.926、2→0.889。即 s=1 只有 p=1 才严格单调；
  p=1.5 在强度10 有 **1.19 级**反转（u > 1.59τ 起），p=1.5 的 1–9 级全严格单调。
- p 的取舍（强度10，本图）：p=1 背景压 34%/线条压 70%（选择比 2.06、反转 0）；
  **p=1.5 → 28%/78%（2.79、1.19 级）**；p=2 → 23%/84%（3.65、3.99 级）。

## 「对比减弱」定稿并落地代码

### 标定：s = 强度 × 0.07
按用户「把目前的强度 7 映射为 10」：旧强度 7 的 k 上限是 0.7，故新刻度 强度1 → k 上限 7%、**强度10 → 70%**。

### 严格单调性（已解析 + 数值双证）
p=1：`out(u) = u·(1 − s·t/(1+t))`，`d(out)/du ∝ 1 + (1−s)(2t + t²) > 0` 对 `s ≤ 1` 恒成立

对照 p=1.5：s=1 时 out(60)=7.25 < out(20)=8.34，正是用户否掉的那种反转。

## 「对比减弱」新增混合颜色带柔化（batchPlay 方案被否）
用户想加「类似 PS 混合颜色带」的功能，让高强度减弱更温和。原计划 batchPlay 七步：存选区→复制图层→全文档减弱→
按选区均值设 blendRange→向下合并→载回选区→删通道。**该路线整体否掉**，三个死结：

1. **复制 + 向下合并必然抬 alpha**：两层同 alpha=a、上层不透明度 α 时合并 alpha = a(1+α−aα/255) ≥ a。半透明选区必坏。
2. **选区外像素也会被改**：第 3 步无选区 → 按**全文档均值**压缩全文档；第 4 步掩模只按「与选区均值的距离」部分还原。
   实测（均值 240、σ≈16、强度10）：选区外灰值 100 → **142**（三通道斜坡相乘）/ **169**（仅灰色通道），抬亮 42–69 级。
3. **掩模强度取决于均值在色阶中的位置**：斜坡端点是 0/255，均值 240 时亮侧斜坡只有 15 级宽 → 背景噪声近一半落在陡坡上被保护，
   暗侧斜坡 240 级宽 → 线条几乎不被保护。实测背景压缩 24%→5%、线条 49%→38%。

### 像素域等价式（已采纳）
batchPlay 的 RGB 结果 = `out = m + d·(1 − w·k·φ)`，φ 即混合颜色带遮罩；**alpha 不乘 φ** → 正好满足「alpha 只吃对比减弱的平均」。
整条流程塌缩成现有的一次 putPixels，不需要临时通道 / 复制层 / 合并 / 载回选区。
- φ 用**单亮度标量**（三通道相乘其实也退化成标量，同样不漂色相，但单亮度版对明暗两侧对称）。
- ⚠️ **平台段是必需的**：若照原参数把四个手柄全收到均值（平台宽 0），背景压缩会从 24% 掉到 5%，且强度随选区均值位置漂移。
  加平台后**背景分档保留率恒为 76%，与无柔化完全一致**（柔化只作用于 >1.5σ 的特征段）。

### 方向取舍由硬条件裁决
- R1「保护偏离大的像素」（=用户描述的方向）：`φ = 1 − λ·clamp((u−1.5σ)/4.5σ, 0, 1)`。
  实测（强度10）：背景 76% 不变、线条 51%→61%（λ=1）、选择比 2.04→1.62、σ_out 9.14→10.34、**逆序 0**。
- R2「保护底色」（φ 随 u 上升）：线条仍 51%、背景 76%→91%、选择比 5.35，但 **a=1.5 逆序 144 / a=2 → 2089 / a=3 → 6253**，
  违反「压缩后偏离大小关系不能变」→ **否决**。用户的硬条件把方向唯一确定为 R1。
- 强度梯度仍严格线性（线条带每级多压 1.42 级）。

### 落地（四个文件）
`processBlockAverage` 增参 `useBlendIf`(默认 true)、`blendIfStrength`(默认 8)；φ 常量 a=1.5σ、b=6σ；λ = 级/10；
alpha 走不带 φ 的因子。UI 加「混合颜色带」开关（label-5）+「柔化」滑块（1-10，step 0.5，label-2）。
`helpTexts` 加 `blendIf` / `blendIfStrength`，`PanelStateManager` 类型同步。
历史记录名：开着对比减弱时 `applyProcessedPixels` 写「对比减弱」，否则「分块平均」。
脚本 `outputs/blockAverage-blendif-spec.cjs`（双方向 + 形态 + 单调性）、`outputs/blockAverage-blendif-ps-faithful.cjs`（忠实 PS 口径对拍）。

### 2) 梯度修改（gradientRelaxProcessor.ts）负值 bug：a=0 像素被注入 alpha
**根因链**：进入时先把 RGB 预乘（`a===0` 的像素 RGB 被清零）→ 负值走 `blurAlpha` 分支，把邻居 alpha 的
邻域加权均值摊到**所有选区内像素**（含 a=0）→ 反预乘时这些像素 RGB=0、alpha>0 → **半透明黑边/暗色光环**
（radius = 2+2·|amount|，量级 5 时半径 12，视觉上就是一圈 20 多 px 的黑雾）。
正值天然无此问题：`mn` 恒等于自身 alpha=0 ⇒ `tn2=0 ⇒ v2=0`，a=0 像素保持 0（所以用户说「**仍然**只影响 alpha>0」）。
**改法（3 处）**
1. 通道循环里加统一不变量：`if (hasAlpha && a0 === 0) continue;`（`a0 = pixels[p+3]`），并复用 `a0` 给颜色通道权重。
2. 负值 alpha 分支不再重复读 `a0`。
3. 末尾反预乘 pass：`a0 === 0 || 选区内 == 0` 的像素**整像素还原原始字节**（原来整幅图都走预乘→反预乘往返，
   有 ±1 舍入漂移；选区内 a=0 的脏 RGB 也会被清零，现在不再动）。
**验证** `outputs/gradrelax-verify.cjs`（ts 源码 transpile 后跑合成图 64×64：方块 255 + 周围 a=0 脏 RGB(7,8,9)，
选区左 4 列外）：amount = -5/-10/0/+5 全部 PASS —— 选区外 4 字节零差异、选区内 a=0 像素 4 字节零差异、
负值时 alpha>0 像素确实被改动。抽样（-5，方块边缘 x=20）：255→191、RGB 提亮为保持黑底观感。
⚠️ 副作用/遗留：a=0 被冻结后「放缓」只能**向内**摊（硬边 255→约 191 且随 radius 向内延伸），
不再向外扩 alpha；若用户要「不缩形」的柔化，需改成把 a=0 排除出 blurAlpha 权重（未做，等反馈）。

### 改法（四条不变量，缺一不可）
1. **阈值自适应**：`estimateBodyLevel` = 选区内 alpha>0 的**粗直方图众数**（8 宽一档），
   `thr = clamp(round(bodyLevel/2), 2, 128)`。不透明形状 → 248 → thr=124（与旧版 128 等价）；
   半透明色块才可能进 mask。
   ⚠️ **取值必须只依赖「哪一档胜出」**（用档的下边界 `bestBin<<3`），不能用档内均值：
   第一次处理新生成的过渡带像素会改直方图，均值漂移→阈值变→二次运行出现零散改动。
2. **本体不透明度场** `bodyAlpha`：种子 = 形状内「距轮廓 ≥2px」的像素（`distOut2 >= 4`），
   宽 ≤5px 的窄条整段算种子（`seedThinFlag`，否则窄条取不到本体水平）；EDT 传播最近种子的 alpha。
   `aRecon = aBody × profile(cov)`（profile 已归一化成 0~1），**硬性封顶 `aRecon ≤ aBody`**。
   同一张图上不同透明度的色块各按自己的水平处理。
3. **两侧单调性**：内侧 `aRecon ∈ [thr, 原值]`（**只削不抬**）、外侧 `aRecon ∈ (原值, thr-1]`（**只补不削**）。
   内侧只削不抬这条是必需的：软边半透明笔触（原剖面 46/93/140）在只有"≤本体"封顶时仍会被
   重新硬成 46/116/140；加"只削不抬"后 106 保持不动。
4. 锚定（mask 内 ≥thr、mask 外 ≤thr-1）保留 → 输出 mask 与输入完全一致 = 严格幂等。

## 「仅主线条」细线失效根因（本轮诊断，未改代码）

1. `binaryOpen(lineMask, r=2)` 按**结构元宽度**筛，等价「线宽 < 5px 一律抹除」→ 细线不进入距离场；

   5px 线 sd 剖面 [1,2,1] 类，卷积后 ≈ −0.97 → `cov = 0`。实测 5px 削到 1px(α255→37)、≤4px 全塌。

## 「仅主线条」二次缺陷：连点变细→断裂（迭代棘轮）+ 平滑范围上限 12→9（本轮，已改代码并验收）

### 根因：不是「一次削太多」，而是**迭代棘轮**
用 `probe_iter.mjs` 把输出反馈为输入连跑 6 次 → 确认变细/断裂是**累积**的，且与掩膜几何无关。
逐步剖面（`probe_stage.mjs`，单列打印 half/sd/σidx/sdB/cov/bodyBlur/outα）定位到两条同源机制：
1. **掩膜最外环的 sdB 恒 ≈ 0.5**：该像素邻域必然含一个背景像素（sd = −1），高斯后中心值被拉到 0.5 附近。
   而旧 `band = max(0.7, radius*0.13)` 在 radius=8 时 = 1.04 > 格子间距 1px
   ⇒ `cov = smoothstep(0.5/1.04) ≈ 0.46~0.57`，**每一轮都把最外环砍掉一半**。
   掩膜几何每轮相同 ⇒ `cov·alpha` 是纯几何衰减：128→104→85→69→56→…→跌破 `THR=16` 后**新的一环继续被砍** ⇒ 断裂。
2. **零交点内移**：`δ = σ·s(h/σ)`。旧 `SIGMA_THICK_RATIO = 1.25`（σ ≤ 0.8×线宽）时 h/σ ≈ 1.33 → δ 显著；
   线越细 σ 相对越大 → 细线先碎（与用户截图一致）。

| # | 位置 | 改动 |

| 2 | 常量 | `SIGMA_THICK_RATIO` **1.25 → 1.80**（σ ≤ 0.56×线宽 ⇒ h/σ ≥ 1.75 ⇒ δ ≤ 0.02σ）；`SIGMA_WINDOW_RATIO` 1.5 → 2.00（窗口须 ≥1.8σ−0.5，否则粗线边缘取不到本档） |
| 3 | Phase C `density` | `density = bodyBlur*bodyScale` → **`max(alpha[i], bodyBlur[i]*bodyScale)`**（仅 `alpha > THR` 分支）。消掉「每轮边缘被压暗 1 级」的观感漂移 |

## 「仅主线条」三次缺陷：粗细波浪拉平无力（诊断 + 原型验证；已于同日落地，见文末第四节）

用户反馈：笔触上「起伏的波浪」拉平效果差。实测确认 **拉平率 ≈ 1%，且与参数无关**。

### 根因（定量，非参数问题）
对「边界位置信号」做尺度 σ 的高斯低通，剩余系数 `exp(−2π²σ²/λ²)`；
而 σ 被线宽封顶（`SIGMA_THICK_RATIO=1.80` ⇒ σ ≤ 半宽/1.8 ≈ 13.3px，半宽 24px），
起伏波长实测 λ = 307/384/513px（振幅 3.5–4.6px，均宽 24.16px）⇒ 剩余 0.977–0.999
⇒ **只能抹掉 0.1%–2.3%**。**σ 比起伏波长小 30–100 倍，算子尺度不匹配，改参数无解。**

### 结论：必须引入「沿笔轴」的宽度低通（跨尺度），SDF 各向同性高斯做不到
验证过的机制（**偏置式，不做几何重采样**）：
```
h  = d(ridge)                        # 脊线（d 的 ρd=8 邻域局部极大）处 d 值 = 局部半宽
H1 = splat_regress(h, σ1=18px)       # 高斯散播回归 → 全窗口宽度场
H2 = norm_blur(H1, R)                # 归一化大尺度低通（必须连权重一起模糊！）
Δ  = clamp(H1 − H2, ±0.35H1, ±12px)
sd' = sd − Δ   →  cov = smoothstep(sd'/band)     # 直接挂 Phase C
```
实测（真实用户笔触）：λ384 波幅 4.56 → R250 **1.86（−59%）** / R450 **1.24（−73%）** / R700 1.02（−78%）；
均宽 24.16 → 23.97/24.08（**无系统性胖瘦**）；R250/R450 保留整体锥度，R700 近均匀宽度。幂等收敛比 0.19（二阶）。

### 踩过并废弃的两条路（勿重走）
1. **几何径向重采样**（每个墨像素取最近边界像素的 (m,k)，`x' = m+(x−m)k`）：
   宽度确实拉平了，但分片映射不连续 → **1px 梳齿毛边**。已废弃。
2. **法向步进配对求 h = |bc|/2**：带步长量化 + 掩码阶梯噪声，且会产出 h=60px 的坏对（∈130px 上限），
   **机制不幂等**（二次点击反而更糙）。改用脊线 `d` 后稳定。

### 其它坑
- **归一化低通**必须 `blur(H1·w)/blur(w)`；否则无样点区的 0 把结果整体拉低（首版假象：−11.5px 全局收缩）。
- **散播核半径要覆盖最大半宽**（σ1=18 → 半径 54 ≥ 最大半宽 38.5），否则最粗处的轮廓收不到 Δ。
- **R 必须 ≫ σ1**：R=120（box r=60）时 H2≈H1，Δ 退化为 σ1 尺度噪声 → 残差 **+25% 反效果**。可用区间 R ≥ 250。

## 23:00–23:45｜宽度拉平「三次修复」：中轴跟随（用户截图「平缓的一侧被吸出凹陷」）

用户第二张反馈截图：笔触一侧平缓、一侧有起伏，平滑后**平缓的那一侧被向内吸出一道轻微凹陷**（红线标注）。

### 根因（机制级，不是调参）
`Δ = H1 − H2` 是**横截面内的标量常数**，对两侧轮廓一视同仁 ⇒ 偏置 `sd -= Δ` 让零等值线**整体平移**、
中轴被迫留在原地 ⇒ 只有一侧凸起时，平缓的另一侧被推入同样的量。合成用例实测左轮廓 252→254（ΔL=+2）。

### 修法：中轴跟随
目标轮廓 = 两侧**各自**沿走向的低频。令 `δh = H1−H2`（半宽超额，即旧 Δ）、`δc = c − c_low`（中轴相对其低频的位移），
则 **左轮廓内推 = δh − δc、右轮廓内推 = δh + δc**；对称场景 δc≡0 ⇒ 退化为旧行为**逐值一致**。
分侧**不需要**显式估计走向/主轴：`half` 的梯度在轮廓处恒指向线内（左 +t、右 −t），`δc·ĝ` 自动带符号。
中轴取「格内以 half 为权重的质心」。实现链：③ 累加质心（必须在 for-x 作用域内）→ ④ 脊线采样带出 →
⑤.1 与 H1 同尺度归一化散播 → ⑥.5 求 δc → ⑦ `d -= δc·ĝ`。
常量 `FLAT_CENTER_DEAD=0.5 / FLAT_CENTER_CLAMP=12 / FLAT_AXIS_RATIO=2.0`。

### ⚠️ 落地期两个缺陷（都靠台架抓到，都已修）
1. **去趋势通道索引转置**：`stride = alongY ? 1 : gw` ✗ → `? gw : 1` ✓。扁平下标 `k=gy·gw+gx`，
   平行于轴的通道在沿 y 时步长必须是 `gw`。写反后通道变成「按行主序斜穿网格」的一串格子，横跨笔画、
   x 质心剧烈跳变 ⇒ 最小二乘拟合出假斜率把 δc 凭空抬到几像素。
   **症状**：所有严格对称场景偏离旧版 8502~16093 字节、幂等二遍差 664→8811（13×）。修正后**对称类全部归零**、幂等 654/511（优于旧版）。
