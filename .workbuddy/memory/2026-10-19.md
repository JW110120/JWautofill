## 0x013B：键盘回调诊断 + 两处放行闸门加固

**用户报（第三次，0x013A 部署后）**：热键始终失效、录制中按键无法录制、之前录好的快捷键加载后看不到。

**取证（只读，未改 C 前的实证）**
- `pi8li.log` 全量 `grep -c "热键命中"` = **0**、`"已捕获组合键"` = **0**，而「录制已开始」多次 ⇒ 面板→C 指令通路正常、钩子确实装着（13:40:59.350「键盘钩子已安装」）。
- 同线程 / 同 hMod / 同安装方式的**鼠标 LL 钩子工作正常**（`[mse]` 计数 + 断流期落笔推断日志在跑）⇒ LL 回调机制本身没问题 ⇒ 问题必在 `kh_dispatch` 前置闸门。
- 录制两次 recordStart 间隔 111ms（App + 工具箱两个面板上下文各发一次），属既有行为，非根因。

**两条独立根因**
1. **按键从未被处理**（录制 + 命中双失灵）：`kh_dispatch` 里 `if (flags & (1u<<30)) return CallNextHookEx(...)` —— `KBDLLHOOKSTRUCT.flags` 的 LLKHF_* 只定义低字节，**bit30 是未定义位**；某些键盘驱动 / 远程输入栈 / KVM 置高位时等于整机按键被静默放行，且零日志。另 `kh_ps_foreground()` 只靠 `g_khPidBuf`（toolhelp 枚举）判定，pid 表为空/未刷新即恒 0 ⇒ 同样全放行（.8li 明明就在 PS 进程内）。
2. **已录条目消失**：`13:06:37` 旧版（漏括号）在「配置已写入 1/2/3 条」与「配置读取/解析失败」间每 ~10ms 振荡，把文件写成残缺；`13:30:21` 新版兼容读取只剩 **2 条**，`13:33–13:37` 面板补默认条目后固定为 4 条系统条目（main_toggle/focus_lasso/focus_clear/blend_hotkey）。属 0x013A 修复前的历史事故余波，数据已不可从该文件恢复。

**修复（keyhook.c 四处）**
1. 删掉 `flags & (1u<<30) ⇒ 放行`，改为首次留痕不拦（LL 钩子本就收不到自身 repeat）；
2. 录制分支**前移到前台判定之前**（录制是面板显式发起的短会话，有 Esc/关面板/超时三重退出，不该被前台判定单点拖死）；
3. `kh_ps_foreground()` 增加 `pid == GetCurrentProcessId()` 直接放行（不依赖 pid 表）；
4. 诊断留痕（零 I/O，走 kh_hlog 入队，每处只打一次/2s 节流）：`★诊断：键盘回调首次进入`、`★诊断：前台判定失败 ⇒ 放行 vk/fgPid/本pid/表内`、`★诊断：按键带 flags 高位`、启动期 `psPid 表：N 个 photoshop.exe（本进程 / 此刻前台 fgPid）`；`kh_install_hook` 日志改打真实 hMod 值。

**验证**：`build.sh` 零告警（-Wall -Wextra）+ PiPL 162 字节往返一致；产物 334848B md5 `100c32d2` 已部署 `Adobe Photoshop 2026/Plug-ins/`（旧版备份 `%LOCALAPPDATA%\JWautofill\JWautofillHost.8li.bak-1348`）。UXP 侧零改动。

**下次启动 PS 的判读口径**：有「★诊断：键盘回调首次进入」= 钩子活着，看后面紧跟哪条闸门日志；**完全没有这一行** = 回调没被系统调用，方向转为换安装方式（hMod=NULL / 主线程装 / 改 RegisterHotKey 或 RawInput），不要再在闸门里找。
