## 0x0215 · 临时多边形套索的 8 方向角度吸附

**需求**：开平滑主开关时，套索按 Alt 临时切多边形套索，折线段吸附上下左右 + 4 个 45°。

**关键依据**：折线的橡皮筋/落点都是 PS 用**包坐标**画的（O51 的「折线预览抖」正是证据），
所以投影包坐标即可吸附，不必动 `GetCursorPos`。

**实现**（`smooth_engine.c` 新增 `poly_snap_run()`，紧跟 0x0214 的冻结之后）：
* 锚点 = 折线起点：一笔之中取 `g_ox/g_oy`（= 圆心），悬空取当下光标。
* 用**比值**判最近方向（水平 `|dy|/|dx|`、垂直 `|dx|/|dy|`、45° `||dy|−|dx||/(|dx|+|dy|)`），
  ⛔ 不调 `atan2`（detour 不依赖 libm）；容差 `POLY_SNAP_TOL_DEG=10°`，超出原样透传。
* 吸附后保持长度反算回轴空间（`cX/cY`）；锚点只在 `buttons` 0→1 且移动 ≥6 逻辑 px 时更新，
  ⛔ 用吸附后的落点当新锚点。
* ⛔ 只写包不动 `g_ox/g_oy`；⛔ 与冻结同批互斥；⛔ 只在套索工具 + 主开关时接管。
* `jw8li_version 0x0214 → 0x0215`；面板 `helpTexts.ts` 的 `smoothEnabledSwitch` 补一句说明。

**校验**：`build.sh` 零告警 + PiPL 往返一致；`yarn build` 通过（仅体积告警）。未提交 git。

**待真机确认**：① 靠近平行/垂直/45° 自动对齐；② 偏差 >10° 自由绘制；

## 0x021F：px 是比例不是坐标 —— 轴↔屏幕只许用差值（15:23 构建 + 已部署）

用户反馈（0x021E 之后）：上一版的「圆心→正上方远处」没了（拒绝闸生效），但按住 Alt

（截图里看到光标右側一个 `-|` 形的交点，青色线从那里向下延伸出画布）。

日志（`jwwh-8284.log`）三组硬数据，直接定死：
1. `[status] pxX=0.0625 **pxY=-0.0625**` —— **Y 比例是负的**（Wintab Y 向上正、屏幕 Y 向下）。
   而 `px` 只是**比例**：轴 → 屏幕还需要**原点偏移**。旧代码写的是 `屏幕 = 轴 × px`
   ⇒ 轴值 12256 变成 −807，跑到屏幕上方外面。
2. `吸附样本：锚点(1406,**-807**) 原始Δ(0,1438) → 吸附Δ(0,1438)`
   —— 锚点在屏幕外，参考线从屏幕外拉进来（就是用户看到的 `-|` 竖线）。
3. `（包路径）锚点 (22496,**-2147483648**)` —— 轴锚点成了 INT_MIN（`(LONG)NaN/溢出`）。
4. `接触包改写 424 次` 而 `消息层 见 0 条` —— 这轮 `DispatchMessageW` 的 IAT 槽没挂上，
   全由包路径扛；而 `poly_pkt_click` 正拿**屏幕点 `/ px` 反算轴**（同样缺偏移）
   ⇒ 写进包的是垃圾坐标 ⇒ 选区被拉到下方远端。

**根因一句话**：本插件里从来没有「轴 ↔ 屏幕」的完整映射（HUD 与光标路径全程在屏幕域，
包路径全程在轴域），而我在 0x021B–0x021E 三次跨域换算里全都写成了单纯乘除比例。

**改法**（`smooth_engine.c`，目标是彻底取消跨域换算）：
1. `poly_anchor_push()`：搬锚点直接取 `se_real_GetCursorPos()` —— 解冻补线的末端**就是**
   此刻光标；拿不到光标就**放弃这次搬锚**（保留旧锚点），绝不写猜出来的坐标。
2. `g_polyHoldX/Y`（冻结钉住点）= `光标基准 + (圆心轴 − 进场raw轴) × px`。
   差值换算 ⇒ 常量偏移自动抵消；基准取进场那一刻的真实光标。
3. `poly_pkt_click` 改为**轴域**：接触边沿时用 `poly_proj(s_snapAx, s_snapAy, 本包raw)`
   直接得轴吸附点 `s_pkPinAx/Ay`，整个接触期间每包写同一个轴点（`pk_put` 只收轴坐标）。
   `poly_snap_run` 在 `g_pkPinOn` 时整批让位，**但不清 `s_snapOn/锚点`**。
4. `poly_snap_run` 在消息层活着时从「整段让位」改为「只不改包（`writePkt=0`）、仍推进锚点」
   —— 否则 `poly_pkt_click` 拿到永不前进的旧锚点，第二段起全错。

**HUD 交替闪**的成因与修法：`fits` 决定窗口中心选「线段中点」还是「吸附点」，hspan
在 `hudSize` 上限附近抖动时布尔值逐帧翻转 ⇒ 窗口两点间来回跳。加 **96/8px 滞回**
（`s_hintFits`）；`poly_hint_live` 保持时间单独放宽到 **350ms**（新增 `POLY_HINT_KEEP_MS`，
接触锁仍用 150ms）；并拒绝画「两端相差 > 4000px」的参考线。

**校验**：`build.sh` 零告警 + PiPL 往返一致（162 字节），369,664 字节；
`jw8li_version 0x021E → 0x021F`；CFG_NLONGS 仍 60；面板无改动。
**部署**：`cmp` 逐字节一致（需完全退出 PS 重启才生效）。

### 同日第三轮：像素级定位到根因（UXP border 两条静默失效）

用户截图仍报「选中项与参数之间有一条线」+「参数盒左右下是黑色、不是边框色」。
写了个 PNG 解码脚本（`analysis/_px.cjs`，gitignored）逐行取色，**证据坐实**：

- 面板底 `50,50,50`（`--bg-color`）、选中格底 `64,64,64`（`--entry-bg`）、
  tab 描边 `95,95,95`（`--border-color`，darkest 档）—— 三个变量都对得上。
- y=35（交界行）：只有中间 71px 是 `95`，两侧是 `50` ⇒ **选中格底边是灰线（没换成底色）、
  未选中格根本没有底边**。
- 参数盒左右边框 `0,0,0` 纯黑，上边则确实不存在。

根因两条，都是 UXP 解析缺陷（静态注入的 CSS 里 `var()` 本身没问题）：

1. ⛔⛔⛔ `border-<side>-color` 长属性**静默失效**（带 `var()` 也不换色，不报错）⇒
   底边永远取 `border-color` 简写的值，那条线就横在选中项下方。
2. ⛔⛔⛔ `border-top: 0` 这类**缺省 color 的单边简写**会把整条 border 的颜色冲成
   currentColor = `rgb(0,0,0)`，所以左右下变黑。

改法：单边一律**完整简写**（width+style+color）；「去掉一条边」＝宽度不动、颜色换同底色。
`app.css` 三处 + `common.css` 参数盒四边逐条显式写，参数盒圆角顺带改 `0 0 3px 3px`
（顶边已被换成盒身色，上角方圆看不出；但首/末格时盒子竖边要接上格子竖边，上角必须方）。
✅ 先例 `.bs-tabs { border-bottom: 1px solid … }` 只画下边线没多出三边 ⇒ 完整单边简写可靠。

校验：3 个 guard 全绿、`yarn build` 通过，产物里 `border-*-color` 与 `border-top: 0`
在本主题域已清零（源码仅注释里留有说明）。

### 同日第四轮：再定位 —— UXP 的 border 粒度是「整条」

第三轮改完仍不对。再采样（`clipboard-2026-10-29T08-31-02-056Z`）：
交界行 `y=43` 整段仍是 `95,95,95`（选中格底边没换色）；
参数盒从 `y=44` 起 `5-218` 全是 `64,64,64` —— **四条单边简写里只有第一条 `border-top`
生效，且扩散到四边**，于是参数盒三边也丢了。

**结论（比前两轮更本质）：UXP 每个元素只有一条 border，四边永远同宽同色。
任何 `border-*` 声明都作用于整条。** 前两轮的「长属性失效」「`border-top: 0` 变黑」
都是这条总规则的不同侧面。⇒ 单边 border 在这套引擎里无解。

用户给出构图口径（选中「拉绳」为例）：轮廓 = 拉绳的上/左/右 + 标准的下边缘 +
追笔的下边缘 + 参数盒的左/下/右。

改用 `box-shadow` 逐边画线（每条边一条阴影，不写＝不画）：
- 格：`border: 0`；未选中 `inset 0 -1px 0`（只有底边＝盒顶边）；选中
  `inset 0 1px / 1px 0 / -1px 0`（上左右，**无底边**）。
- 参数盒：`border: 0` + `inset 1px 0 / -1px 0 / 0 -1px`（左下右，**无顶边**），
  圆角 `0 0 3px 3px`。
三格与盒都 `border:0` ⇒ 线条落在同一 x 上对齐；去掉 border 后内容区左右各宽 1px（可接受）。

校验：CSS guard 绿、build 通过。**唯一未知**：UXP 是否渲染多值 box-shadow
（仓里既有 box-shadow 全是单值）。若整条不渲染，退化＝「线消失」而非错色错位；
彻底兜底方案是加一层 wrapper 用「背景色＋1px padding」画边框（必然可行，但要动 TSX）。

### 同日第五轮：多值 box-shadow 确认不渲染；用户点破关键 —— 宽度本来就能单边

真机：**完全没边框**（多值 inset 阴影整体不渲染，仓里既有 box-shadow 全是单值）。
用户同时指出：早前那版 `border-top: 0` 的截图里，参数盒明明有「左/下/右三条边、没有上边」，
只是颜色是黑的 —— 所以「单边画不出来」这个结论是我判错了。

重新归纳（唯一能解释全部四次的说法）：
**UXP 的 border：宽度/样式逐边、颜色整条共享一个值。**
- `border-top: 0` 让上边归零、另三边保持 1px ⇒ 宽度逐边成立 ✓
- 但它缺 color ⇒ 共享色被刷成 currentColor = `rgb(0,0,0)` ⇒ 三边黑
- `border-<side>-color` 长属性改不动共享值 ⇒ 静默无效
- 四条单边简写各带 color ⇒ 共享值被反复覆盖 ⇒ 四边同色

解法（三连，顺序是硬约束）：
`border: 1px solid var(--border-color)` → `border-<side>: 0` → **最后补 `border-color: var(--border-color)`**。
`border-color` 只写颜色、不碰逐边宽度，所以归零的边不会被撑回来。
三处落地：未选中格 `top/left/right:0`（只留底边）、选中格 `bottom:0`（上左右）、
参数盒 `top:0`（左/下/右）。box-shadow 方案全部撤掉。

校验：CSS guard 绿、build 通过，编译产物确认 `border-color` 都排在 `border-*-0` 之后。

## 0x0222 · Alt 期间 HUD 只许是参考线（修「落笔前闪一下平滑 HUD」）

**用户报**：开启吸附后（平滑开不开都一样），按 Alt 切多边形套索，落笔前把光标从一个吸附

**根因两根因叠加（全在 HUD 线程显隐层，前端与包路径无关）**
- ① 参考线靠 `g_polyHintMs` 衰减（`POLY_HINT_KEEP_MS`=350ms），超出即 `polyHint=0`；
  `wantVisible` 是「主门槛 ∨ 参考线」，主门槛在 Alt 期间已被 `gateOk` 归零 ⇒ 本该为假，
  但它管不住**已经可见的窗口**；
- ② 90ms **隐藏去抖**把窗口「维持显示」，而绘制分支的判据只有 `!polyHint`
  ⇒ 立刻改画圆/绳，且 `putValid=0` ⇒ 圆心取当下光标 ⇒ 光标处闪出一个圆，90ms 后隐藏。
  ⇒ 那句总结：**隐藏去抖是为「圆」的帧间抖动设计的，对「参考线掉线」毫无意义。**

**改法（引擎 HUD 线程三处）**
- `int polyAltHold = (g_cfg && g_cfg[CFG_I_POLYALT]) ? 1 : 0;`
- `wantVisible = polyAltHold ? polyHint : (((cheapOk && canvasOk) || polyHint) ? 1 : 0);`
- 隐藏去抖分支加 `&& !polyAltHold`（Alt 期间立即隐藏）；
- 隐藏边沿改成 `if (!polyAltHold) s_hudHideAt = now;`
  —— `s_hudHideAt` 只服务「刚隐藏过⇒重现等 180ms」，Alt 期间的隐藏是**正常节拍**
  （每次脱离吸附都会发生），记进去会让「松开 Alt 立刻起笔」第一笔圆白等 180ms。
- ⛔ 判据用物理 `I_POLYALT` 而非吸附开关（吸附关掉时 Alt 期间同样不该出圆）。
- 版本 `jw8li_version` 0x0221 → **0x0222**，槽位无变化（`CFG_NLONGS` 仍 61），前端零改动。
