# 像素算法详述（JWautofill）

> MEMORY.md 的展开页。改这些处理器前先读本文件。

## 分块平均 / 对比减弱（blockAverageProcessor.ts）
- 「分块」= **不连通选区各自成块**，普通模式各自求均值填平。
- 对比减弱 `factor=(coeff/255)·(强度×0.07)·t/(1+t)`，`t=|亮度−块均值亮度|/max(σ_L,6)`；α 用同一 factor 但不乘 φ。
- **内置混合颜色带柔化（写死、不暴露 UI、无持久化）** `φ = clamp(1−(u−1.5τ)/4.5τ, 0, 1)`，只作用于 RGB。

## 梯度修改（gradientRelaxProcessor.ts）
- 写回只影响原本 alpha>0 的像素；末尾反预乘 pass 对「a=0 或选区外」整像素还原原始字节（预乘往返有 ±1 漂移）。
- 负值 alpha 走 blurAlpha 邻域加权均值，a=0 冻结 ⇒ 放缓只能向内摊，不回扩 alpha。

## alpha 对齐（alphaAlignProcessor.ts **v10 三档整片归一**）
- **v10 语义（2026-09-23 用户二次纠正）**：三个按钮共用同一次「**选区**直方图」，只是取的统计量不同，动作都是**整片归一**：
  **上对齐 = 选区内 alpha 的最大值**（最深档）；**下对齐 = 选区内 alpha 的最小值**（最浅档，"与之对应"）；
  **众对齐 = 众数**（`processAlphaModeAlign`，独立函数，本轮未改）。
- 实现：直方图 = **选区本身**（v10 起不再用 halo；`ALPHA_ALIGN_HALO` 已删，外部无引用），只统计 `a ≥ MIN_ALPHA(32)`；
  `target = alignUp ? maxA : minA`；写回 `na = round(a + (target - a) × rate × fade)` 覆盖选区内**所有** `a ≥ 32` 像素，
  **没有任何"找不到参照就跳过"的分支** ⇒ 结构上不可能有遗留；目标只依赖直方图 ⇒ 同一 alpha 处处同一结果（完全空间一致）。
  唯一跳过 `a < MIN_ALPHA`。常量只剩 `MIN_ALPHA / FEATHER_RADIUS / EXTREME_WARN_SHARE`。
- ⚠️ **为什么极值必须从 `a ≥ 32` 起算**：低于 32 的是没擦干净的残留与 AA 尘埃。实测恢复素材 `min=32` 只有 116px ⇒
  整片 mean 74.22 → **29.53**（等于擦掉画面）。用户自己的稿子 AA 全在 32 以下（域内全 ≥82）⇒ 该下限对他无副作用；
  若某稿 AA 落在 32~80，"最小值"就会落在 AA 尾上（日志会打 ⚠️ 提示）。
- ⚠️ **已知取舍（用户选定，勿擅自加门槛）**：极值档可能是**孤立极值** ⇒ 整片被它带走。实测 `_real` 代理素材 `max=168`
  只有 **1px**、`_aa_like` 的 `max=207` 有 48px。v9 用"同侧计数最多 + 规模门槛"规避过，但那是用户**明确否掉**的方向
  （他要的就是"极值"这个统计量）。v10 不加门槛，只在 console 对占比 <1% 的基准档打 ⚠️（`EXTREME_WARN_SHARE`）。
  真要排除孤立极值就缩小选区（或先清理那些像素）。
- ⚠️ **硬事实**（决定了"只抬偏淡像素"这条路必然失败）：用户 3508×2480 画稿（选区内容 181×779）console：域内像素 30642、
  **基准 87 占 45.3%、像素全部 ≥ 82**（`<32` 的残留只有 1297 个）。v8 的 `a < baseA-5 → baseA` 在这类稿上数学恒为空转
  （修改像素数=0）—— 不是 bug，是语义与画稿不匹配。**任何"只动偏离基准那一侧"的设计都会在"内容全在基准一侧"的稿上空转。**
- **实测**（台架 `outputs/aa_run.cjs`；日志 `_v10_run.txt` / `_v10_run2.txt` / `_v10_hist.txt`；台架用**全图选区**）：

    下对齐 基准=最浅 87（19335 个 / 82.6%）→ **全 87**、改 4063、mean 97.76→87.00、粗糙度 **0.000**；
    上对齐 基准=最深 207（48 个 / 0.2%）→ **全 207**、改 23350、粗糙度 **0.000**（v8 时上对齐在这里是 0 改动）。

## 消除锯齿（aliasSmoothProcessor.ts）
- 覆盖率重建 mask(alpha≥thr)→box 模糊→4×4 子采样 cov→`aRecon = 本体不透明度 × profile(cov)`。
- **四条不变量**：
  ①阈值取「选区内 alpha 直方图众数/2」且只依赖胜出档下边界；
  ②本体不透明度由 EDT 从「距轮廓 ≥2px」的种子传播（窄条 ≤5px 整段当种子）、**硬性封顶 `aRecon ≤ 本体`**、
  **循环里必须 `if (distOut2 >= 4) continue`**；
  ③内侧只削不抬、外侧只补不削；
  ④锚定 mask 内 ≥thr / 外 ≤thr-1 → 输出 mask 不变 = 严格幂等。
- 细线（≤4px）走几何重建：游程→链→平台中心插值→刚性带宽（众数厚度）→墨量守恒 `ink·cov/Σcov`。
- 铁律：墨量跨距取几何区间 `[⌊eT⌋,⌈eB⌉-1]`（取 mask 游程会让肩部掉出 mask、墨量逐轮流失）；
  幂等闸门 = 以本行游程内最大 alpha 为基准、窗口内出现 0.25~0.75 基准像素的行过半即判已平滑（只认领不改写）；
  「有任何中间 alpha」会被硬边毛刺全拦掉，用全链最大则压感渐变整段误判；主路径用 thinScope+thinDone 避让、认领游程 ±2px。
- ⚠️ `estimateBodyLevel` 直方图必须**按墨量投票**（`hist[a>>3] += a` 而非 `++`；细线毛刺像素比本体多 → 按个数投票 thr 会落到毛刺档）。
- ⚠️ `makePlateauInterp` 首/尾平台常被链边界截断 → 按典型平台长度重建中心；写出循环不写链外一行；
  被 `aRecon ≤ a0` 截断丢的墨转投外侧肩部。
- 脚本 outputs/alias_smooth_test.cjs + alias_compare_old_new.cjs。

## 「仅主线条」边缘平滑（lineSmoothProcessor.ts）
- 管线：A 开运算+SDF（双 Felzenszwalb 精确 EDT）→ A.5 原线 8 连通域（面积/小杂点）→ B 高斯（σ 几何 / σ·0.55 密度抛光）→
  中值归一 → C 多源 BFS 近旁源 + `cov = smoothstep(sdB/band)` → D 去孤立点 → E.5 分量覆盖率 → E 写回。
- **窗口化**：只算「选区包围盒 + halo」，`halo = max(8, 2·kr+8)`，`kr = ceil(3σ) ≤ 10`。
  1000² 选区在 4000² 文档：旧 16M 像素 → 1.1M；实测 4000² 文档 1000×1000 选区 17.1s → **478ms（35.8×）**，
  2000² 文档同选区 2966→465ms（6.4×），1000² 全图选区 724→369ms（2.0×），5000×4000 文档 +1500×1200 选区 845ms。
  halo 依据：截断对选区影响按 `exp(-(halo-kr)²/2σ²)≈1e-7` 衰减；截断只会让距离变小、不会变大。
- ⚠️ **已知语义代价**：E.5「分量覆盖率」是连通域级统计量，窗口化后只能按窗口内可见碎片统计 → 跨边界连通域判定可能与旧版不同。
  实测（合成交叉细线稿）：全图选区 **0 差异**（逐字节一致）；1000² 0.01%；200² 0.28%；极小选区落在密集细线区最多 ~3%。
  **方向恒为「新保留、旧清除」**（偏保守、不误删）。试过「只统计选区内分量」（更差）与 halo=96（部分场景有效且 +28% 耗时）→ 维持现状。
- ⚠️ 重构期踩过并修掉：`nearSrc` 存局部索引 → 写回取色必须换算回全图坐标（否则 RGB 全 0）；
  中位数不能取整档（medBlur 差 0.019 → 系统性压暗 1 级）→ 现用「三级直方图细化到 1/65536」。
- 回归台架（全在 `analysis/line_vis/`）：`ab_planA.mjs`（S1~S11 场景矩阵）、`probe_iter*.mjs`（连点 N 次收敛）、
  `probe_fix*.mjs`（带宽/σ判据/密度抛光候选对比）、`probe_fix4.mjs`（**墨量质心抖动** = 不受边缘压暗影响的几何平滑度）、
  `verify_final.mjs`（真实 src 验收）、`make_*_cand*.mjs`（按行替换生成候选副本）+ `_cand/`、`_old/`。
  旧实现备份 `analysis/line_vis/_old/lineSmoothProcessor_head.ts`（= git HEAD 版）。

### 细线失效 → 已修（2026-09-18）
**旧版三条同源机制**（`binaryOpen(r=2)` 按结构元宽度筛 = 线宽<5px 一律抹除；σ=3.0 与细线半宽同量级
→ sd 高斯后中心变负；E.5 连通域连坐 ⇒ 细线只要与宽实体同连通域就整段归零）。

**现行实现（方案 A + 方案 B，2026-09-18 两次修复后）**：
- Phase A 用**面积开运算**（复用 A.5 的 8 连通域面积 / `isSpeck` 同一判据）取代半径开运算；线宽不再参与筛选。
- Phase B 前置做**逐像素自适应 σ**：档位 `σ_user / 0.66σ / 0.44σ / 0.5`，选「以 i 为中心、半径 `2.0σ` 的窗口内
  存在内切半径 ≥ `1.8σ` 的线内像素」的最大档，等价 **σ ≤ 0.56 × 该处结构线宽**。
  常量 `SIGMA_THICK_RATIO=1.80`、`SIGMA_WINDOW_RATIO=2.00`、`SIGMA_MIN=0.5`、`SIGMA_MAX=3.2`。
  窗口存在性用积分图查询（O(1)/像素）。窗口半径必须 ≥ `1.8σ-0.5`，否则粗线边缘够不着核心 → 边缘掉档出现跳变。
- Phase B 几何抛光逐档高斯、按 `sigmaIdx` 取用；**密度抛光只对最高档生效**。
- Phase C 抗锯齿 `band = BAND_LATTICE = 0.30` **定值**（格子尺度，不随 σ/radius 缩放）；密度取
  `max(原线像素自身 alpha, 抛光密度)`。
- `buildSignedDistance` 顺带输出 `half`（线内像素到最近背景的精确欧氏距离），同一次 EDT 的副产品。

**⚠️ 已证伪的错误判据**：第一版用「像素自身的 EDT 距离」当线宽（σ ≤ 0.4×2·half_i）。
任何形状的边界像素到最近背景都只有 1px → 粗线边缘被误判成细线 → σ 被压到最低档 → 高斯核不再跨过边缘
→ **平滑能力掉到 1/4**（24px 锯齿线改动量 3106 像素/平均Δα 53.2 → 880/2.9），且边缘剖面变成非单调的
`255,255,255,251,254`。判据必须问「附近有没有足够粗的结构」，不是「这个像素自己离边界多近」。

**🔴 二次缺陷：连点变细 → 碎裂「棘轮」（2026-09-18 晚诊断并修复）**
用户反馈「变细趋势强，多次点击后线条碎掉/断开」。根因**不是** σ 太大，而是**抗锯齿带宽比格子间距还宽**：
- 任何形状的「掩码最外圈像素」sd 恒为 1，但高斯模糊后的 **sdB 恒为 ≈0.5**（它的邻居必有背景像素 sd=−1，
  加权平均必然把它拉低）。实测 7px 掩码 σ1.98 → 0.503；宽线 σ3.0 → 0.567，**与 σ 基本无关**。
- `cov = smoothstep(sdB/band)`，band=1.04(σ 档)/0.69 时最外圈 cov≈0.46~0.82 → 每轮被乘一次 <1 的系数。
  掩码几何每轮完全相同 ⇒ sdB 相同 ⇒ cov 相同 ⇒ **纯等比衰减**。剖面实测 `128→104→85→69→56→…`，
  跌破 THR=16 后离开掩码 → 下一圈成为新的最外圈继续衰减 ⇒ **线宽每 ~4 轮掉 1px，最终断裂**。
- 现状（band≤1.04）连点 12 次：硬边 5px **−76.8%**、软边 8px(峰120) **−74.1% 且碎成 17 段**、
  软边 6px(峰45) **−41.3% / 10 段**、长细交叉网 **−31.1% / 13 段**。
- 次因（σ 判据过松）：`1.25σ` 门槛下 σ=3.0 用在 7px 掩码上（h/σ=1.33），sd 场的 zero-crossing 内移
  δ≈0.33σ（h/σ≥1.75 时 δ≤0.02σ 可忽略），最外圈 sdB 掉到 0.078 → 首轮直接削掉。
- 次因（密度抛光）：对 alpha 再做 σBody=σ·0.55 高斯会把线外的 0 掺进边缘（硬边 12px 最外圈 255→158），
  是又一处减墨源。

**修法（三条同时改，任一单独改都无效）**：
1. `band` → **格子尺度定值 0.30**：`cov(sdB=0.5)=smoothstep(1.67)=1`，最外圈完整保留；
   轮廓真被切到的像素（sdB∈(−0.3,0.3)）仍拿部分值 ⇒ 抗锯齿不减。
2. `SIGMA_THICK_RATIO` 1.25→**1.80**、`SIGMA_WINDOW_RATIO` 1.5→**2.0**：σ ≤ 0.56×线宽，zero-crossing 不移。
3. 密度 → `max(自身 alpha, 抛光密度)`：保底项消除压暗（抛光只保留「抬升内部低值噪点」的作用）。

**实测（真实 src，`verify_final.mjs`）**：连点 12 次硬边 1/3/5/12/24px **全部 0.0%**、分量恒 1；
软边 5px −0.1%、淡线(峰45) 0.0%、8px(峰120) −6.4%、压感渐变 −11.1%（现状 −41%~−74%）。
细线保留率 1~20px 全 ≥99%（7px 由现状 70% → 99%）。性能 208→202ms。
⚠️ **几何平滑力度与旧版相当但不再靠「压暗边缘」伪装**：质心抖动度量下 20px 抖动线 1.985→1.794（旧版 1.764，
但旧版代价是侵蚀）。12px 以上粗线的平滑仍由 σ_user 决定；细线（σ 被封顶）本质只能「原样保留」。
⚠️ 术语陷阱：`σ ≤ 0.4×线宽` 是「不塌缩」底线，`σ ≤ 0.56×线宽` 是「不内移」口径，两者用途不同勿混。

## 「仅主线条」宽度低通拉平 flattenRadius（2026-09-18 已落地）

### 为什么现有 SDF 高斯拉不平粗细波浪
边界位置信号经尺度 σ 高斯低通后剩余系数 `exp(−2π²σ²/λ²)`。σ 被线宽封顶（`SIGMA_THICK_RATIO=1.80` ⇒ σ ≤ 半宽/1.8），
实测半宽 24px ⇒ σ_max 13.3px，而起伏 λ = 307/384/513px ⇒ 剩余 0.977–0.999 ⇒ **只抹掉 0.1%–2.3%**（实测 ≈1%，全参数档位一致）。
⇒ **σ 与 λ 差 30–100 倍，属算子尺度不匹配，调参无解。**

### 落地实现（偏置式，不做几何重采样）
接入点：**Phase A 之后、Phase B 之前**；A.5 顺带统计 `lineCompId / lineCompSize / lineCompBox`（分量包围盒）。
`sd` 字段本身不改写 —— 偏置做在「双线性采样读值」处（改写 sd 场会破坏后续共用 half 的语义）。
```
flattenWidthUndulation 内部：
① 脊线取样：half[i] 在 ρd 邻域内为局部极大 且 half > FLAT_RIDGE_EPS(0.6) → 记为 (网格坐标, half)
② 逐分量隔离：取样/散播/低通都只在本分量网格上做，写回时跳过别的分量墨像素 ⇒ 相邻线条宽度零串味
③ H1 = splat(sv) / splat(sw)   归一化散播回归；散播半径 rSig = maxHalf / (2·FLAT_GRID)（≈半宽一半）
④ H2 = boxBlur3 级联低通，尺度 = flattenRadius；同样「值域/权重域分别模糊再相除」
   ⇒ 网格外 0 填充就是无限域精确解 ⇒ 网格只需盖「包围盒 + 散播支撑」，不必留低通边距
⑤ 细支门槛：ref[k] < FLAT_BODY_RATIO(0.35) · maxHalf ⇒ Δ 归零（ref = **双侧邻域最大半宽**，见「二次修复」）
⑤.5 ref = H1 沿 x/y 两轴的 min(max⁻, max⁺)（切比雪夫半径 rRef 格），取两轴较大者 —— 语义「两侧都至少有 W 那么宽」
⑥ Δ = clamp(H1 − H2, ±FLAT_CLAMP_FRAC(0.50)·ref, ±FLAT_CLAMP_PX(12))
⑦ 写回：cov 计算处按 Δ 双线性采样偏置 sd
```
常量：`FLAT_MAX=700 FLAT_GRID=8 FLAT_EDGE=1.5 FLAT_RIDGE_EPS=0.6 FLAT_CLAMP_FRAC=0.50 FLAT_CLAMP_PX=12
FLAT_MIN_AREA=200 FLAT_SPREAD_MAX=10 FLAT_HALO=96 FLAT_BODY_RATIO=0.35
FLAT_REF_DIV=6 FLAT_REF_MIN=3 FLAT_REF_MAX=10`（rRef = clamp(round(flatR/(6·8)), 3, 10) 格 ⇒ flatR 200/250/450/700 → 24/40/72/80px）
halo：`halo = max(8, 2·kr + 8, flatOn ? FLAT_HALO : 0)`。
参数链：面板 `edgeLineFlatten` → `lineSmoothFlatten`（smartEdgeSmoothProcessor，clamp 0~700）→ `flattenRadius`（lineSmoothProcessor，clamp 0~FLAT_MAX）。

### ⚠️ 落地期踩过并修掉的五个坑
1. **双线串味**（细线 9.00→7.74px、std 0→2.74）：散播半径 `maxHalf/FLAT_GRID` 过大伸到邻线 → 改 `maxHalf/(2·FLAT_GRID)`；
   同时把 box blur 改成**纯卷积求和**（不归一化），值域/权重域分别模糊再相除。
2. **系统性变细**：`FLAT_CLAMP_FRAC` 0.35 会绑住窄相位、Δ 均值 ≠ 0 ⇒ 每轮净减。改 **0.50**。
3. **T 形细支被撑胖**（3px→5px）：同分量共享宽度场，细支的 H2 被主体抬高 ⇒ 加 `FLAT_BODY_RATIO=0.35` 归零。修后发丝全程 3px。
4. **halo 必须含 `FLAT_HALO=96`**，否则散播支撑被截断、选区边缘的 Δ 失真。

### ⚠️ 限幅的非对称陷阱
clamp 上界必须 `±0.50·H1`（不是 0.35）：0.35 把「窄相位」的 Δ 削掉、宽相位却保留满额 ⇒ Δ 均值 ≠ 0 ⇒ 连点系统性变细。

### 二次修复：削平残留 + 凹陷无补偿（2026-09-18 晚，用户截图反馈）

用户反馈两点：「削平的地方还有一些像素残留」「线条中凹陷的区域没有获得补偿」。两个根因独立，互不相关。

**缺陷 A：亚阈值淡边残留**
- 根因：Phase E 的残留清理只覆盖 `isSpeck[i] || (cid>0 && compCovered[cid])`，而 **alpha ≤ THR(16) 的软边像素
  不属于任何连通域**（线掩码要求 alpha > THR ⇒ cid=0）⇒ 任何按 cid 的规则都够不到它。轮廓被拉平内推后，
  这些软边像素留在原地、与新墨之间拉开空隙 ⇒ 变成孤立淡点（实测 alpha≈10，10× 缩放即一个可见浅灰小方块）。
- 修法（Phase E 新增，仅 `flatOn` 生效 ⇒ flat=0 仍逐字节一致）：`a0>0 && a0<=THR` 且 **8 邻域无任何「输出墨」(输出 alpha>0)** ⇒ 清零 RGB+A。

  ② 紧贴新轮廓的淡边是正常抗锯齿过渡必须保留。

**缺陷 B：凹陷被「全局 maxHalf 门槛」整段豁免**

  长细支在靠近粗段的根部会被误判成凹陷而撑胖（破坏 T 形不变量）。双侧 min 额外要求**反方向也是粗段** ⇒
  长细支/毛笔尖沿走向一侧永远细 ⇒ 仍豁免。限幅同步改 `0.50·ref`；因窗口含自身 ⇒ **ref ≥ H1 恒成立**
  ⇒ 凸起与均匀段的限幅与旧版**逐值一致**（不会削弱削平）。
- 变化集可精确刻画：`ref ≥ H1` ⇒ 旧豁免集 ⊇ 新豁免集 ⇒ **唯一变化集 = { H1 < T 且 ref ≥ T }**（= 被粗段夹住的窄段）。

div=8 在 flatR=200 时窗口仅 24px，长凹陷（≈70px）中心看不到粗段 ⇒ 补偿失效；div=12 退化为 MIN 反而更差。

### 三次修复：中轴跟随（2026-09-18 深夜，用户截图「平缓的一侧被吸出凹陷」）

**缺陷 C：单侧凸起时，平缓的另一侧被无辜内推**
- 根因（机制级，不是调参）：`Δ = H1 − H2` 是**横截面内的标量常数**，对两侧轮廓一视同仁。偏置 `sd -= Δ`
  让零等值线**整体平移**、中轴被迫留在原地 ⇒ 只有一侧凸起时，平缓的那一侧被推入同样的量。
  实测 A 用例（左恒定 250、右 260→270）左轮廓 252→254（ΔL=+2），正是用户看到的红线凹陷。
- 修法：目标轮廓 = **两侧各自沿走向的低频**。设 `δh = H1−H2`（半宽超额，即旧 Δ）、`δc = c − c_low`（中轴相对其低频的位移），
  则 **左轮廓内推 = δh − δc、右轮廓内推 = δh + δc**。对称场景 δc≡0 ⇒ 退化为旧行为**逐值一致**。
  分侧**不需要**显式估计笔画走向/主轴：`half`（线内欧氏距离）的梯度在轮廓处恒指向线内（左轮廓 +t、右轮廓 −t），
  `δc·ĝ` 自动带符号。中轴位置取「**格内以 half 为权重的质心**」（比几何中心更贴中轴）。
- 实现链：③ 格内取 max 时同步累加质心 `mx/my/mw`（⚠️ 必须在 for-x 作用域内）→ ④ 脊线采样同时带出 `tx/ty/tw`
  → ⑤.1 与 H1 同尺度、同归一化手法的散播 → ⑥.5 求 δc → ⑦ 施加处 `d -= δc·ĝ`。
- 常量：`FLAT_CENTER_DEAD=0.5`（死区，兜住质心亚像素噪声 ⇒ 对称场景逐值一致）、`FLAT_CENTER_CLAMP=12`（限幅）、
  `FLAT_AXIS_RATIO=2.0`（包围盒长宽比 ≥ 此值才锁定走向；不足则**整体退化**，斜线/团块不冒风险）。

**⚠️ 落地期两个必记缺陷（都已修，都靠台架抓到）**
1. **去趋势通道索引转置**（`stride = alongY ? 1 : gw` ✗ → `? gw : 1` ✓）。扁平下标 `k = gy·gw + gx`，所以
   「平行于轴」的通道在沿 y 时步长是 `gw`、沿 x 时才是 `1`。写反会退化成一串**按行主序斜穿网格**的格子 ——
   它横跨笔画、x 质心值剧烈跳变，最小二乘拟合出的假斜率把 δc 凭空抬到几像素。
   症状：**所有严格对称场景（对称凸起/凹陷/均匀/锥度）全部偏离旧版 8502~16093 字节**，幂等二遍差 664→8811（13×）。

   ⇒ 任何真实变形都有 **`|δc| ≤ |δh|`**（等号 = 单侧变形，δc≡0 = 两侧对称）；而**纯平移/纯路径弯曲**（宽度没变 ⇒ Δ≈0）
   封顶后立刻归零。缺这条时：等宽长弧 δh=0.79 而 δc 被 `FLAT_CENTER_CLAMP` 顶到**饱和 12** ⇒
   左轮廓 d=−8.65、右 +10.23，实测轮廓横移 **左5/右−6px**（旧版对等宽弧完全不动）。封顶后降到 **左−1/右0**。
   （曾试「按 |Δ| 线性门控」，量纲不对：0.79/1.0×12 = 9.44 仍远大于 δh，只把 5px 降到 5px。）

## ⚠️ 写回型像素处理器的边界两条铁律（2026-09-19 高频增强「白边」复发）

**症状**：执行后沿**选区边缘**出现一圈 1px 白边（浅色内容直接顶到 255）；全选时同因而沿**图层自身 alpha 轮廓**也出一圈。
用户对症状的描述是「靠近选区边缘的像素直接缺失了」。

两条铁律（`highFrequencyEnhancer.ts` 已按此重写；台架 `analysis/line_vis/repro_hf_edge.mjs`）：
1. **区域判定只能用「选区掩码 > 0」，不能用「alpha > 0」**。写回范围是 `selectionDocIndices`（掩码>0），
   按 alpha 判定 ⇒ 统计口径 ≠ 写回口径（原实现只有背景图层这两者天然一致）。
2. **采样到「数据缺失」像素（图层外/全透明 ⇒ RGBA 全 0）必须用中心像素值顶替（边缘延拓）**，
   不能把 0 当真实像素参与卷积/方差。

**为什么必成白边**：3×3 高通核是「−1 环 + 中心 8」，邻居全 0 时 `hp = 8c`；5×5 方差同时被 0 拉爆
⇒ `varianceFactor = 1`，`enhanced = c + 8c·k·0.5` 当场饱和到 255（浅粉 238 → 纯白）。

**三路对照台架（可复用到任何写回型处理器）**：
A = 旧处理器 + `selectionPixelData`（复现现象）；B = 旧处理器 + `fullPixelData`（隔离"仅数据源"这一因）；
C = 新处理器 + `fullPixelData`。指标 = 按 `applyProcessedPixels` 系数混合后的**最终 RGB** 与原图之差，
分 `rim / band2 / core` 三区，另报 `A vs C 逐像素 RGB 完全相同比例`（core 应 100%）。

| 场景 | A 旧路径 | B 仅换数据源 | C 修复版 |
|---|---|---|---|
| T1 椭圆选区（实心粉层） | rim Δ亮度 **+9.70**，max 53，172/480 可见、4px 顶白 | 0 | **0** |
| T2 全选（图层 alpha 轮廓） | rim Δ亮度 **+39**，**668/668 全部顶白** | +39（与 A 同 ⇒ 光换数据源不够） | **0** |
| T3 纹理层 + 左半选区 | rim **+38.6**（432/432 可见、379 顶白）；core 改动 **0** | 0 | rim 0；core \|Δ\|0.5 |

**T3 的意外发现（必记）**：旧路径的 `maxIntensity` 被边缘伪影（8c≈700）占据 ⇒ `adaptiveThreshold = 0.33·max`
高到真实纹理永远过不去 ⇒ **白边的同时功能对选区内部几乎失效**（core Δ 恒 0）。
⇒ 凡是「自适应阈值 / 自适应统计量」类算法，**伪影会劫持统计量、连带废掉全局行为**，验收必须同时看 rim 与 core。
