146 **「追笔」只能是滞后驱动，不能是定速追赶**（0x023A）：`step = vmax·dt` 只有「贴合 / 退到半径钳位」两个稳态，人速与 vmax 同区间 ⇒ 滑杆中段全是死区（实测「10–70 无感、80 以上才有」）。现在 `k = dt/(dt+τc)`、`τc = 2.2·radiusPxF·u`、`u = (50-原生catchUp)/49`，稳态滞后 = 笔速×τc，力度 100 ≈ 一个半径。⛔ τc 必须**按半径归一**（否则小半径用户在中段撞钳位）；⛔ 包路径 `smooth_packets` 与光标路径 `gp_step` 必须**逐字同源**，光标路径只多一条 `still` 时 k≥0.5。

148 **标准模式强度必须线性映射 τ，不能指数**（0x023B，2026-11-16）：旧律 `τ = 8ms·(e^(3.4735·t/100)−1)` 把势能挤在 75–100 段，稳态滞后 v·τ 在 t=30 仅 5.9px、t=50 仅 15px（满量程 100px）⇒ 用户实测「1–70 几乎无感知」，与 146 追笔的死区同类。现改 `τ = TAU_MAX_MS·t/100`（250ms 满量程不变，只重分布 1–99），t 与滞后成正比、全程单调可辨。⛔ 满量程 t=100 必须仍是 250ms（上端手感不变）；⛔ 与 146 一样，包路径/光标路径都调 `tau_from_strength()`，改函数体即逐字同源；⛔ 删掉随之失效的 `exp_series()` 否则 -Wall 报 unused-function。面板「追笔速度」标签已改「追笔耗时」、单位 %→「值」（helpTexts 术语同步），语义仍是「数值越大越黏」。详见 `2026-11-16.md`。

149 ⛔ **UXP 的 `Document` 没有 `bounds`**（2026-11-19，0x02 填充线）：只有 `Layer` 才有 `bounds`。`Document.width` / `Document.height` 官方文档写明**就是像素**（Number），`Document.resolution` 是 ppi、与本值无关。⛔ 也别用 `width._value`（batchPlay 那条路，是标尺单位，需要 ×resolution/72，单位一换就算错）。踩坑后果不是报错而是**全链路静默失效**：`getDocPixelSize()` 拿不到尺寸 ⇒ 返回 `{0,0}` ⇒ `blendTopIntoBase` / `compositeTopIntoBase` / `multiplyTopAlphaByBase` 第一行 `return false` ⇒ 特殊剪贴永远退回合并路径（用户实测「开不开选项结果一样」+「上方剪贴被解除」）。

150 ⛔ **PS 里不存在「只释放某一层剪贴」**（2026-11-19）：`ungroup` 与 `Layer.isClippingMask = false`（UXP 里 R/W）都会释放**整组**——官方文档原话 *Releasing a clipping mask will also release the layers above*。ExtendScript 圈传的 `setd → T:{Lyr:{UsrM:false}}` 是**图层蒙版开关**（`userMaskEnabled`），与剪贴无关，别当剪贴用。✅ 正道是**从源头避开**：需要「不参与剪贴的临时层」时，建层前先 `select` 到 `ordinal: front`（最顶层一出生就无剪贴关系），收尾用像素写回 + 删层，全程不碰 `groupEvent` / `ungroup` / `mergeLayersNew`。

151 **填充收尾统一走「写回目标层」而非合并**（2026-11-19）：`rasterize → 严格 applyMask → imaging 写回目标层 → 删内容层 → 选回目标层`。特殊剪贴 = 权重乘基底 alpha（alpha 一字节不动），普通填充 = alpha 取并集（等价一次向下合并）。这样结果与剪贴关系彻底解耦：不再有「合并图层不可用」、不再为纠正裁剪语义去动别人的剪贴层，也不会出现「同一组操作两次结果不同」。⚠️ `applyMask` **必须成功**才允许写回（`imaging` 看不到图层蒙版，蒙版没应用掉等于按整层糊上去）；失败则放弃写回、退回「移到目标层上方 + 合并」。⚠️ 代价是每次填充多 2 次整图 `getPixels` + 1 次 `putPixels`。

152 ⛔ **像素读的 `sourceBounds` 必须按「图层自身 `boundsNoEffects`」，⛔ 不是文档矩形**（2026-11-19 第 6 轮，用户当场纠正）：这和 149（`Document` 没有 `bounds`）是**两件不同的事** —— 149 说的是「文档尺寸怎么取」，本条说的是「读像素时请求哪块区域」。铁律 ③ 的原文（`ClearHandler.readLayerPixels` 注释）写明：按选区读会漏「图层有像素但在选区外」的部分；**全文档 `sourceBounds` 在图层没画满画布时会被 PS 裁剪、甚至直接报 `Missing image`**（`MaskSyncEngine` 实测）⇒ 必须「读图层实有块 → 按**返回的** `sourceBounds.left/top` 索引扩充成 `docWidth × docHeight` 缓冲（块外填 0）→ 整图写回、不传 `targetBounds`」。本仓正确样板 = `ClearHandler` 三件套 `readLayerPixels` / `expandToDocument` / `writeLayerPixels`；`SpecialClipMask` 的 `readBlock` / `expandToDocument` / `writeDocument` 必须与之逐条同口径，改任一侧前先对照另一侧。取不到图层边界时**只允许回退文档矩形并 warn**，绝不把「请求区域」当「块形状」用（那会整体错位）。

153 **像素写回必须三态，`'nothing'` 不许降级合并**（2026-11-19 第 7 轮，用户实测）：`blendTopIntoBase` / `compositeTopIntoBase` 返回 `'written' | 'nothing' | 'failed'`。`'nothing'` = 按语义本来就不该写任何像素（特殊剪贴：基底在选区处 alpha 全为 0；普通填充：填充层在选区里全透明）⇒ 这是一次**成功**的填充，调用方只删内容层。旧实现用 boolean 把 `'nothing'` 当失败 ⇒ 降级「`moveActiveLayerAbove` + `mergeIntoBase`」⇒ `mergeLayersNew`/`groupEvent` 只认**紧邻那一层**，于是出现三种乱象：① 在 alpha=0 处也填了一块渐变（落在最上方的剪贴蒙版上）；② 对最上方剪贴蒙版填充弹「合并图层不可用」并在其上又新建一个剪贴蒙版；③ 图案填充一律糊到最上层同位置。判据：只有 `putPixels` 抛错（锁定的背景层 / 权限）才是 `'failed'`；读不到图层像素、`touched === 0` 一律 `'nothing'`。⛔ **`'failed'` 也不再降级合并**（2026-11-19 第 8 轮，用户拍板）：降级的 `mergeLayersNew` / `groupEvent` 只认**紧邻那一层**，内容层在文档最顶层时必然合到别人的图层上 ⇒ 现在一律「撤回内容层（`deleteLayerById` → 失败再 `deleteActiveLayer`）+ `core.showAlert` 说明原因」，文档回到填充前状态。随之删除 `mergeIntoBase` / `moveActiveLayerAbove`（已无调用方，留着只会诱导后人重新走上降级老路）。

154 **「特殊蒙版」只能有一个入口，且在填充层面判定**（2026-11-19 第 9 轮）：它原是图案 / 渐变子面板各一个「特殊剪贴蒙版」复选框（`Pattern/Gradient.preserveTransparency`，只对当次预设生效、旧值还会被写进预设），现收口成 APP 面板「填充选项 · 新建图层」下方的 `AppState.specialMask` 全局开关，**三种填充模式共用**。⛔ 别再往子面板加第二个入口：两个入口必然出现分歧值，而填充只认一个（`fillSelection` 里 `specialMaskOn = !!fillState.specialMask && !isSpecialMaskDisabled()`）。落地方式三选一：渐变/图案走既有的像素合成（`blendTopIntoBase` / `compositeTopIntoBase`，`useSpecialClip = hasPixels && preserve`）；**纯色**没有临时层可写回 ⇒ 直接用 PS 原生 `fill` 的 `preserveTransparency: true`（= 填充对话框「保留透明像素」，一次 IPC、零读像素），且只在 `!createNewLayer && hasPixels && !isBackground && !isNonPixelLayerKind(kind)` 时挂它（背景层无 alpha / 空层无像素可留 / 非像素层不允许）。纯色 + 新建图层（新层是空的，保留透明像素等于什么都不填）⇒ 填完再 `clipNewLayerToBase()`：原生 `groupEvent` 优先，`isClippingMask` 为真则跳过，被拒才 `multiplyTopAlphaByBase`。禁用条件与「新建图层」同构（清除模式 / 快速蒙版 / 图层蒙版 / 单通道）。

155 **「选区修正」折叠分区 = 套索轨迹平滑 + 多边形吸附**（2026-11-19 第 11 轮）：原「套索轨迹平滑」分区改名「选区修正」（4 字 ⇒ `label-4`）。平滑开关从 `.collapse-header` 降到内容区第一行（`label-6` 标题 + 开关分列两端，不再需要 stopPropagation 包装）；**参数（滤波族三档 + `.smooth-params` 盒）以 `isPenSmoothOn()` 为渲染条件**整块进退。参数下方用与「填充选项」**同一份** `<div className="divider" />`（同层 `collapse-content-expanded` 直接子级 ⇒ 天然同款同间距，块容器折叠取 max=10px），其后是多边形吸附行（从「填充选项」的 `.slider-container` 挪入）。⛔ 拨开关会整块增删参数区 ⇒ `toggleLassoSmooth` 两个出口都必须补 `resyncAfterLayout`，否则 UXP 原生数字输入留残影（同 `handleSmoothModeChange` 的理由）。

156 **描边必须「剪贴组安全」**（2026-11-19 第 12 轮）：描边原是「`make layer` → `stroke` → `mergeLayersNew`」，而 PS 会把建在**剪贴组成员**上方的新层**自动塞进同一剪贴组** ⇒ ① 组内最上层 merge 被拒、弹「合并图层不可用」；② 组内中下层虽能合并，但描边被**基底** alpha 裁而不是被**目标层自身** alpha 裁 ⇒ 描边落在目标层 alpha=0 处。⛔ 修法分两条：**特殊蒙版开**（且非背景 / 非锁定透明 / 非像素层）⇒ 全像素链 `make → stroke(100,normal) → multiplyTopAlphaByBase(目标层自身 alpha) → compositeTopIntoBase(用户 opacity/blend) → deleteLayerById → selectLayerById`，全程不 merge/不 groupEvent；**普通描边** ⇒ `mergeStrokeLayerDown` 三级兜底（silent merge → tryCreateNativeClippingMask + 重试 → composite 并集兜底）。⛔ 所有 merge/clip 命令必须 `_options.dialogOptions:'silent'`（`dontDisplay` 失败会弹宿主原生框并绕过 try/catch）。⚠️ `createNewLayer` 时收窄基底必须是**当前活动层**（填充新层），不能再用 `layerInfo.layerId`（那是填充前的旧目标层）。

157 **特殊蒙版 + 新建图层：目标层本身是剪贴蒙版时必须按「它自己的 alpha」收窄**（2026-11-19 第 13 轮）：PS 的两条硬规则叠在一起——(1) 在剪贴层正上方 `make layer`，新层会被**自动塞进同一剪贴组**；(2) 剪贴只能指向「紧邻下方且不是剪贴层」的层，对剪贴层发 `groupEvent` 一律被拒。⇒ 目标层 `isClippingMask === true` 时，新层被**组基底**裁而不是被**目标层自身** alpha 裁 ⇒ 填充/描边会渲染在目标层 alpha=0 处。修法：**不要**看 `readActiveLayerClipState().isClippingMask` 就收工（新层已被自动剪贴，该值恒真），必须用 `targetIsClipping`（= make 之前读的目标层 clip 态，`layerInfo.isClippingMask`）分支，为真时直接 `multiplyTopAlphaByBase(base=目标层, top=新层)` 做像素收窄；为假才走 native clip。落点三处：`app.clipNewLayerToBase(baseId, targetIsClipping)`（纯色 + **图案**共用，图案的新层是 `fillSelection` 建的，`PatternFill` 自己不建层也不剪贴 ⇒ 收尾只能在外层补）、`GradientFill` 的 createNewLayer 分支。描边不必单独改：它收窄的基底是**当前活动层**（= 已被收窄的新层），自然继承同一条边界。⛔ 另：「清除模式」↔「特殊蒙版」**双向互斥**——两个 toggle 各自开启时把对方置 false，且「清除模式」开关的 `disabled` 也要带上 `specialMask`（否则出现「开着特殊蒙版、清除模式仍可点」）；存档恢复时按「清除模式优先」裁掉 specialMask。

158 **特殊蒙版 + 新建图层的「剪贴结构」必须真的建出来**（2026-11-19 第 15 轮，接 157）：像素收窄只保证看得对，用户要的是**图层上真有剪贴箭头**。① 建箭头三级链：`readActiveLayerClipState().isClippingMask`（PS 可能已自动进组）→ `tryCreateNativeClippingMask()`（原生 groupEvent，仅当紧邻下方不是剪贴层）→ `enableActiveLayerClippingMask()`（**直接写 DOM `Layer.isClippingMask = true`**，UXP 官方文档标明 R/W / min 23.0；⛔ 只置真，置假会释放整组，见 150）。② 剪贴基底由 `planSpecialClipBase()` 统一算，**必须在 `make layer` 之前**（建层后 `layerInfo.layerId` 已是新层）：目标层有内容 ⇒ 剪贴它自己（本身是剪贴层才额外收窄）；目标层是**像素空层** ⇒ 边界只能取**紧邻下方那一层**（指向空层的剪贴必然什么都看不见），新层要先 `select` 到下方那层再建、落在两者之间，剪贴指向它；下方也没像素 ⇒ 照建剪贴、结果就是什么都不填（用户口径）。⛔⛔ 「有没有内容」**不能只看 `hasPixels`**：它前提是 `kind === 'pixel'` ⇒ 文字 / 智能对象 / 形状 / 组恒为 false，必须用 `isNonPixelLayerKind(kind)` 兜住，否则在文字层上填充会去剪贴它下方那层。③ UXP `Document.layers[0]` = **最上层** ⇒ 「下方图层」是 `index + 1`（同级内找，跨组返回 null）。落点：`SpecialClipMask.planSpecialClipBase / readLayerBelow / enableActiveLayerClippingMask`、`app.clipNewLayerToBase(plan)`、`GradientFill` 的 createNewLayer 分支。

159 **特殊蒙版 + 新建图层 的四问模型（2026-11-19 第 16 轮，取代 158 的三问）**：`SpecialClipPlan` 现在只有四个字段 —— `resultLayerId`（谁承载内容，`null`=新建）、`boundaryLayerId`（谁当边界：剪贴指向它 + 像素按它 alpha 收窄）、`reuseTarget`（目标层是空层 ⇒ **复用目标层、不新建**）、`shouldFill`（边界层没像素 ⇒ 只建剪贴不填）。⛔⛔ 空目标层必须复用：新建会留一个空白层悬在结果层上方（用户截图「空白层 + 未约束剪贴层 + 下方层」三层，而他只选了一层）。⛔ 「下方也是空层」时**不填**（不是填完再乘 0 擦掉 —— 白做一次整层读写还留个空壳层）。⛔ **剪贴只是渲染期裁剪**：原生 groupEvent 不改变图层里的像素，用户口径是「alpha=0 处不填像素」⇒ 收窄（`multiplyTopAlphaByBase`）**一律要做**，不能再「基底是普通层就跳过」；箭头（结构）与收窄（像素）互不替代。⛔ `tryCreateNativeClippingMask` 必须**回读验证** `isClippingMask`：它用 `dialogOptions:'silent'`，宿主拒绝时**不抛异常**，旧写法 `return true` 会把「什么都没做」当成功 ⇒ 调用方跳过收窄 ⇒ 用户看到的「有箭头 / 没约束」。落点：`planSpecialClipBase`（含 `readLayerBelow` 补 `hasPixels`/`kind`）、`app.clipResultLayerToBoundary`（reuseTarget 时先把活动层选回目标层再收窄+建箭头）、`GradientFill`（复用目标层时上层传 `createNewLayer=false`，走「写回目标层」分支；`insertBelow` 支路已删）。

160 ⛔⛔ **「空目标层复用」不许把像素写回空层**（2026-11-19 第 17 轮，用户截图实证）：渐变 / 图案的收尾是「建内容层 → 栅格化 → 应用蒙版 → `imaging.putPixels` 写回目标层」，目标层若是**空图层**（`hasPixels === false` 的普通像素层），写回被宿主拒绝 ⇒ 弹「渐变填充未完成：目标图层拒绝了像素写入（可能锁定了「透明像素」，或该图层类型不支持写入）」，撤回内容层后图层结构全乱：用户实测「图层 1 消失、原渐变莫名成了背景的剪贴蒙版」。⇒ 空目标层这条改走 `SpecialClipMask.replaceEmptyTargetWithContent`：**按边界层 alpha 收窄内容层 → 删掉那个空层（它本来就没像素）→ 内容层接管空层的名字 → groupEvent 建剪贴**（此刻内容层下方紧邻的就是边界层，一次到位）。落点：`GradientFill` / `PatternFill` 的 `options.replaceEmptyTarget`（由 `app.fillSelection` 从 `plan.reuseTarget` 派生），建内容层前必须先 `selectLayerById(targetLayerId)`（内容层要落在空层正上方，⛔ 不能 `selectFrontLayer`，否则删空层时内容层下方紧邻的是「原来最上层那个图层」，剪贴建错对象）；`contentId === targetLayerId`（宿主就地替换空层）是**合法**情形，照常收窄+剪贴，别当异常退出。⛔⛔ 同时收口一个更致命的隐患：`clipResultLayerToBoundary` 旧写法在 `selectLayerById` 失败时**强行**把 `resultId` 赋成期望值，随后 `groupEvent` 作用在实际活动图层上 ⇒ 出现「原渐变被剪到背景上」这种不可逆破坏。现在必须先 `layerExists(目标层)`、再 `selectLayerById` + `resolveActiveLayerId()` **回读确认**，两者任一不成立就**直接返回**（宁可没有箭头，也不把剪贴建到别人头上）。

161 **当前图案 / 当前渐变必须跨会话持久化**（2026-11-19 第 17 轮，用户要求「重启 PS 后不用重新选」）：**渐变**整份对象存 `panel-state.json` 的 `appPanel.selectedGradient`（只有 stops 数组，体积很小），恢复时先用 `isUsableGradient()` 校验（`type` + 非空 `stops` + 每项 `color` 是字符串）——残缺对象会让 `generateColorStops` 抛错，表现为「首次填充就报错」。**图案**只存 `selectedPatternId` + `selectedPatternTransform`（angle / scale / fillMode / rotateAll）：`Pattern.patternRgbData` / `grayData` 是几 MB 的像素数组，⛔ 绝不塞进存档，本体由 `PresetManager.loadPatternPresets()` 从预设文件恢复。恢复必须**延后 ~1s**（`PERSISTED_SELECTION_RESTORE_MS`）：解码所有预设的 base64 是纯 CPU 活儿，启动期跑会与首帧抢主线程；恢复前再判一次 `this.state.selectedPattern` 是否已被用户重新选过（延后窗口里会被覆盖）。UI 侧两个选择器各加一个「初始选中」入口（`PatternPicker.initialSelection` / `GradientPicker.initialGradient`），**只在首次打开、且本面板还没有选中态时种一次**（ref 守门），否则会出现「面板显示空、填充却用着旧图案」的分歧视图。

162 ⛔⛔ **空目标层首选「向下合并」，不要删层+改名**（2026-11-19 第 18 轮）：`putPixels` 写空层被拒之后的那套「收窄→删空层→结果层接管名字→建剪贴」是**三步都可能被宿主静默拒绝**的绕路，用户实测的结果是「没约束、没箭头、图层只多不少」。新首选：内容层建在空层**正上方** → `select(_id=内容层) + mergeLayersNew` **同一次 batchPlay**（原生向下合并，内容融进空层，id/名字/位置全不变）→ 判据只看「合并后目标层 `bounds` 非空」（先 `await 120ms` 等 DOM 刷新）→ 再收窄、再剪贴。删层方案只作**降级**保留，且 `isLayerEmptyById` 返回 `null`（读不到）时**一律不删**（那时它很可能已被合并进内容，删掉就是不可逆丢失）。⛔ 另两个同源坑：①**不要用 `layerExists` 当流程门槛** —— 刚建层/刚删层后 UXP 的 `document.layers` 滞后一帧，假阴性会让整段交接被跳过（这正是本轮「填充成功但什么都没做」的成因）；②剪贴一律走 `clipLayerToBelowById`（`select`+`groupEvent` 同一次下发），并**只在「紧邻下方就是边界层」时**才建（删层没成功时下方是 alpha=0 的空层，剪上去会让填充整块不可见）。

163 **这类「静默失败链」必须有落地日志**（2026-11-19 第 18 轮）：`src/utils/SmDebug.ts` 的 `smLog()` 把每一步的判据/返回值/回读结果写进 `PluginData/debug/special-mask.log`（串行写链、只留最近 30KB、全程 try/catch 吞错）。用户看不到 UXP 控制台，出问题时直接读该文件就能定位卡在哪一步，不必靠猜或反复截图。
