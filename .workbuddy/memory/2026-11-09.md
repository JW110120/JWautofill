# 2026-11-09

## 0x0225：停笔「描边自动补齐」在标准/追笔模式下时好时坏

**用户报**：选区平滑标准/追笔模式下停住光标，描边自动补齐在插件刚加载一段时间常不生效，跑一会才恢复；最小化 PS 再切回可恢复，但原本生效时最小化反而失效。

**根因（构造性，非参数）**：`smooth_engine.c` HUD 帧里的宽判 `canvasHit` 与严格焦点门 `canvasOk` 一起写在 `if (cheapOk)` 分支、跳帧沿用 `s_cvHitLast`。`cheapOk` 硬含 `ropeMode=(MODE==1)` 与 `fgOk` ⇒ 标准/追笔模式下恒 0 ⇒ `g_canvasHitDbg` 从加载起冻在初值 0。而 `cursamp_thread` 的 MSE 落笔推断武装(2759)、长停摆续命(2801)、喂入冻结(2829)、代投 WT_PACKET(2889) 全读这一位 ⇒ 一停笔喂入被钉死、PS 不被唤醒 ⇒ 描边追不上光标。前台切换恰是它偶尔被重算的一帧，光标在画布内翻 1、在任务栏/桌面翻 0 ⇒ 同一动作结果相反的「翻转」观感。

**真机证据**：`%TEMP%\jwwh-16152.log`（10:56 起）每条 `[hud] 未显示` 都是 `cv=0 rope=0 ck=0`；却反复出现 `[post] 喂入冻结：光标离开活动文档画布` 而光标在画布内；`[hud] 前台切换` 在 10:58–11:01 密集出现（用户反复最小化测试）。另 10:56:24.783 `★解析映射就绪`（93 对配对）说明补流还有一段固有预热，但不是翻转的来源。

**改动**（只碰 2 个 .c，无共享槽变化，`CFG_NLONGS` 仍 61）：
| 文件 | 改动 |
|---|---|
| `native/JWautofillHost/smooth_engine.c` | ① 8421–8446：`canvasHit = canvas_hit_ok(cur)` 移到 `cheapOk` 之外每帧无条件现算；`canvasOk`/`wantVisible` 逻辑逐字不动；顺带加 `curOk`（GetCursorPos 读失败时沿用上一帧宽判，别拿 (0,0) 误判「离开画布」）；② 8478–8495：新增 `[hit] 宽判 x→y` 边沿日志（500ms 节流）；③ 尾部补 0x0225 版本史条目 |
| `native/JWautofillHost/plugin_main.c` | 铁律 3：`jw8li_version` 0x0224 → **0x0225**，并补版本注释 |

**验证**：`build.sh`（沙箱外）零告警 + PiPL 往返一致 + 导出表 5 项（AutoPluginMain / jw8li_version / jwwh_set_engine_off / jwwh_unhook / jwwh_version）。PS 进程已退出 ⇒ 新 `build/JWautofillHost.8li` 直接覆盖 `C:\Program Files\Adobe\Adobe Photoshop 2026\Plug-ins\JWautofillHost.8li`（cmp 一致），未留备份（沿用项目约定）。**真机效果待用户重启 PS 验收**。

**验收判据**：① 加载后第一笔停住光标即补齐，不必等；② 最小化→切回不再改变补齐是否生效；③ 新日志出现 `[hit] 宽判 x→y`，`[post] 喂入冻结` 只在光标真离开画布时出现。
