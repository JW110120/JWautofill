## 修：主开关圆点切换时左移 ~3px
- 根因：`.main-button-content` 是 width:100% + justify-content:center 的居中 flex 行，两态字号不同（开启 `.main-button-text`=16px 粗体 / 关闭 `.label-disabled` 仅改色、继承 14px）→ 组宽变化 ΔT，居中基准移动 ΔT/2，左侧圆点被挤动；文字中心恒在圆点右侧固定偏移处，所以看起来不动。
- 修法：两态共用定宽居中槽 `.main-button-label`（width:64px = 4 字×16px；text-align:center; flex:none; white-space:nowrap）。开启态像素不变，关闭态圆点左移 4px 后即与开启态同位置，切换不再跳动。

## 修：面板高 ≈823px 时滚动条中间态裁掉右侧原生控件
- 现象：APP 主面板在 ~823px 高度出现「有滑块条 / 无滑块条的中间态」，描边模式的 sp-switch 与填充模式齿轮的右半截被裁；工具箱无此问题。
- 根因：PS/UXP 滚动条由宿主原生绘制，**只按需占位**——内容溢出才挤掉 10px，不溢出就还给内容。common.css 里为它写的 `scrollbar-gutter: stable` 与 `::-webkit-scrollbar` **在 UXP 下均不生效**（Adobe 官方论坛：UXP 不支持自定义滚动条），故内容盒在 230↔220 之间翻转。高度 823 时内容高正好压在阈值上：滚动条一出现，CSS 重排到 220px，而 UXP 原生控件（sp-switch / sp-radio 的 slot 内容）来不及重排、仍按 230 画在 x=240（旧内容盒右缘），恰落在滚动条槽位上被后绘制的滚动条压住。工具箱无症状＝其内容永远溢出、滚动条从不消失（内容盒恒 220）。
- 修法：`app.css` 加 `#app .app-root > .panel { overflow-y: scroll; }`，把 APP 主滚动容器钉在「滚动条常驻」状态，内容盒永久 220px，不再翻转。
- ⚠️ 只限 `#app .app-root > .panel`：4 个子面板是独立 `.panel`，其 228px 内宽链（pattern.css）按「无滚动条」标定，不能一起改；工具箱 `.panel` 上有 position:fixed 锁屏遮罩依赖现状，也不动。
- ⚠️ 无效尝试（勿重犯）：别想用 `padding-right` 预留槽位——Chromium 的 scrollport = padding box − scrollbar，加 padding 只会让内容盒再窄 10px（220→210），位移照旧。

## 修正：滚动条问题（推翻上面的 overflow-y: scroll 方案）
- 用户反馈：内容盒恒 220 破坏了原设计（无滚动条时设计要 230）。要求恢复原生 230/220 两档。
- 拿用户截图（250×823）逐像素量：分隔线 x=10..229 → 内容盒 220px；右侧 14 列（236..249）**没有任何滚动条像素**；填充模式齿轮右缘被竖直切在 x≈230、只露 9px（图标 18px）；清除模式 sp-switch 只露 13px（左半）。
- 新根因：`scrollbar-gutter: stable` 在 UXP 的 CSS 侧**确实生效**（预留 10px → 内容盒 220、无滚动条绘制＝用户说的「中间态」），但 **PS 宿主给原生控件排版时不扣这份槽位** → 控件按内容盒 230 摆位、右缘落到 240 探出 10px，被面板右缘裁掉右半截。工具箱（行在 `.border-panel-section` 里，padding 10px）多出的 10px 正好落进 padding，所以看不出。
- 修法：**删掉 `.panel` 的 `scrollbar-gutter: stable`**（common.css），app.css 里删掉 `overflow-y: scroll` 兜底。槽位回到按需占位：无滚动条 230 / 有滚动条 220，CSS 与宿主始终对齐。
- 教训：`::-webkit-scrollbar` 不生效 ≠ `scrollbar-gutter` 不生效，当初把两者一起当死代码是错的。

## ⚠️ 本轮踩坑（务必记）
- **分区可见性包裹时绝不能用 `)}` 替换 collapse-section 的 `</div>`**：我首版把 fillOptions 的 `</div>` 顶成了 `)}`，导致 collapse-section 丢失闭合 → 连锁 8 条 TS 错（TS17008「div has no closing tag」在 1693 最外层 + L2231「Unexpected token }」）。正确是**追加** `)}`、原 `</div>` 保留（先关 collapse-section，再关可见性表达式）。
- **定位 JSX 语法错误别信 webpack 首条**：ts-loader 报的首错在 1693（最外层 div），是级联假象。用项目自带 typescript：`ts.createSourceFile('app.tsx', src, Latest, true, TSX).parseDiagnostics` 拿 `getLineAndCharacterOfPosition`，才能拿到**真正第一个**错误（L2231:18）。写个 `dbg_parse.js` 用托管 Node 跑即可。
- **本机终端现状**：Bash shim 已坏（`dirname:`/`awk:`/`grep:`/`wc:` not found、`cd: null directory`）→ 一律改 PowerShell 或托管 Node 绝对路径。且 PowerShell stdout 在本环境不回显、`>` 重定向写 UTF-8-BOM/UTF-16 会被 Read 判 binary → 让 Node 脚本 `fs.writeFileSync(name,'...','utf8')` 写结果文件再 Read。构建成功判据：`npx webpack --mode=production` 后 `$LASTEXITCODE`==0（写入 txt 再读），日志仅 3 条既有体积警告。
