## 键盘卡死致命问题修复（JWautofill 快捷键服务）

### 根因
- 用户反馈：重启且未开 PS 时也打不出字；卸载守护进程+重启后仍复发（前几分钟能打，随后死）。
- 取证发现本机 `HKCU\Control Panel\Desktop\LowLevelHooksTimeout = 25000`（系统默认 300ms）。
  该值非本项目设置，是系统既有/第三方设置，但它把「任意全局键盘钩子卡一下」放大成「全系统键盘冻结 25 秒甚至永久无响应」——这是键盘卡死头号放大器。

   - `LowLevelKeyboardProc` 首行加 `IsPhotoshopForeground()` 焦点闸门：PS 非前台直接 `CallNextHookEx` 放行（暂停监听），彻底杜绝非 PS 场景吞键。
   - 钩子回调/消息循环路径移除同步网络写与文件写（统一经队列+独立线程），避免钩子线程阻塞 → 全键盘失灵。
   - 启动期自检 `LowLevelHooksTimeout` 过大时写日志告警。
2. **一键修复脚本** `native/HotkeyDaemon/fix-keyboard.ps1/.bat`：
   - 停止服务进程 + 移除开机自启 + 重置 LowLevelHooksTimeout（>5000ms 危险值删除恢复默认）+ 补发修饰键抬起事件 + 重启 ctfmon。
   - 全程无交互（绝不 Read-Host）、不删用户数据；UTF-8 BOM 保存（PS5.1 否则按 GBK 解析乱码）。
   - 已在本机实跑一次，清除了 25000 危险值，键盘当场恢复。
3. **卸载脚本去交互+汉化** `uninstall.ps1/.bat`：去掉 y/n 等待，默认保留 hotkeys.json，全中文输出。
4. **面板右上角菜单** 新增「键盘卡死一键修复」（位于「卸载快捷键服务」上方）：MenuManager / AdjustmentMenu / AdjustmentPanel / BrushHotkeySection / HotkeyBridge 串联，鼠标点一下即唤起 fix-keyboard.bat。

## 图案面板新加载图案一片漆黑（UXP formats.base64 回归）

### 症状
- 图案面板：本次会话新加载的图案缩略图/预览全黑，只有更早会话持久化保存的旧图案能显示。

### 根因
- `src/components/PatternPicker.tsx` 的 `arrayBufferToBase64` 在性能重构（commit c7a78c5）里改成
  `file.read({ format: formats.base64 })`，误以为 UXP 有 base64 直读格式。
- 实际 UXP `storage.formats` 只有 `binary` / `utf8` 两种，`formats.base64 === undefined`；
  `file.read({format:undefined})` 不抛异常，静默按 UTF-8 把图片二进制解码成乱码字符串返回。
- 拼出的 `data:image/...;base64,<乱码>` 非法 → `<img>` 加载失败（onError）→ 缩略图 opacity 0 一片黑；
  且 onLoad 不触发 → `createPatternFromImage` 不被调用 → grayData/patternRgbData 不生成 → 填充也失效。
- 旧图案在回归前用 `binary+btoa` 生成并持久化，preview data URL 干净，故仍正常显示。

### 修复
- 删除 `formats.base64` 直读 try 分支，一律 `file.read({format: formats.binary})` 取 ArrayBuffer → 分块
  `String.fromCharCode.apply` + `btoa` 编码（保留分块性能优化，避免逐字符拼接卡顿）。已 `webpack --mode=production` 编译通过。
- ⚠️ 已在回归期被持久化进 `pattern-presets.json` 的坏 preview 无法自愈（原图 File 引用不持久化）。这些条目需用户手动删除并重新导入，刷新后新导入的预览即正常。

### 症状
1. 无选区时点「边缘平滑」行为不明；
2. 透明图层里只有一小块内容，写回后被**拉伸**，图层外接矩形撑满整个文档；
3. 历史面板留下「全选 / 复制图层 / 中间值 / 删除图层 / 选择图层 / 边缘平滑」一长串条目。

### 根因（第 2 条，最关键）
- `src/adjustments/smartEdgeSmoothProcessor.ts` 的 `getMedianFilteredSelectionRegionRGBA`：
  复制图层 → 跑 PS median → 用**整个处理区域**的 `sourceBounds` + `targetSize: {regionW, regionH}` 读像素。
- UXP `imaging.getPixels` 会把 `sourceBounds` **裁剪到图层 bounds**，再把裁剩下的内容**重采样到 targetSize**。
  图层只有 100×100 而请求 1000×800 时 → 那一小块被拉伸铺满整个区域 → 写回即「撑满文档」。
- 佐证：`knockoutBatchProcessor.ts` 注释明确「透明区域不计入图层 bounds」，所以撑大只可能是真实内容被铺开，不是写透明像素导致。

### 修复
1. **索引/拉伸**：`smartEdgeSmoothProcessor.ts` 新增 `normalizeLayerBounds` / `findLayerByIdRecursive` / `getLayerPixelBounds`；
   median 之后取临时图层**实时 bounds**，只请求「处理区域 ∩ 图层 bounds」且 source 与 targetSize 严格 1:1，
   再按文档坐标把像素摆回 region 缓冲（其余保持全透明）。与 `pixelDataProcessor.processPixelData` 口径一致。
   另加长度守卫：返回数据不是 `gotW*gotH*4` 或 `*3` 直接返回 null（宁可不动，绝不写脏数据）。
2. **无选区自动全图**：`AdjustmentPanel.tsx` 的 `getSelectionBounds(autoSelectAll = true)` 新增探测模式（false 时不改选区）；
   `handleSmartEdgeSmooth` 先探测，无选区则 `selectAllDocument()`，再走后续流程（median 受选区约束，必须先有全图选区）。
3. **历史记录压成一条**：`handleSmartEdgeSmooth` 整段（全选/复制/中间值/删除/写回）包进
   `doc.suspendHistory(..., '边缘平滑')`；`applyProcessedPixels` 新增可选
   `options.skipHistorySuspend`，外层已登记时跳过内部 suspendHistory，避免嵌套出第二条。
4. `helpTexts.ts` 的 `edgeSmoothMode` 补一句「未建立选区时会自动全选整张图后再处理」。
- 验证：tsc 无 src 错误；`webpack --mode=production` 编译通过（仅体积告警）。待实机验证。

## 第九轮：仅主线条选区边缘透明环修复 + edge 参数精简

### ring bug 根因与修复（lineSmoothProcessor.ts）
用户实报「仅主线条平滑，选区边缘一圈像素消失」。四个成因同修：
1. `lineMask` 原按 `a>THR && sel[i]` 截断 → 选区边界成为线条「断口」。改为 `a>THR` 全图统计。
2. `buildSignedDistance(lineMask, sel, ...)` 的 sel 参与「线内/线外」判定 → 边界处 sd 变负 → cov=0。改为签名去 sel，SDF 全图。
3. Phase C strokeAlpha 原 `if (sel[i]!==1) continue;` → 全图计算（写回阶段才用 sel）；Phase E.5 覆盖率统计同步去 sel（按全图分量统计）。
4. Phase D/E 邻居判定新增 `effAlpha[i] = sel[i]===1 ? strokeAlpha[i] : alpha[i]`（「实际最终输出 alpha」：选区外写回不动、看原值）。lineNbr 与 hasEmptyNbr 均改用 effAlpha——否则选区外原线被当空邻居 → 误清。
另修 `binaryOpen` 画布边缘缺陷：原循环限 [r,h-r) 使边缘 r px 条带整体变 0；改全范围+越界邻居跳过（腐蚀不因越界失败、膨胀不因越界命中）。

### edge 模式参数精简
- `EdgeDetectionParams` 只剩 mode / edgeMedianRadius / lineSmoothStrength / lineSmoothRadius；`processLineSmooth` 转发去 `lineStrength` 兜底；`defaultSmartEdgeSmoothParams` 同步 4 字段。旧预设不再兼容。
- AdjustmentPanel 删 `edgeBackgroundSmoothRadius`、`edgeLinePreserveDetail` 两 state 及 init/restore/save/deps/reset/`handleEdgeLinePreserveDetail*`/`processSmartEdgeSmooth` 透传（`backgroundSmoothRadius:` 行）全部引用；restore 中 edgeLineWidthScale/edgeLineHardness 旧预设 fallback 一并删。`PanelStateManager.values?` 本就未声明这些字段，无类型影响。
- PanelStateManager.ts:30 的 preserveDetail 是 toggles（加权平均）字段、highFrequencyEnhancer 的 intensity 是高频增强参数，均与本功能无关，勿误删。
