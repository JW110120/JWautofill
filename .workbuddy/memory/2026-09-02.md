# 2026-09-02

## 滑块标签拖拽统一修复（三项缺陷 + 一处排版）

### 1. 选区填充「扩散」标签能拖光标但值不变
- 根因：`src/utils/DragHandler.ts` 的 `configs` 漏了 `selectionExpand`，
  `calculateNewValue()` 找不到配置就 `return startValue` → 值恒定不变（CSS 光标却照常切）。
- 修复：补 `selectionExpand: { min: 0, max: 100, sensitivity: 0.5 }`（与平滑/锐度一致）。
- **教训：新增可拖拽滑块标签时，必须同步在 DragHandler.configs 注册，否则静默失效（无任何报错）。**

### 2. 描边子面板拖拽灵敏度极低
- 根因：`src/components/StrokeSetting.tsx` 里 `dragStartValue + deltaX * (sensitivity / 100)`
  把灵敏度又除了 100，等于迟钝 100 倍；另外宽度上限写成 10，而 RangeSlider 的 max 是 20。
- 修复：去掉 `/100`；起点信息改存 `useRef`（`dragRef`/`valueRef`/`cbRef`），
  effect 依赖只剩 `[isDragging]`，不再每次值变化都解绑/重绑 document 监听。
- 灵敏度标定统一为「每 5px 鼠标位移 = 1 个步长」→ sensitivity = step / 5：
  宽度(0~20/step0.5)=0.1；不透明度(0~100/step1)=0.2（与 APP 主面板不透明度一致）。
  特例：木刻边缘阈值量程 0~255 用 0.5（否则全程要拖 1275px）。

### 3. 工具箱滑块标签全部补上拖拽（新 hook）
- 新增 `src/utils/useLabelDrag.ts`（通用 hook）：
  `useLabelDrag(configs, applyValue)` → `{ dragTarget, onLabelMouseDown, labelClass }`。
  起点存 ref、configs/apply 每次渲染刷进 ref，闭包永拿最新值；值先按灵敏度放大 → 吸附 step → 夹 [min,max]。
- `AdjustmentPanel.tsx` 增加 `SLIDER_DRAG_CONFIGS`（13 个滑块）+ `sliderLabelClass()` 辅助，
  13 个标签挂 `onMouseDown`；两个下拉行（平滑模式 / 线稿参考）挂 `-static` 不拖拽。
- CSS（`adjustment.css`）新增：
  `.adjustment-slider-label-drag{cursor:ew-resize}` + `.dragging{cursor:grabbing}`；
  `.adjustment-slider-label-static{cursor:default}`；
  并把 `.wide-/.wider-adjustment-slider-label` 里写死的 `cursor:pointer` 删掉（光标交给上面两个修饰类）。

### 4. 边缘处理 2×2 按钮排版
- 四颗按钮（alpha下对齐 / alpha上对齐 / 保底下对齐 / 线条加黑）统一新类
  **`.adjustment-button-quad{width:92px;padding:0;flex:none}`**：
  - 92px 来自 alpha 上/下对齐：中英混排（alpha + 3 汉字）按「13×字数+20」纯汉字算法会算到
    8 字档 124px 明显偏宽，实际视觉宽度落在 5 字档(85) 与 6 字档(98) 之间 → 取中值 92px。
  - **四颗必须同宽**，否则父级 `justify-content:space-between` 会因两行总宽不同造成列错位
    （实测：工具箱面板 300、`.adjustment-section` 内容区 260；原 124+124 vs 85+72 →
    右列起点 x=136 vs x=188，错开 52px）。统一 92px 后两行总宽均为 184，左右列严格对齐。
  - `flex:none` 必须带，否则 `space-between` 下会被压缩回不确定宽度。
- 新增 `.adjustment-double-buttons-mb{margin-bottom:10px}`，**只**加在第一行，第二行不加。
- 宽度参考：工具箱面板 `manifest.json` 里 `com.listen2me.pixeladjustment` 为 300px 宽（主面板 250px）。

## 5. 双行滑块：拖拽热区从「标签」上移到「参数集合行容器」
- 用户反馈：双行滑块（第一行=标签+数字输入+单位，第二行=滑块条）希望**第一行整行可拖**，
  含标签与输入框之间的中间空白处，不局限于标签文字本身。
- 涉及：APP 主面板 2 个（不透明度 / 羽化）、图案面板 2 个（角度 / 缩放）、
  纯色面板 4 个（灰度或色相/饱和度/亮度抖动 + 不透明度抖动，全部走 `renderSlider`）。
- 做法：把 `onMouseDown` 与 `title` 从 `<label>` 移到上层行容器
  （`.slider-parameter-collection` / `.pattern-slider-parameter-collection` /
  `.colorsettings-slider-parameter-collection`，三处 CSS 本来就已带 `cursor:ew-resize`）。
- **必须加的守卫：三个 handler 开头统一排除输入框**：
  `const el = event.target as HTMLElement | null; if (el && (el.tagName === 'INPUT' || el.tagName === 'TEXTAREA')) return;`
  否则容器上的 `preventDefault()` 会连带吞掉数字输入框的聚焦/编辑。
- CSS 配套：给三个行容器内的 `input[type="number"]` 显式 `cursor:text`，
  覆盖从容器继承的 `ew-resize`，避免用户误以为输入框不能点。
- **不改的范围**：单行滑块（APP 选区选项 3 个、工具箱 13 个、描边 2 个）保持只拖标签——
  单行里 label 与 RangeSlider 同行，整行可拖会与滑块条自身的点击跳转/拖动冲突。

## 6. 拖拽期间光标全程锁定 ew-resize（否则变回普通箭头）
- 现象：所有滑块（单行/双行）按下开始拖后，鼠标一旦移出标签/行容器（滑到面板空白、滑块条、
  甚至面板外），光标就由鼠标下方元素接管 → 退化成普通箭头（default）或 pointer，观感像「拖一半丢了」。
- 机制（已存在：`src/utils/dragCursor.ts`）：拖拽开始给 `document.body` 加 `label-drag-cursor` 类，
  CSS `body.label-drag-cursor, body.label-drag-cursor * { cursor: ew-resize !important }` 强制全局锁定；
  mouseup 摘类。`!important` 是必需的——要压过面板里 button/label/input/RangeSlider 的常规则 cursor。
  用**引用计数**（同 bundle 两面板可能叠加拖拽）而非布尔量。
- **本轮补齐的遗漏**：此前只有 `styles.css`(APP) 有 CSS 规则，且只有工具箱 `useLabelDrag` 调了
  `setDragCursorActive`。其余 5 个面板既没调也没规则。**现已统一**：
  - CSS：5 个面板各补 `body.label-drag-cursor` 规则 → styles/adjustment/pattern/colorpanel/gradient/stroke 全覆盖
    （input-fix.css、license.css 不含滑块面板，无需）。
  - TS：APP/图案/纯色/描边/渐变 5 处 handler 在 mousedown 调 `setDragCursorActive(true)`、mouseup 调 `false`
    （工具箱已通过 `useLabelDrag` 自动调，无需改）。
- 渐变子菜单「角度」滑块（单行，GradientPicker `handleAngleMouseDown`）此前漏在清单外，本轮一并修好。

## 7. 拖拽中光标改为 grabbing（覆盖第 6 节）
- 用户要求：所有滑块 **dragging 状态**的光标从 ew-resize 改为 **grabbing**（按下即「抓住」元素横拖的语义；
  态/悬停仍保持 ew-resize 表示可横向拖调）。
- 改动：
  - 6 个面板 CSS 的 `body.label-drag-cursor * { cursor: grabbing !important }` 全局锁（原 ew-resize）。
  - 全部 `.dragging` 规则 → `cursor: grabbing`：
    APP `.slider-parameter-collection.dragging` / `.selection-slider-label.dragging`、
    工具箱 `.adjustment-slider-label-drag.dragging`、纯色 `.colorsettings-slider-parameter-collection.dragging`、
    描边 `.stroke-label-2.dragging` / `.stroke-label-4.dragging`。
    （图案/渐变无独立 `.dragging` 规则，仅靠全局锁兜底 grabbing。）
  - `.not-dragging` 规则维持 ew-resize 不变。
  - `useLabelDrag.ts` 注释同步（「锁成 grabbing」）。
- **顺带修复第 6 节遗留的真 bug**：第 6 节把全局锁规则误写进了**未被引入的死文件**
  `src/styles/adjustment.css`（工具箱真实样式是 `src/adjustments/adjustment.css`，由 `AdjustmentPanel.tsx` 的
  `import './adjustment.css'` 引入；webpack 只打包被 import 的 css，无引用则不会进 bundle）。
  故工具箱此前实际**没有全局锁**，拖拽移出标签光标就丢失。本轮：
  ①在真实文件 `src/adjustments/adjustment.css` 补入 `body.label-drag-cursor` 规则；
  ②删除死文件 `src/styles/adjustment.css`。

## 8. 三个面板体验优化（蒙版同步告警 / 笔刷热键分区 / 分区拖拽虚线）

### 8.1 蒙版同步启动不再弹「警告」观感
- 用户：每次 PS 启动插件就显示「未检测到活动文档」像告警。经查 MaskSyncEngine 无 showAlert，
  该「警告」实为状态条显示 `getDocName()||'无文档'`。
- 修复：无文档时显示静默 `未打开文档` 并加 `.mask-sync-status-info.idle{opacity:0.45}`，
  title 说明「未打开文档时蒙版同步不运行，属正常状态」。

### 8.2 笔刷热键并入分区系统（支持拖拽排序 + 隐藏）
- 根因：`BrushHotkeySection` 此前硬编码在 `.map(renderSection)` 之后、游离于 sections 状态数组，
  故不继承拖拽/折叠/隐藏逻辑。
- 修复：
  - `SectionConfig.id` 联合类型加 `'brushHotkey'`；`defaultSections` 加 `{id:'brushHotkey',title:'笔刷热键',isCollapsed:false,isVisible:true,order:4}`。
  - `renderSectionContent` 加 `if(sectionId==='brushHotkey') return <BrushHotkeySection/>`；删原硬编码实例。
  - `BrushHotkeySection.tsx` 去掉外层 `.adjust-expand-section` 包裹 + 折叠头部（含 `collapsed` state 与 `ExpandIcon` import），改为返回 Fragment，头部/折叠/拖拽归父分区所有。

### 8.3 分区拖拽虚线样式（复用笔刷记录 drop-target 观感）
- `renderSection` 头部 draggable 挂 `handleDragStart/Over/Drop/End`，
  用 `dragSourceId`/`dragOverId` 切换 `.dragging`(opacity:0.45) / `.drop-target`。
- CSS 加 `.adjust-expand-section.dragging{opacity:0.45}` 与
  `.adjust-expand-section.drop-target{outline:2px dashed var(--primary-color);outline-offset:-2px}`（复用 `.hotkey-entry-row.drop-target` 同一主色虚线）。
- `handleDrop` 按 order 重排（sort→splice→落新序）。
