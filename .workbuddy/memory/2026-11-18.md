## 滚轮第 3 版（快滚不再退回 0.1）+ 数字框范围夹紧 + HUD 起笔闩（0x0238）—— 已部署

- **滚轮快滚退回 0.1 的根因**：滚轮改值是 UXP 原生控件内部行为，脚本只能事后看 `input` 的差值。
  慢滚时一次 `input` 差 ±0.1 ⇒ 命中「原生特征」被纠正成 ±step；**快滚时原生攒了几格才派发一次 input**
  ⇒ 差值是 ±0.2/±0.3 ⇒ 旧判据「必须**恰好** 0.1」不成立 ⇒ 完全不纠正，值停在 0.1 网格上，
  且基线 `lastGood` 被更新成那个 0.1 值 ⇒ 之后连慢滚也「正常」了（= 用户说的「又变回 0.1」）。
  ⇒ 判据改成「**0.1 的整数倍**」，倍数 k = 攒下的格数，直接 `lastGood + k×step`（快滚一次到位）。
- **过冲保护**：step=0.5 时「自家写入 + 原生叠 0.3」的差值 0.8 也是 0.1 的倍数（k=8）⇒ 会 +4.0。
  新增回声闸：`inWheelWindow && 自家写过后 200ms 内` ⇒ 一律**拉回权威值**，不按格数推进。
- **手输越界（截图羽化=50，max=20）**：滚轮路径有 clamp、**键入路径没有**。新增 `change`/`blur`
  两个时机做**只夹范围、不动 step** 的夹紧（手输 3.3 这种不在网格上的合法值不被抹平）。
  `change`/`blur` 只从 document capture + 元素 blur 各挂一份（input/change 元素级重复挂会跑两遍纠正）。
- **HUD 拖浮窗松手仍闪（0x0238）**：0x0237 的 200ms「进画布迟滞」治不住——真机 jwwh-12640（10:13:02）
  证明幽灵窗出现得比 200ms 更早（`02.797 挡(OWL.TabGroup)` → `02.838 why=8` → `03.025 恢复` →
  `03.029 显示 penDown=1` → `03.167 隐藏`，可见 140ms）。**任何按时间等的门都治不住**（幽灵窗可持续数秒）。
  ⇒ 换判据：`g_penDown` 0→1 的**边沿**问一次 `canvas_focus_ok`（真实命中测试），不在画布就把整笔闩死
  （`s_offCanvasStroke038`，why=9），直到下一笔重新取样。0x0237 迟滞保留（兜住悬停尾巴）。
  ⛔ 不能用 `canvas_hit_ok()` 取样：宽判只认主框矩形，浮窗浮在画布上方 ⇒ 恒 1。
  ⛔ 悬停期 `g_penDown` 恒 1 时没有边沿 ⇒ 不误伤「悬停面板→移到画布落笔」。
  ⛔ 取样放在 `frame_resolve(now)` 之后（它才刷新主框/主机句柄）。新增日志 `[hud] 起笔在画布外:`（2s 节流）。
- 版本 `jw8li_version = 0x0238`，plugin_main.c 版本史已追加。`CFG_NLONGS` 仍 61。
- 验证：`build.sh` 零告警 + PiPL 往返一致 + 导出表 5 项（AutoPluginMain/jw8li_version/jwwh_set_engine_off/jwwh_unhook/jwwh_version）；
  `npx tsc -p tsconfig.check.json` 新模块零报错。.8li md5 `bb6bdb…`（**需重启 PS**），bundle md5 `e21914…`（**需关掉面板再打开**）。

## 自绘数字框 NumField（替换 31 个原生 number 框）+ HUD 起笔闩复核/自救（0x0239）—— 已部署

- **为什么弃用 `input[type=number]`**（用户第 4 次反馈滚轮后定案）：UXP 27.8 前它是原生控件 ——
  滚轮写死 0.1、`preventDefault` 拦不住、方向不可靠（用户实测「缩小反而变大」）、
  `z-index` 无效（原生绘制层压 DOM 之上）、34px 定宽把 `14.5` 裁掉。
- **`src/components/NumField.tsx`**：`type="text"` + 自算滚轮/键盘/夹紧/格式化。
  **对外契约特意保持事件形状** `onChange({target:{value}})`，31 个既有处理器（`Number(e.target.value)`
  / `parseInt(...)`）零改动；`onChange` 形参必须是 `any`（strictFunctionTypes 逆变会拒绝更窄形状）。
  · 滚轮**只能用元素级原生监听 `{passive:false}`**（React 17+ 的 wheel 是 passive，preventDefault 无效）；
    方向取 deltaY→wheelDelta→detail 三级兜底；以 `latest.current` 为基准（props 回流滞后也不丢格）。
  · 提交时机：**回车/失焦**（打字不提交，避免每字符触发 PS 调用）；Esc 回退；聚焦全选。
  · 提交**只夹紧不吸附**（手输 3.3 保持 3.3）；只有滚轮/↑↓落 step 网格（以 min 为基准）。
  · 聚焦时给父级 `.num-input-row` 挂 `is-focus`（UXP 不支持 `:focus-within`）。
- **CSS**：`.num-input-row` 34→**40px**（内宽 32px，`14.5` 不再被 overflow 裁）；
  新增 `.num-input-row input.num-field{width:100%}`（压过 `input[type=text]{width:60px}`，那是渐变 #RRGGBB 的）；
  `.num-input-row.is-focus{border-color:var(--primary-color)}`。
  `input-fix.css` 里 4 条 `input[type="number"]` 选择器全部补 `.num-field`（层级/遮挡/次级面板可见性）。
- **HUD 丢笔根因（我上一版 0x0238 的锅）**：真机 jwwh-22792（10:27）`起笔在画布外: cur=(774,508) why=4`
  —— 光标确实在画布上，`canvas_focus_ok` 那一帧因文档区矩形抖动判 why=4；**一次取样定生死**，
  且闩只能靠「下一次干净 penDown 边沿」解除 ⇒ 用户连丢两笔。
- **0x0239**：① 落笔取样改 **60ms 复核**（`LATCH_VERIFY_MS`，任一次通过即放行）；
  ② **抬笔自救** `LATCH_REARM_MS`=250ms（闩着时笔抬起 + 焦点门连续确认画布 ⇒ 立即解除）；
  ③ **删除 0x0237 的 200ms 进画布迟滞**（只增延迟，治不住幽灵窗）——`canvasOk` 直接取焦点门结论。
  墓碑注释已留在原 #define 处，why=8 文案改成「已停用，仅占位保持索引」。
- 版本 `jw8li_version = 0x0239`（注：NumField 的 `commit` 之后还有 `resync()`，用 40ms 回读 props 对齐 —— 调用点的 `parseInt(e.target.value)` 会把 14.5 收成 14，不回读输入框会一直显示 14.5）。验证：`build.sh` 零告警 + PiPL 往返一致；`tsc` 全仓仍 146 条历史错误（新文件零报错）；

## 数字框两态化（显示=div / 编辑=input）+ 34px 定宽 + 22px 盒高；命中错位守卫 —— 已部署

- **UXP 铁证：原生 input 的 `text-align:center` 完全不生效**（用户截图逐像素量：40px 容器里
  `15` 左间隙 8px、右间隙 19px ⇒ 永远左对齐）。所以「个位数右侧空白太多」不是宽度问题，
  加宽/收窄都治不了。⇒ `NumField` 改**两态渲染**：显示态 `<div class="num-field-view">`
  （flex `justify-content:center`，几何居中与字体/位数/原生排版解耦），点一下才挂
  `<input type="text">`（全选、回车/失焦提交、Esc 回退、↑↓ 走格、元素级 wheel 仍走 `{passive:false}`）。
  ⛔ 两种形态共用一个 `nodeRef`；wheel 监听的 effect 依赖 `editing`（节点会换）；
  进入编辑态后**必须主动 focus()+select()**（新挂载的节点不会自己拿焦点）。
- **容器尺寸定案（common.css）**：宽 40→**34px**（数字箭头已不存在，34px 内宽 32px 就够：
  实测 SourceHanSansCN 数字 6.59px/字、句点 3.24、负号 4.12 ⇒ `14.5`=23.0、`-20.5`=27.1 < 28px 可用文字宽）；
  高 32→**22px + `margin:5px 0`**（视觉盒 22、占位盒仍 32 ⇒ 行高/纵向节奏/与滑块中心对齐全不变）。
  22px 的来历：内宽 32 − `100` 墨迹 19.2 = 12.8（左右各 6.4）；cap height 0.733em×12px=8.8
  ⇒ 8.8+2×6.4≈21.6，取 22（上下各 6.6，与左右 6.4 基本相等）。input/view 高度都保持 20px
  （UXP 文字锚在绘制区上缘，**盒高每减 2px 文字下移 1px** 的旧规律继续成立）。
- **命中错位（切换平滑模式后点哪儿都差 ≈45px，能自愈）**：

## 第 6 轮：数字框编辑态改「全自绘」+ Shift 滚轮加速 + 滑块边对齐行程

**问题 1（编辑态两个硬伤）**：点进数字框后 ① 数字从居中跳到**左上角**；② 输入框底色
**溢出盖住** `.num-input-row` 的蓝色激活边框。
- 根因：`type="text"` 在 UXP 里走原生 NSTextField 风格绘制 —— 文字锚在绘制区左上
  （不吃 `line-height` / `text-align:center`），绘制区连底色都比 CSS 盒大，且原生层压在
  DOM 之上 ⇒ `overflow:hidden` 裁不到。第 2 版把编辑态留给原生 input，必然复发。
- 排除的绕法：`padding-top`（原生绘制区不随内容盒走）、`background:transparent`（UXP 渲染成纯黑）、
  1px 隐形 input 当键盘桩（同样画黑点）。
- **定案**：`NumField` 第 3 版 —— **显示态/编辑态共用一个 `<div class="num-field-view">`，
  彻底没有 `<input>`**。编辑态内部三段渲染 `光标前文本 / 光标 / 光标后文本`，
  居中由外层 flex 保证、光标位置 = 字符串下标（19.5 多位值不错位）。
- 键盘：`document` **捕获阶段** 的 `keydown`（项目里快捷键录制同款，UXP 可用），
  自实现 字符插入/退格/Delete/←→/Home/End/Ctrl+A/↑↓/Enter 提交/Esc 取消/Tab 提交。
  ⛔ 必须 `preventDefault`+`stopImmediatePropagation`，否则数字会被 PS 或面板热键吃掉。
- 失焦提交：`document` mousedown **捕获**（滑块的 mousedown 里有 `stopPropagation`，冒泡会被掐断）
  + `window.blur` 兜底（点画布不派发 DOM mousedown）。
- 进入编辑时先 `blur()` 掉别的 activeElement：渐变面板的 `#RRGGBB` 还是原生 input，
  不踢焦点的话敲键会钻进那个框。
- ⛔ 草稿三件套（draft/caret/selAll）必须**同时写 ref**（`setDraftBoth` 等）：
  commit 在 document 事件里读值，React state 可能还没落盘 ⇒ 不写 ref 会丢最后一位。
- 样式：`.num-field-edit`（flex 行、`flex:0 0 auto` 防单边裁切）、`.num-field-text`（字号字体行高
  与显示态逐项一致）、`.num-field-text.is-selected`（蓝底白字，与 `.select-opt-sel` 同款）、
  `.num-field-caret`（1px×12px，不做闪烁 —— UXP `@keyframes` 不稳）。
  删掉已作废的 `.num-input-row input.num-field` 规则（不再有 input）。

**问题 2（Shift+滚轮加速）**：分档数 `levels = floor((max−min)/step)+1`（0–100/步 1 = **101** 档）。
`levels ≥ 100` ⇒ 10×步长；`≥ 20 且 <100` ⇒ 5×步长（羽化 0–20/步 0.5 = 41 档）；否则 1×。
↑↓ 带 Shift 同倍率。倍率只在 NumField 内生效（滑块本身无滚轮逻辑）。

**问题 3（滑块几何）**：
- 手柄改**边对齐行程**：`left: percent%` + `margin-left: -(percent×12/100)px`（JS 算纯 px，
  不用 `calc()`，也避开 `-0px`）。min 时左边缘贴轨道左端、max 时右边缘贴右端。
- 命中换算同步改成逆运算：`ratio=(x−轨道左−6)/(轨道宽−12)`（旧版按整条轨道线性映射，两端各差半颗手柄）。
- `--rs-track-inset: 6px → 3px`（`.range-slider` 与 `.slider-track` 两处）⇒ 轨道左右各长 3px。
  左边距 = 标签溢出后的余量≈5 + 3 = 8；右边距 = 3 + `margin-right:6` = 9（≈相等，差 1px）。
- `.range-slider-thumb` 的 `margin-left:-6px` 删除；`THUMB=12` 常量与 CSS 12px 必须同步。
