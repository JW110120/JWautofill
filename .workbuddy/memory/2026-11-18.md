## 滚轮第 3 版（快滚不再退回 0.1）+ 数字框范围夹紧 + HUD 起笔闩（0x0238）—— 已部署

- **滚轮快滚退回 0.1 的根因**：滚轮改值是 UXP 原生控件内部行为，脚本只能事后看 `input` 的差值。
  慢滚时一次 `input` 差 ±0.1 ⇒ 命中「原生特征」被纠正成 ±step；**快滚时原生攒了几格才派发一次 input**
  ⇒ 差值是 ±0.2/±0.3 ⇒ 旧判据「必须**恰好** 0.1」不成立 ⇒ 完全不纠正，值停在 0.1 网格上，
  且基线 `lastGood` 被更新成那个 0.1 值 ⇒ 之后连慢滚也「正常」了（= 用户说的「又变回 0.1」）。
  ⇒ 判据改成「**0.1 的整数倍**」，倍数 k = 攒下的格数，直接 `lastGood + k×step`（快滚一次到位）。
- **过冲保护**：step=0.5 时「自家写入 + 原生叠 0.3」的差值 0.8 也是 0.1 的倍数（k=8）⇒ 会 +4.0。
  新增回声闸：`inWheelWindow && 自家写过后 200ms 内` ⇒ 一律**拉回权威值**，不按格数推进。
- **手输越界（截图羽化=50，max=20）**：滚轮路径有 clamp、**键入路径没有**。新增 `change`/`blur`
  两个时机做**只夹范围、不动 step** 的夹紧（手输 3.3 这种不在网格上的合法值不被抹平）。
  `change`/`blur` 只从 document capture + 元素 blur 各挂一份（input/change 元素级重复挂会跑两遍纠正）。
- **HUD 拖浮窗松手仍闪（0x0238）**：0x0237 的 200ms「进画布迟滞」治不住——真机 jwwh-12640（10:13:02）

  `03.029 显示 penDown=1` → `03.167 隐藏`，可见 140ms）。**任何按时间等的门都治不住**（幽灵窗可持续数秒）。
  ⇒ 换判据：`g_penDown` 0→1 的**边沿**问一次 `canvas_focus_ok`（真实命中测试），不在画布就把整笔闩死

  ⛔ 不能用 `canvas_hit_ok()` 取样：宽判只认主框矩形，浮窗浮在画布上方 ⇒ 恒 1。
  ⛔ 悬停期 `g_penDown` 恒 1 时没有边沿 ⇒ 不误伤「悬停面板→移到画布落笔」。
  ⛔ 取样放在 `frame_resolve(now)` 之后（它才刷新主框/主机句柄）。新增日志 `[hud] 起笔在画布外:`（2s 节流）。

## 第 6 轮：数字框编辑态改「全自绘」+ Shift 滚轮加速 + 滑块边对齐行程

**问题 1（编辑态两个硬伤）**：点进数字框后 ① 数字从居中跳到**左上角**；② 输入框底色
**溢出盖住** `.num-input-row` 的蓝色激活边框。
- 根因：`type="text"` 在 UXP 里走原生 NSTextField 风格绘制 —— 文字锚在绘制区左上
  （不吃 `line-height` / `text-align:center`），绘制区连底色都比 CSS 盒大，且原生层压在
  DOM 之上 ⇒ `overflow:hidden` 裁不到。第 2 版把编辑态留给原生 input，必然复发。
- 排除的绕法：`padding-top`（原生绘制区不随内容盒走）、`background:transparent`（UXP 渲染成纯黑）、
  1px 隐形 input 当键盘桩（同样画黑点）。
- **定案**：`NumField` 第 3 版 —— **显示态/编辑态共用一个 `<div class="num-field-view">`，
  彻底没有 `<input>`**。编辑态内部三段渲染 `光标前文本 / 光标 / 光标后文本`，
  居中由外层 flex 保证、光标位置 = 字符串下标（19.5 多位值不错位）。
- 键盘：`document` **捕获阶段** 的 `keydown`（项目里快捷键录制同款，UXP 可用），
  自实现 字符插入/退格/Delete/←→/Home/End/Ctrl+A/↑↓/Enter 提交/Esc 取消/Tab 提交。
  ⛔ 必须 `preventDefault`+`stopImmediatePropagation`，否则数字会被 PS 或面板热键吃掉。
- 失焦提交：`document` mousedown **捕获**（滑块的 mousedown 里有 `stopPropagation`，冒泡会被掐断）
  + `window.blur` 兜底（点画布不派发 DOM mousedown）。
- 进入编辑时先 `blur()` 掉别的 activeElement：渐变面板的 `#RRGGBB` 还是原生 input，
  不踢焦点的话敲键会钻进那个框。
- ⛔ 草稿三件套（draft/caret/selAll）必须**同时写 ref**（`setDraftBoth` 等）：
  commit 在 document 事件里读值，React state 可能还没落盘 ⇒ 不写 ref 会丢最后一位。
- 样式：`.num-field-edit`（flex 行、`flex:0 0 auto` 防单边裁切）、`.num-field-text`（字号字体行高
  与显示态逐项一致）、`.num-field-text.is-selected`（蓝底白字，与 `.select-opt-sel` 同款）、
  `.num-field-caret`（1px×12px，不做闪烁 —— UXP `@keyframes` 不稳）。
  删掉已作废的 `.num-input-row input.num-field` 规则（不再有 input）。

**问题 2（Shift+滚轮加速）**：分档数 `levels = floor((max−min)/step)+1`（0–100/步 1 = **101** 档）。
`levels ≥ 100` ⇒ 10×步长；`≥ 20 且 <100` ⇒ 5×步长（羽化 0–20/步 0.5 = 41 档）；否则 1×。
↑↓ 带 Shift 同倍率。倍率只在 NumField 内生效（滑块本身无滚轮逻辑）。

## 第 7 轮：自绘数字框把滚轮弄丢了 → 改「document 捕获 + 模块级分发器」

**现象**（用户第 7 次反馈）：第 3 版删掉 `<input>` 后，编辑态滚轮/Shift+滚轮**完全不改数值**，
只有面板滚动条在滚。

**根因**：UXP 里 `wheel` 的目标是「最近的滚动容器」，**非滚动元素收不到 wheel** ——
挂在元素自身的 `{passive:false}` 监听一次都不触发（自然也无从 preventDefault）。
对照证据：`AdjustmentPanel` 的滚轮拦截之所以"有效"，是因为它挂在**滚动容器本身**上；
v1/v2 之所以"能滚"，其实是**原生 number/text input 自己的原生滚轮**在干活（0.1 步长那堆怪象也来自它）。

**定案（NumField 第 4 版）**：模块级单例分发器
- `bindWheelDispatcher()` 在 `document` + `window` 各挂一次 `wheel`（capture + passive:false），
  靠 `e.__jwNfWheel` 去重 ⇒ 一次滚轮只走一格（30+ 个框各挂一个会跳多格）。
- 三级归属判定：① 坐标命中 `.num-input-row` 的 rect → ② `target` 包含 → ③ **仅当没有坐标时**
  用"全场唯一编辑中的框"保底（有坐标时禁用 ③，否则"编辑中随手滚面板"会被暗改成改数值）。
- `handleWheel` 改返回 boolean：命中才 `preventDefault/stopPropagation`，
  禁用态/无方向照旧让面板滚。
- 元素级监听降级为**保险**（带 `__jwNfWheel` 去重），不再承担主入口。
- Shift 倍率：优先 `e.shiftKey`，缺失时退到物理键状态（document keydown/keyup 维护 + window blur 清）。
- 留一次性诊断日志 `[NumField] wheel 首次到达 ...`（只打 1 条）与命中日志（3 条）：
  区分「wheel 压根没进 DOM」（= 必须上 .8li 原生鼠标钩子）与「进了但命中判定不对」。

**验证**：`tsc -p tsconfig.check.json` 146 条历史错误不变、NumField 0 条；CSS guard 通过；
watch 已重编 `dist/bundle.js`（含 `WHEEL_FIELDS`/`wheel 首次到达`，md5 9de5d3d8…→ 12:24 版）。
`.8li` 零改动（仍 0x0239）。待用户实测 + 回传 console 日志。

## 第 8 轮：滚轮改「祖先链分发」+ 新增 0x023A 工具图标呼吸外框

### A. 滚轮（NumField 第 5 版）
上一版「document/window 捕获」实测**仍然不动数值、只滚面板** ⇒ 说明 UXP 的 wheel
**不沿冒泡/捕获传播**，只在目标元素自身派发（目标是"最近的滚动容器"）。
- 定案：把模块级分发器挂到**整条祖先链**（从字段自身 → 16 层父级 → document），
  同一元素只挂一次（`BOUND_ELS` 去重），同一事件靠 `e.__jwNfWheel` 去重 ⇒ 一次滚轮只跳一格。
- 归属判定：① 坐标命中 `.num-input-row` rect → ② target 包含 → ③ **悬停中的字段**
  （`mouseenter/mouseleave` 维护 `HOVER_FIELD`）→ ④ 全场唯一编辑中的字段；③④ 仅在
  "事件没带坐标"时启用。
- 诊断保留：`[NumField] wheel 首次到达 …`（1 条）+ 命中方式（3 条）。

### B. 0x023A 工具图标呼吸外框（原生）
需求：H 自动填充 与 L/M 单纯选区在画布上无视觉差别 ⇒ 自动填充激活时在**选项栏最左的
当前工具图标**外侧画 --primary-color 呼吸外框。
- 全部实现在 `smooth_engine.c` 新增 `ring_*` 段（约 320 行）：
  独立线程 + 分层窗口（`WS_EX_LAYERED|TOPMOST|TRANSPARENT|NOACTIVATE`），

## 第 9 轮：滚轮改「原生 WH_MOUSE_LL 代理」（0x023B）+ 工具外框重定标 / 顺时针流光

### A. 滚轮（第 6 次反馈「依然只滚面板」⇒ 换层级）
**结论（不再猜）**：这个 UXP 版本的 `wheel` **完全不进脚本层** —— 元素级 `{passive:false}`、
document/window 捕获、整条祖先链（16 层）三种挂法实测全不触发。面板能滚是 Chromium
原生滚动行为，脚本拿不到事件，`preventDefault` 自然也无从谈起。
⇒ 唯一可行路径：**.8li 的 `WH_MOUSE_LL` 在消息进入 PS 之前截住**。

实现（面板 + 原生各一半）：
- 面板 → 原生 `{"type":"nfHover","on":0|1}`：
  · `NumField` 导出 `numFieldHoverActive()`（用**指针坐标**判 `.num-input-row` 的 rect，
    不用 mouseenter 维护的 HOVER_FIELD —— UXP 不保证派发 enter/leave）；
  · 指针坐标由 `NumField` 模块级 `trackPointer()` 在 document 捕获 mousemove/pointermove 记录
    （指针静止时保留最后位置 = 「悬停不动直接滚」这个主诉场景）；
  · `SmoothBridge` 每 400ms 心跳 + 指针移动时（80ms 限流）立刻补一帧。
- 原生 `keyhook.c`：
  · `kh_note_nf_hover(on)` 写时间戳 `g_nfHoverMs`（心跳语义，`KH_NF_HOLD_MS` 900ms 过期）；
  · 鼠标钩子 `WM_MOUSEWHEEL` **最前面**（先于录制/滚轮热键）判四条与：nfHover 新鲜 ∧
    delta≠0 ∧ `!g_khTextGuard` ∧ 前台是本进程 ⇒ `kh_nf_push(dir, shift)` 并 `return 1` **吞掉**；
  · 调度线程 ②b 消费队列 → `jw_panel_broadcast()`（plugin_main.c 新增的薄包装，
    避免把 `g_cliS`/`g_sendLk` 暴露出去）发 `{"type":"nfWheel","dir":±1,"shift":0|1}`。
- 面板回程：`SmoothBridge.onmessage` 的 `nfWheel` 分支 → `numFieldNativeWheel(dir, shift)`
  → 坐标命中（或唯一编辑中）的字段 `onNative()` 走 step（含 Shift 倍率）。
- 方向口径：`dir=+1` = 增大（滚轮向上），与 DOM 版 `dy>0 ⇒ 减小` 互为镜像，两边都不再翻。

⛔ 900ms 过期是硬要求：面板崩溃/断连/指针离开时滚轮缩放必须自动恢复（用户第一大忌）。
