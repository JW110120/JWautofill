## 同三处问题的真正根因修复（上一节方案仍不生效，本次定位到根因）
- **①下拉层级（根因：弹层被困在面板的层叠上下文里）**：`.pattern-picker{z-index:9999;position:sticky}`、`.gradient-picker{z-index:10;position:sticky}` 都创建层叠上下文，弹层的 `z-index:10002` 只在上下文内部生效，永远盖不住上下文之外的元素（主面板滑块 thumb 10000 等）。→ 弹层改用 `createPortal(..., document.body)`（`Select.tsx` 与 `AdjustmentPanel.tsx` 的 `MaskSyncSelect` 同步改），`.mask-sync-select-pop` z-index 提到 `99998`（低于模态遮罩 99999），并补 `display:block` + `min-width:96px` + `font-family`（脱离面板后不再继承面板字体）。
- **①附带的真 bug：选项横排成两列**：`.gradient-setting-item div{display:flex;align-items:center}` 命中弹层（弹层当时是面板内 div 且自身未声明 display），弹层变 flex 行容器 → 「线性/径向」两个选项并排成两列。portal 到 body 后不再被命中；CSS 里仍显式 `display:block` 兜底。
- **②图案 checkbox 行**：`.field-cell-label{flex:0 0 auto}` 后每组内容都贴各自单元格左缘，右组被卡在整行中间。→ 新增 `.pattern-checkbox-container.field-row-two > .field-cell:first-child{justify-content:flex-start}` 与 `> .field-cell:last-child:not(:only-child){justify-content:flex-end}`（左组内容靠行左端、右组靠行右端；单次模式只有一组时用 `:not(:only-child)` 保左对齐）。
- **③渐变「样式」行**：`flex:0 1 190px`（有上限）+ 标签 `flex:1 1 auto` 的组合在 UXP 下把下拉压窄。→ 改为统一的 `.gradient-setting-item > label{flex:0 0 auto;white-space:nowrap;margin-right:8px}`（「样式：」与「角度：」同为两字+全角冒号，宽度天然一致，两行控件左端对齐），下拉改 `flex:1 1 auto;min-width:0` 自适应占满剩余整行。

## portal 到 document.body 导致「所有下拉打不开」+ 渐变下拉异常窄（上一节 portal 方案的纠正）
- **①portal 目标错了（致命）**：`createPortal(..., document.body)` 后**所有下拉菜单完全打不开**。原因：本插件 index.html 里 body 下同时有两个 `<uxp-panel>`（`#app` 主面板 / `#pixeladjustment` 调整面板），**UXP 只渲染当前激活的那个 panel 子树**，挂到 body 的弹层落在所有 uxp-panel 之外，根本不会被绘制。
  → 新增 `src/utils/popRoot.ts` 的 `getPopRoot(from)`：从下拉头部 `parentElement` 链往上找 `#app` / `#pixeladjustment`，兜底 `uxp-panel` 元素，最后才 body。`Select.tsx` 与 `AdjustmentPanel.tsx` 的 `MaskSyncSelect` 都改用 `getPopRoot(headRef.current)` 作为 portal 容器。这样既脱离面板内层叠上下文（仍能盖在最上层、z-index 99998），又仍在被渲染的子树内。
- **②渐变下拉异常窄的真凶（与 portal 无关）**：`.gradient-setting-item > div{display:flex;align-items:center}` 把 `.mask-sync-select-wrap` 变成了 flex 容器，于是内部的 `.mask-sync-select-head`（默认 `flex:0 1 auto`）退化成**内容宽度**（约 40~50px），弹层宽度 = head 宽度 → 展开后也极窄、文字换行看着像两列。0ffd3e1 用的是 sp-picker（自身会撑满）所以当时正常。
  → adjustment.css 新增通用兜底 `.mask-sync-select-wrap > .mask-sync-select-head{flex:1 1 auto;width:100%;min-width:0}`，无论 wrap 是不是 flex 容器，head 都撑满 wrap（对 `.pattern-setting-item div{display:flex}`、`.stroke-wide-container div`、`.selection-slider-item div` 这类通用规则同样生效）。
  → 同时 `.gradient-type-setting .mask-sync-select-wrap` 的 flex-basis 由 `auto` 改 `0%`（`flex:1 1 0%`），避免 UXP 下残留内容宽度。
- `yarn build` 通过（仅体积警告）。

## 下拉弹层 × 文本控件穿透（UXP 官方已知限制）+ 渐变下拉箭头/字号统一
- **①number-input 穿透弹层：内联样式/z-index 救不了（硬限制）**。Adobe 官方 Known Issues 原文："While z-index is supported, no element can overlay a widget that has text editing capabilities. Text fields and areas will always render the text editor above everything else in the same panel or dialog." → input[type=number]/textarea/sp-textfield 无视 z-index、无视 portal、无视 transform 提层，永远画在同一面板最上层。官方给的只有两条路：用 popover 承载 / 隐藏被盖住的控件。
  - 已做：弹层内联样式仍尽量提层（`POP_LAYER_STYLE = {zIndex:99998, transform:'translateZ(0)', willChange:'transform'}`，对滑块 thumb、sticky 面板等普通 DOM 有效）。
  - 已做（官方方案②的精确版）：新增 `src/utils/popOverlay.ts` 的 `hideOccludedTextFields(popEl, root)`，在 `useLayoutEffect`（依赖 [open, pos]）里按弹层**实际矩形**只把「与弹层相交」的可编辑控件临时 `visibility:hidden`（保留占位不重排，跳过 `document.activeElement`），关闭时逐个还原。相比早期「打开下拉就隐藏面板内所有 number 输入」，被隐藏的正是本来就被完全遮住、用户看不见的那几个，不会出现一堆数字凭空消失。`Select.tsx` 与 `AdjustmentPanel.tsx` 的 `MaskSyncSelect` 均已接入。
- **②渐变下拉箭头紧贴文字 + 字号与其它下拉不一致**：`.gradient-setting-item span{font-size:13px;margin-left:-4px}`（特异性 0,1,1）覆盖了 `.mask-sync-select-caret{margin-left:auto}`（0,1,0）→ 箭头不再右对齐；字号也被改成 13px。→ 该规则收紧为 `.gradient-setting-item > div > span`（只命中数字输入框后的 ° 符号）；并给头部内部元素加「两级类」兜底 `.mask-sync-select-wrap .mask-sync-select-value / .mask-sync-select-caret`（特异性 0,2,0），防止今后再被面板级 `X span` 规则覆盖。另加 `.gradient-setting-item > .mask-sync-select-wrap{display:block}`。
