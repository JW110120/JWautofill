## 选区填充开关跨面板通讯修复（2026-08-30，已 yarn build 通过）

- **现象**：用户在「绘画工具箱」面板把选区填充开关绑了 Ctrl+Q，按下后该面板有文字提示，但「选区填充」主面板（#app）开关纹丝不动。
- **根因（两个叠加）**：
  1. `connectHotkeyDaemon()` 在 App（app.tsx:105）与 BrushHotkeySection（line 53）两处各调用一次；
     manifest 的多个 entrypoint 共用同一个 `main: index.html` → **同一 bundle / 同一 JS 世界**，于是建出**两条 WebSocket**。
     守护进程向所有客户端广播，同一条 toggleMain 被投递两份；两份 `handleHotkey` 各自跑一次「读-改-写」翻转，
     await 让出线程后读到同一个旧值、各翻转一次，结果互相抵消 → 表现正是「按了没反应/开关不动」。
  2. 旧方案靠 `registerMainToggleHandler`（面板内回调）直接切开关，跨面板不共享；且回调注册在 componentDidMount 一连串 await 之后，易被前置 await 卡死。
- **修复**：
  - 新增 `src/utils/MainToggleBus.ts`：用插件数据目录下的 `settings/main-toggle.json` 作为跨面板共享状态（rev 单调递增 + token 幂等防重复翻转）。
  - 热键只负责翻转「共享状态」（`requestMainToggle` 加串行锁 `toggleChain` 杜绝竞态），由 App 面板 `subscribeMainToggle` 订阅并应用到本地 state；同时保留 250ms 文件轮询兜底 + 同上下文即时 mem 通知。
  - `connectHotkeyDaemon` 改为**幂等 + 引用计数**：同上下文只保留一条连接，退订按引用计数关闭，彻底消除双连接导致的双投递。
  - `registerMainToggleHandler` 标记废弃（空操作，仅留兼容告警）。
  - 提示文字改为反映真实结果（`已开启/已关闭`），不再无条件显示「已切换」。
- **验证点**：PS 重载插件后，按 Ctrl+Q 两个面板开关应同步翻转；面板持久化（PanelStateManager）与总线文件在挂载时由 `seedMainToggle` 对齐。
