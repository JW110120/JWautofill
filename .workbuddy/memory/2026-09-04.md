# 2026-09-04 工作日志

## 00:1x 笔刷热键守护进程：键盘失灵 BUG 修复 + 焦点暂停监听
- 现象：笔刷热键功能运行一段时间后「键盘完全打不出字」，只有卸载（杀进程）才恢复。另要求：焦点不在 Photoshop 时键盘钩子暂停监听。

### BUG 根因（键盘失灵）
- 常驻 WH_KEYBOARD_LL 低层键盘钩子装在独立录制线程，该线程的消息循环即钩子泵。两处**阻塞 I/O 发生在钩子线程上**：
  ① `LowLevelKeyboardProc`→`FinishRecordingInternal(combo)`→`SendToClient`（同步 `NetworkStream.Write`）：录制到组合键时若 UXP 客户端缓慢/无响应，写阻塞卡死钩子线程消息循环 → 全键盘失灵（只有杀进程恢复）。这是「运行一段时间后打不出字」的真凶。
  ② `DrainLogQueue()` 在录制线程消息循环里 `Console.WriteLine` 写文件——写阻塞同样卡死钩子（代码旧注释已预警热键失灵）。
- 修复（native/HotkeyDaemon/Program.cs，已 `dotnet publish -c Release -r win-x64` 通过，0 警告 0 错误）：
  ① 日志：Console.SetOut 改为 `QueueTextWriter`（只把行入 BlockingCollection），由新 `LoggerThreadProc` 专线程落盘；`LogFromHook` 不再 PostThreadMessage 让钩子线程自己写；删除 `DrainLogQueue`/`WM_DRAIN_LOG`。钩子线程永不碰文件句柄。
  ② 录制回传：`FinishRecordingInternal` 把 `SendToClient` 移交 `Task.Run`（脱离钩子线程），共享 socket 设 `SendTimeout=2000` 兜底。
  ③ 焦点闸门：`LowLevelKeyboardProc` 首行加 `if (!IsPhotoshopForeground()) return CallNextHookEx(...)`；新增 `IsPhotoshopForeground`（GetForegroundWindow+GetWindowThreadProcessId 比对 PID）+ `RefreshPsPids`（WatchPhotoshop 周期刷新 `_psPids`）。

### 焦点暂停监听（新需求）
- 旧逻辑只按「PS 进程是否运行」(_active) 拦截；现为「前台焦点是否落在 PS」拦截：焦点在其它程序时钩子直接放行（不拦截/不录制），满足「焦点不在 PS 时暂停监听」。
