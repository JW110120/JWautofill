# 2026-10-13

## 蒙版同步「无任务仍刷 modal scope」修复 + 全量高频 modal scope 清点

### 报障
用户截图：`[蒙版同步] 收到事件: set` 后紧跟红色 `821 Too many modal scope commands`，
且**当前一个蒙版同步任务都没有**。诉求：① 无同步任务时监听应停摆；
② 线稿参考下拉是否也产生高频 modal scope、能否改成展开时才取文件树；
③ 列出还有哪些监听会导致高频 modal scope。

### 根因（MaskSyncEngine）
「没任务」的短路点位置错了 —— 它排在**四个受保护读取之后**：
`refreshActiveDoc`(1) + `psRead(app.activeDocument)`(1) + `refreshActiveDoc` 又一次(1)
+ `checkUndoGate→readActiveHistoryId`(1)，之后才 `if (list.length===0) return`。
`set` 是最高频事件（画一笔/改滑块/拖选区各一条）⇒ 无任务时反而模态命令最密。
2s 兜底轮询再重复一遍这 4 个。

### 改动
**`src/utils/MaskSyncEngine.ts`**
- 新增 `IDLE_POLL_INTERVAL_MS = 6000`、`hasAnyTask()`（全局，零 IPC）、
  `hasRunnableTask()`（当前文档，启用且配置完整）、`syncPollingCadence()`、`pollInterval`。
- `handleNotification`：全局无任务时，仅**文档级事件**（`isDocLevelDescriptor`）
  唤醒身份刷新；普通事件直接 return。新增 `isDocLevelDescriptor` 导入。
- `doTimedSync` 改为**三级短路，全部前置到任何 `psRead` 之前**：
  ① 全局无任务 → 0 次读取；② 当前文档无任务 → 只做身份跟踪；
  ③ 无 runnable 任务 → 只跑 `reconcileStructureIfNeeded()`。
- 「取活动文档」与 `refreshActiveDoc` **两读合一**（都读 id+name），`d` 延后到
  真的要跑像素同步时才取。
- 抽出 `reconcileStructureIfNeeded()`（原 doTimedSync 内联的 hasPaths + 签名比较 +
  reconcileTasks），使「要不要 reconcile」与「要不要跑像素同步」解耦。
- `startPolling` 节奏随空闲态切换（有任务 2s / 无任务 6s）；
  `addTask`/`updateTask`/`removeTask` 调 `syncPollingCadence()`。

**`src/adjustments/AdjustmentPanel.tsx`**
- `refreshMaskSyncAndReconcile()` 开头 `if (!maskSyncEngine.hasAnyTask()) return;`
  （只挡通知驱动；`onOpen` 通路不变）。
- 线稿参考监听 `handleNotification` 打脏/刷新收窄为**仅结构事件**
  （make/delete/move/rename + `isDocLevelDescriptor` + `shouldInvalidateLayerInfo`）；
  纯选区 `set`/`clearEvent`/切图层通道 `select` 不再打脏。
- 线稿参考 `Select` 加 `onOpen={refreshLineReferenceOptions}` 兜底时效。
- 新增导入 `isDocLevelDescriptor`（psProbe）、`shouldInvalidateLayerInfo`（LayerInfoHandler）。

### 线稿参考的根因（比预想更深）
两缺陷叠加：① 回调对**每条**通知（含纯选区 set）无条件 `invalidateLayerSnapshot()`；
② `refreshLineReferenceOptions` 里 `refreshLayerSnapshot()` **没传 maxAgeMs** ⇒ 不吃缓存。
⇒ 每条 set = 1 模态作用域 + ≈5N 次 get。
且 `scheduleStructureProbe` 里的 `if (!isLayerSnapshotDirty()) return`
因上一行刚打脏而**永远为真**，守卫形同虚设。

### 关键教训
⛔ **短路必须排在所有受保护读取之前**。「没任务/没数据就返回」写在链路末尾，
等于每个高频事件仍付全额模态作用域成本 —— 这是「无任务反而最拥堵」的通用模式。
⛔ 事件驱动的缓存打脏必须**按语义分类**（结构 vs 选区），不能「来什么事件都打脏」；
否则下游的 `isDirty()` 守卫与 `maxAgeMs` 复用全部失效。
⚠️ UXP 各面板是**独立 JS 上下文**：`app.tsx`（选区填充）与 `AdjustmentPanel`（绘画工具箱）
是两个 entrypoint，`MaskSyncEngine` 单例只存在于后者。
