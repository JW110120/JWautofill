## HUD 拖浮窗误显（0x0237 进画布迟滞）+ 滚轮第 2 版三层纠正 —— 已部署

- **现象**：长按 Coolorus 浮窗标题栏拖动时不出 HUD（对），**松手后短暂显示 ~124ms 再消失**。
- **真机证据**（jwwh-15996，18:14:22）：`焦点门·过 cur=(573,337) hit=Static par=PSViewC **mouseMsg=OWL.Dock**` → `显示: penDown=1` → 124ms 后 `隐藏: ck=1 **cv=0** gate=1 penDown=1`。
- **根因**：浮窗拖动时 Windows 把它从命中测试摘掉（DWM 幽灵窗口），`WindowFromPoint` 在松手瞬间返回画布 ⇒ 焦点门 0→1；`penDown` 还挂在 1（合成包残留/CONTACT_HOLD 尾巴）⇒ cheapOk 成立 ⇒ 圆冒 124ms，浮窗恢复命中后 cv=0 又消失。
- **修法（smooth_engine.c 0x0237）**：只给 `cv` 的 0→1 方向加迟滞 `CANVAS_OK_ENTER_MS=200`：`cv=0` 时记 `s_cvOffAt`，之后须连续 200ms 命中画布才放行（why=8）。`cheapOk=0` 的跳帧**不推进** `s_cvOffAt`（否则每笔起头白等 200ms）。⛔ 不用「起笔点须在画布」：Wintab 悬停就可能 penDown=1 ⇒ 会整笔无 HUD（0x0121 死法）。代价：刚从非画布移回画布 200ms 内不画（用户还没落笔，通常无感）。
- **滚轮第 1 版无效**（用户实测仍 0.1、可为负、面板不滚的副作用也没出现）：说明 UXP 的 number 滚轮是**原生控件内部行为**，`preventDefault` 拦不住且 `wheel` 未必派发/冒泡到 document。
- **第 2 版（`src/utils/numberInputWheel.ts` 重写）三层**：① document+window+元素级（MutationObserver 逐个挂）`wheel`：能判方向就 ±step 并 clamp，同时记 `wheelUntil`；② 滚轮窗口内 150ms 的 `input`：按「lastGood ± step」纠正（**方向由新值与上次合法值推出**，不依赖 delta 字段）；③ 无滚轮窗口时，差值恰为 ±0.1 且 step≠0.1 ⇒ 判为原生滚轮并纠正（治「连 wheel 都收不到」的环境）。⛔ 写入用原生 value setter + input 事件；`ourWriteEl/ourWriteVal/ourWriteAt(200ms)` 防递归且**必须连值一起比**（否则原生在我们写回后 60ms 内的 0.1 会被误认为自家写入而漏纠）；⛔ `keydown` 开 500ms 键入窗口，手输的值（如 3.3）一律不被纠正。`lastGood` 用 WeakMap 逐框维护。
- 验证：`build.sh` 零告警 + PiPL 往返一致；`tsc` 新文件零报错。.8li md5 `f57331…`（0x0237，**需重启 PS**）；bundle md5 `33f77a…`（**需关掉面板再打开**）。
