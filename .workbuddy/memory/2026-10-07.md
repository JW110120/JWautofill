## APP 父子面板四项优化（app.tsx / 三个子面板 / common.css / app.css / MenuManager / state.ts）

### 1. 填充模式提到「填充选项」区首位（普通 + 紧凑一致）
- 整块 JSX 从三个开关行之后移到 `collapse-content-expanded` **首位**，加显式类 `.fill-mode-section`
  （UXP 无 `:has()`，不能靠「首元素」这类结构选择器反推，故必须挂类）。
- app.css 紧凑规则**相邻关系反转**：删掉 `.row-grid + .panel-section{margin-top:7px}`，
  改为 `.fill-mode-section{margin-bottom:0}` + `.fill-mode-section + .row-grid{margin-top:7px}`。
- ⚠️ `.row-grid-fit{margin-bottom:0}` **必须保留** —— 旧版归零是因为它后面是 panel-section（间距由 7px 那条给），
  移位后后继换成 divider（自带 10px 上边距），不归零会叠成 20px。删掉它 = 描边模式行下方行距突变。

### 2. 子面板打开时隐藏菜单里的「隐藏/显示分区」项
- `MenuManager.setAppVisibilityItemMounted(mounted)`：`removeAt` 摘除 / `insertAt` 挂回，
  在 app.tsx `componentDidUpdate` 的 `isAnySecondaryPanelOpen` 变化分支调用。
- 🔴 **UXP 铁律（新踩）**：`removeAt` 只把项摘出菜单，**宿主侧仍记得这个 id**；
  用同一 id 再 `insertAt` 会抛「...as it already exists」⇒ **整个面板起不来**（与两面板同名 id 同级后果）。
  解法：重新插入用 `原id#递增轮次`，分派前 `normalizeMenuId()` 截掉 `#` 后缀再进 switch。
- 摘除时**不能按固定下标**（菜单项会随其它动态改动移位）⇒ `getItemAt(i)` 遍历 + 前缀匹配找下标。
- 不用 `enabled=false`：那只是灰掉、仍占一行，达不到「隐藏」。

### 3. 复位参数补齐纯色/图案/渐变三个子面板
- 根因：三个子面板参数活在**各自组件内部 state**，父面板 `...initialState` 管不到
  （描边之所以正常，是它的参数本就在父面板 state 里）。
- 解法：`AppState.resetToken`（自增计数）→ 传 `resetToken` prop → 三个子面板
  `prevResetTokenRef` 跳过首次、变化时 `setXxx(默认值)`。
- ⚠️ `resetToken` 必须写在 `...initialState` **之后**：`initialState.resetToken` 恒为 0，
  放展开之前会被覆盖成 0、子面板收到 0 不触发复位。
- ⚠️ **渐变面板的陷阱**：它有一条「参数变化 → 回写当前选中预设」的 effect（依赖 gradientType/angle/stops 等）。
  复位时若保留 `selectedPreset`，用户的预设会被就地改写成默认值（等于悄悄毁掉预设）。
  ⇒ 复位**必须先清选中态**让该 effect 落空。图案面板同理清 selectedPattern。
- ⚠️ 三个子面板复位都**不动 presets/patterns 列表**（预设是用户资产，不是参数；用户明确要求）。
- 纯色面板复位后靠已有的 300ms 防抖 `onSave` 自动回传父面板，无需额外回传。

### 4. 三列 radio 顽疾（换行 + 局促）根因与解法
- 用户诉求：首项贴容器左缘、末项贴右缘、中项正中、项间距自动。
- **数学前提**：三项**等宽** + `space-between` ⇒ 中项自动精确居中。所以「中项居中」不需额外手段，
  只需保证等宽 —— 而等宽的前提是三项内容宽一致。
- 🔴 **真正的根因是宿主 `sp-radio` 自带的 15px 水平内边距**：三项 = 45px 纯浪费，
  全被吞进每个选项盒子内部。旧方案为了让三项之和 < 内容盒，只能继续砍标签宽度
  （`width: 22px`，比 2 个 13px 字的 26px 还窄 4px、文字溢出盒外）⇒ 间距被挤没、版式局促。
- 解法：`padding-left/right: 0` 归零宿主内边距 + 标签盒回 26px 自然宽
  ⇒ 单项 ≈ 51px、三项 ≈ 153px，剩余宽度全额变成可见项间距（210 档每缝 ≈28px、200 档 ≈23px）。
- ⚠️ 渐进增强：若某宿主版本不允许覆盖 sp-radio 的 padding，该规则空转，
  单项仍 76−0=76px…此时仅靠「标签去 10px 右外边距」即可压到 198px ≤ 200px 仍不换行。两条都不会更糟。
- ⚠️ `flex-wrap:nowrap` 保留但**不可依赖它防溢出**（实测 UXP 下写了照样换行，
  sp-radio-group 内部均分/换行由宿主实现）。

### 顺带修掉的既有缺陷

## 同日第二轮修正（用户实测反馈后）

### A. 分割线随填充模式移位漏改（问题 1，已修）
- 移位后普通模式末尾出现**两条连续 divider**，且「填充模式」与「新建图层」之间**没有** divider。
- 修法：删掉「清除模式」后面那条多余的 divider，在普通模式分支**开头**补一条

- ⚠️ **教训：整块 JSX 移位时，必须把它「夹在中间」的分隔元素一起搬过去**。
  只搬主体元素 ⇒ 旧位置的 divider 留下重复、新位置缺 divider。

### B. 🔴🔴 菜单项「越来越少」= removeAt/insertAt 方案是错的（问题 2，已换方案）
- 上一轮为满足「隐藏显示/隐藏分区按钮」做了 `menuItems.removeAt()` 摘除 + `insertAt()` 挂回。
- **用户实测：反复开关子面板，菜单选项越来越少** —— 累积损坏。
- 根因：UXP 的 `menuItems.removeAt()` **与宿主内部状态不同步**
  （Adobe 官方论坛确认：removeAt 后项在宿主内存里仍残留、getItem 返回 null、无法按同 id 重插）。
  `insertAt` 每轮插回的位置被宿主算到既有项之前 ⇒ 反复挤压掉其它菜单项。
- **正确做法：只用 `enabled`（官方文档保证「立即生效」的幂等属性），绝不 removeAt/insertAt。**
  `MenuManager.setAppVisibilityItemEnabled(enabled)`，逐个 `getItemAt` 按 id 前缀同步。
- 代价与取舍：该行仍占位呈灰态、不是完全消失 —— 这是「不破坏整个菜单」的自觉取舍，两者取其轻。
- ⚠️ 连带的部署风险：若用户跑过旧版本，宿主侧可能仍残留带 `#` 后缀的项 ⇒
  保留 `normalizeMenuId()`（截 `#` 后缀）作为无害兼容，不再新增带后缀的 id。

### C. 三列 radio 全面改自绘 + 修紧凑模式行距（问题 3）

  弃用原因两条硬事实：① 内部排版由宿主实现，`flex-wrap:nowrap`/`space-between` 全拦不住它折行；
  ② 自带 15px 水平内边距（三项 45px 被吞进盒内），不砍标签宽度就没法不局促。
- 两处三列都换掉：父面板紧凑「填充模式」（app.tsx）+ 描边「位置」（StrokeSetting.tsx）。

- 紧凑模式保留「点文字开子面板」：新增 `labelRenderer` prop，
  ⚠️ 自定义文字节点**必须自己 `e.stopPropagation()`**，否则点文字会连带触发外层选中（开面板同时切模式）。
- 版式改为**三项 `flex:1 1 0` 等宽 + 内部居中**（不再用 space-between + 等宽内容）：
  后者要求三项内容宽**严格相等**，一旦某项文字多一画就不再居中；让 flex 均分容器更稳。
- CSS：`.radio-group` / `.radio-option` / `.radio-option-dot`（12px、圆角写显式 **6px**，不写 999px）

  ⚠️ 空心圆**禁用 `background:transparent`**（UXP 下渲染成纯黑），用 `var(--entry-bg)`。
- **行距修正（用户反馈「偏小」）**：
  - `.fill-mode-section + .row-grid` 7px → **10px**（7px 是旧结构「上方还有一行网格」时的压缩值，
    移位后 radio 成了分区首元素，上方不再有网格 ⇒ 7px 视觉偏紧）。
  - `.row-grid-fit{margin-bottom:0}` → **10px**。🔴 关键：该归零的理由是「其后紧跟 divider，不归零会叠 20px」，
    但 **divider 在紧凑模式下是 `display:none`、不占任何空间** ⇒ 归零等于让「描边模式」直接贴住
    「自动删选区」。**教训：给某个元素归零外边距前，必须先确认它后面的元素是否真的占位**
    （display:none 的元素不占位，这条与「divider 隐藏后相邻兄弟选择器仍命中」是两件事，别混）。

### 补充：JSX 整块移位的通用检查项（问题 1 引申）
整块 JSX 跨位置搬移后，**必查这三样**（本轮全部踩到）：
1. **夹在中间的分隔元素**（divider）—— 旧位置留重复、新位置缺一条；
2. **依赖相邻兄弟选择器的 CSS**（`X + Y`）—— 相邻关系反转后规则失效或误命中；
3. **为「后继元素」写的补偿值**（`margin-bottom:0` 等）—— 后继变了就得重算。

### 3. 🔴 自绘 radio「点不动」+「没占满整行」
**(a) 点不动的根因 = 事件签名不兼容（不是布局/层叠问题）**
- `app.tsx` 的 `handleFillModeChange(event)` 从 **`event.target.selected`** 取值（原生 sp-radio-group 的路径），
  且整个函数体被 `try/catch{}` **静默吞掉异常** ⇒ 自绘组件传裸字符串时 `event.target` 为 undefined，
  异常被吞 ⇒ **点多少次都没反应、也不报错**。这是「静默失效」的典型案例。
- 修法：`RadioGroup` 的 `onChange` 回传 `{ target: { value, selected } }` —— **同时提供两个键**，
  `e.target.value` 与 `e.target.selected` 两条取值路径都能工作 ⇒ 四处调用零改动。
- 与 ToggleSwitch 刻意回传 `{target:{checked}}` 是同一套「兼容原生事件形状」设计，已写进组件头注。
- ⚠️ **教训：替换原生控件时必须核对「调用方从事件对象的哪个属性取值」**。
  只看类型签名（都是 `(e) => void`）会漏判；而 `try/catch` 吞异常会把 bug 伪装成「点击无响应」。

**(b) 没占满整行 = 三列容器缺 `width:100%`**
- `.radio-group` 有 `width:100%`，但三列容器是被 `.radio-trio`（有左右 10px padding）包着的**独立 div**，
  作为块级元素在 UXP 下未被拉伸到父内容盒 ⇒ 三列挤在左侧一小块。
- 修法：三种版式（trio/pair/vertical）一律显式 `width:100%` + `box-sizing:border-box`，不再依赖隐式拉伸。

**(c) 全量替换 sp-radio（用户要求「所有 sp-radio 都换成自绘」）**
- 4 处全换：`app.tsx` 普通模式填充模式（纵向+齿轮 suffix）、`StrokeSetting` 位置（三列）、
  `ColorSettingsPanel` 计算方法（两列）、`PatternPicker` 填充方式（两列）。
- `RadioOption` 新增 **`suffix?: ReactNode`** 字段承载齿轮按钮（替代原 `.row-end` 包裹）。
- ⚠️ 普通模式的 options **只能在 render 内构造**（齿轮要绑 `this` 的方法与 title，无法提到模块级）；
  紧凑模式/两列/描边的选项表仍用**模块级常量**保引用稳定（`React.memo` 靠引用比较）。
- 清理死代码：common.css 里 79 行原生 radio 规则（`sp-radio-group`/`sp-radio`/`radio-pair-230`/
  `radio-pair-210`/`radio-group-vertical`）全删；app.css 的齿轮间距选择器
  `sp-radio .row-end .icon-button` → `.radio-vertical .radio-option .icon-button`。
- ⚠️ `StrokeSetting` 的 RadioGroup onChange 曾漏改（写成 `(v) => onPositionChange(v as ...)`），
  收到事件对象后类型断言失效 ⇒ 修成 `(e) => ...e.target.value as ...`。
  **替换组件后必须逐个复核调用点的回调签名**，不能只改 JSX 标签名。

## 同日第四轮修正：亮色主题可读性（3 条）

### 1+2. 自绘滑块圆点 / 开关手柄 / radio 选中项 —— 白手柄在亮色主题不可见
- 🔴 **根因：硬编码 `rgb(255,255,255)`**。`.range-slider-thumb` 与 `.toggle-switch-knob`
  都写死白色 ⇒ 在 light/lightest 的浅灰轨道/胶囊上几乎看不见（用户反馈可读性差）。
- **新增两个令牌**（theme.ts，四主题齐全，规则统一为「深主题白 / 亮主题近黑」）：
  - `--control-handle-color`：滑块圆点 + 开关手柄共用（深 rgb(255,255,255) / 亮 rgb(10,10,10)）
  - `--radio-checked-color`：radio 选中项圆心（**不与开关手柄合并**，语义不同，见下）
- ⚠️ **radio 选中项不要复用 `--primary-color`**：原先圆心填主色蓝 + 外圈也是主色蓝，
  在亮色主题下选中项与「开启态胶囊 / 滑块填充」同色 ⇒ radio 选中态**淹没**在 switch/slider 里、失去区分。
  现改为「外圈描边 = 主色蓝（保留主色语义）+ 圆心 = `--radio-checked-color`（深浅随主题反转）」。
- ⚠️ inset 留白色由 `var(--entry-bg)` 改 `var(--bg-color)`（与手柄同源、随主题深浅反转）。

### 3. 状态灯绿色在亮色主题发灰
- 🔴 **根因有两层**（只改颜色值不够）：
  ① `--notify-ok-fg` 亮色主题是 `rgb(21,128,61)`，本身偏暗；
  ② **外圈辉光写死 `rgba(46,204,113,0.6)`（半透明浅绿）** —— 这层浅绿光晕
     叠在浅灰底上会把整颗点**冲淡成灰绿**，这才是"看着发灰"的直接原因。
- 修法：辉光改 `currentColor`（= fill 色，自动跟随加深后的令牌），
  `--notify-ok-fg` 亮色主题调深为 `rgb(15,109,52)`。
  ⚠️ 深色主题 currentColor = rgb(74,222,128)，比原色更亮 ⇒ 光晕更明显，无副作用。
- 专注模式靶心图标的 `filter: drop-shadow(...)` 同样固定浅绿，一并改 `currentColor`。

### 🔴 4. radio「没占满整行容器」的**真正根因**（前两轮改错地方）
- 前两轮我一直以为问题在 `.radio-trio-group`（三列容器）缺 `width:100%`，加了但**没治好**。
- **真因在 `.radio-trio`（三列的父包装层）**：`margin: 10px auto` 里的 **auto 横向外边距
  会禁用 flex 容器的 `align-items: stretch`**（CSS 规范：auto margin 优先于拉伸对齐）
  ⇒ `.radio-trio` 塌成「内容宽度 + 水平居中」⇒ 三列挤在容器中间一小块、右边大片空白。
- 修法：`.radio-trio` 显式 `width: 100%`（auto margin 无余量可分配 ⇒ 真正占满内容盒）。
  ⚠️ `margin: 10px auto` 本身**不能删**（纵向 10px 行距还要靠它）。
- **两列场景**（颜色面板「计算方法」/图案面板「填充方式」）**没有 `.radio-trio` 包裹**、
  直接是 `.panel-section` 的 flex item（无 auto margin）⇒ `.radio-pair-group` 的
  `width:100%` 已足够，无需额外处理。
- ⚠️ **教训：flex 子项「没占满容器」优先查 `margin: auto`**，而不是先给子元素加 width ——
  auto margin 与 stretch 是互斥的，加 width 只是掩盖症状（这里 width 确实也加了，但必须加在
  **带 auto margin 的那一层**，加在子元素上无效）。

### 🔴🔴 本仓最易算错的一条：两种外边距行为必须分清
- `.panel`（及 `.collapse-content-expanded`、`.border-panel-section` 的**父级**）是**块容器**
  ⇒ **相邻兄弟外边距折叠、取 max**。
- `.panel-section` / `.border-panel-section` 是 **flex 列容器**
  ⇒ 它的子项（`.row-between` / `.radio-trio`，各带 `margin:10px auto`）的上下外边距**不折叠**，
  会**叠加在 section 自身下边距之外**。
⇒ 于是「内容行 ↔ 分割线」的距离永远是**两项相加**：
`行内 margin-bottom 10 + max(section 下边距, divider 上边距 10)`，
只按折叠算（漏掉行内那 10px）必然算错。**本轮我第一次就踩了这个坑**，
写完 stroke.css 后重算才发现，已在注释里写明推导过程。

### 1. radio 行间距 → 对齐滑块行（common.css `.radio-vertical .radio-option`）
- `height: 32px → 24px`。推导：滑块行视觉白缝 = 32px 满高输入框 + 10px = **10px**；
  radio 行内最高的**可见**元素只有 14px 的齿轮图标（`IconButton` 盒 24px 但 `background:transparent`
  ⇒ 盒子不可见），32px 行盒上下各留 9px ⇒ 白缝 32−14 = **18px**（实测 17px，吻合）。
  改 24px 后上下各留 5px ⇒ 白缝 **10px**，与滑块行同档。
- ⚠️ **不加外边距**：加边距只会把已偏宽的白缝进一步撑大，与需求相反。行距只由行盒高度决定。

### 2. 渐变行 ↔ divider 对称（app.css `#app .fill-mode-section`）
- `margin-bottom: 15px → 10px`。`.collapse-content-expanded` 是块容器 ⇒ 折叠取 max：
  原上方 = max(15,10) = 15px、下方 = max(10,10) = 10px（截图反推确认为 15/10，不对称）。
  收到 10px 后两侧同为 10px。
- 特异性 (1,0,1) 低于紧凑模式的 `body.compact-app … .fill-mode-section`（1 id + 4 class + 2 element）
  ⇒ 紧凑模式（装 `.radio-trio`）不受影响，无需额外排除。

### 3. 单位符号容器（common.css `.num-unit`，29 处调用点一次生效）

  `text-align: center → right` + `justify-content: center → flex-end`（文字紧贴槽位右缘）。
- ⚠️ 宽度必须按**最宽的 `px`** 算（Source Han Sans 13px 下 p≈0.573em + x≈0.513em ≈ 14.1px，留 2px 余量），
  **不能按 `%` 算**（`%` 墨迹只有 8px）—— 否则羽化/描边宽度两行的 `px` 会溢出压回输入框。

  中间 `.slider-track`（flex:1）抠掉 1px**；再叠加居中留白 ⇒ 轨道被压短 + 右侧死白 ⇒ 重心左移。

- ⚠️ **渐变面板的 `#` 必须显式钉回原值**（gradient.css `.num-unit-hash` 加
  `width/flex:20px` + `text-align/justify-content:center`）：`#` 是**前缀**、后面还跟 62px 宽色值框，

## 修「切换活动文档时弹『易修: 命令"获取"当前不可用』」

### 根因（不是单点bug，是一类缺失）
宿主弹框绕过 JS try/catch 与 `_options.dialogOptions` ⇒ **唯一有效防护是「不发 get」**。
切文档是 PS 的**长命令**（重建文档窗口 + 图层面板 + 历史状态），忙碌窗口 ~1s+，而原代码三处都按「短命令」设计：
1. **无守卫的 300ms 轮询**：`pollQuickMask`（读 `activeDocument.quickMaskMode`）与 `pollToolChange`
   （发 batchPlay `get application.tool`）**完全不查 `isPsBusy()`**，与用户操作完全异步 ⇒ 必然有机会落进切文档窗口。
2. **固定等待的防抖**：`debouncePsProbe` 只等 200ms、AdjustmentPanel 的 `scheduleRefresh` 只等 300ms，
   到期就发 get——事件后 200~300ms PS 往往还在切。
3. **忙碌窗口写死 300ms**：`markPsBusy(PROBE_IDLE_MS)` 不区分事件类型，切文档与「合并图层」同等对待。
4. `MaskSyncEngine.scheduleSync` 的忙碌闸门在 `doTimedSync` 里，但 `checkDocFirst` 分支的 `refreshActiveDoc()`
   （读 activeDocument + name）在闸门**之前**执行，不受保护。
5. **启动期同理**：`checkMaskModes` / `refreshLineReferenceOptions` / `refreshMaskSyncOptions` /
   `maskSyncEngine.init` 里的 `refreshActiveDoc` 都在挂载瞬间裸调（挂载也是忙碌峰值）。

### UXP 事实核查（重要，别再找错方向）
- **UXP没有 `currentDocumentChanged` 事件**。官方 Action 事件表（eventcodes）与 Core 事件表都没有；
  那是 ExtendScript / Generator 的网络事件。`app.on()` 也不在官方 Photoshop 类文档的方法表里。
- 唯一可行识别：**`select` 事件 + `descriptor._target` 含 `{_ref:'document'}`**（官方论坛：已打开文档之间切换会派发 select）。
  ⚠️ 必须**同时限定 eventName === 'select'**，否则改文档级属性的 `set` 也命中 → 平白多等 900ms。

### 新增铁律
- **「固定等待 + 统一忙碌窗口」只对短命令成立**。任何长命令（切文档、打开大文件、批量导出）
  都需要 (a) 按事件类型给不同窗口、(b) 探测点自己再查一次 `isPsBusy()` 并顺延、(c) 无条件轮询必须有闸门。
- **闸门位置要覆盖「闸门之前的所有读取」**，不只是主流程入口（`scheduleSync` 的 `checkDocFirst` 就是反例）。
- **切换判定不要只用文档名** —— 同名文档互切是最隐蔽的一类漏判。
