## 二次修复（用户反馈 3 个运行时 bug，22:36）

- **A. 选择文件报错 `e.trim is not a function`**：根因是 `getFileForOpening` 的 `types` 写成了 DOM 风格的 `{description, accept}` 对象数组；UXP 内部对每个 types 元素调 `.trim()` → 对象没有该方法而崩。正确签名是**扩展名字符串数组** `types: ['exe','bat']`。已修正，并归一化返回值（单文件/数组两种返回），catch 安全字符串化。
- **B. 唤起安装器失败 `could not find an entry of plugin:/native`**：`getPluginFolder().getEntry('native')` 在沙箱下找不到 native 目录。改为用 `getPluginFolder().nativePath` 拿真实系统路径再 `shell.openPath(完整路径)`，绕开沙箱。安装器/卸载器都走这个 `getBundledNativePath` + `openBundled` 帮助函数（openPath 成功返回空串、失败返回错误串）。
- **C. 笔刷未能自动枚举**：原 `enumerateBrushes` 用 `get` + `brushPreset ordinal all`，取到的结构里拿不到 name 列表。改为读 application 描述符的 `presetManager`（第 0 组 = Brush Presets，第 7 组 = Tool Presets），并优先尝试 `app.brushes.get()`。结构解析做了多重兼容（presetManager 可能是分组数组，或带 preset/brushPreset 容器；结果可能直接是 presetManager 描述符）。`HotkeyBridge.ts` 已 `import { app }`。
- 生产构建验证通过（仅资源体积 warning，无 ws/error）。
- **关键坑记录**：UXP `getFileForOpening` 的 `types` 是字符串数组（非 DOM 对象数组）；插件内定位文件优先用 `getPluginFolder().nativePath` 而非 `getEntry`（沙箱下 native 目录不可见）。
