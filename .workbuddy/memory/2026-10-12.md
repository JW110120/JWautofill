## 套索工具实时平滑 — 可行性分析与实施计划（未动代码）

产出：`docs/lasso-realtime-smoothing-plan.md`（v1，待用户确认）。

### 关键结论（新增认知，可复用于后续讨论）
- **UXP 层完全没有画布指针输入能力**：全仓无画布指针 API；`app.tsx:552` 的 `document.addEventListener('mousemove')` 监听的是**插件面板自身 DOM**，不是 PS 画布。⇒ 「绘制过程中实时平滑」在纯插件内**不可能实现**。
- UXP 唯一能拿到套索结果的时刻是**提交后**（`set` 通知 + `channel + _property:'selection'`，`app.tsx:534`）⇒ 在 UXP 侧做平滑天然等于"事后平滑"，与现有「选区改造」（`SelectionHandler.ts`）同形态。
- **只有入口（PS 收到鼠标输入之前）能实时** ⇒ 必须扩展 `native/HotkeyDaemon` 挂 `WH_MOUSE_LL` + `SendInput` 回注（即 Lazy Nezumi Pro 的路线）。
- 现有骨架可直接复用：常驻 `WH_KEYBOARD_LL` 钩子线程（`Program.cs:859`）、`IsPhotoshopForeground()`（`Program.cs:765`）、WS `127.0.0.1:18923`（`HotkeyBridge.ts:24`）、**300ms 工具巡检**（`app.tsx:2034/2075`，可作为布防/撤防信号源）。
- 三个候选插入点：① 输入层（唯一可实时）；② 选区生成后 = 现有「选区改造」（本次已排除，且栅格域取轮廓有量化损失）；③ PS 内部轨迹后处理（**不可行**，PS 不暴露套索中间轨迹；`Select > Modify > Smooth` 属提交后掩码形态学，是 ② 的变体）。
- PS 的 Smoothing 四要素（Standard / Smooth / Stroke Catch-up / Pulled String）**只存在于画笔类工具，套索没有** —— 这正是本功能要补的缺口。

### 最大风险（写给未来自己）
- 🔴 数位板/触控笔可能不走 `WH_MOUSE_LL`（PS 走 Wintab/Windows Ink 直读）⇒ 平板用户完全不生效。**必须先做 P0 探针验证**。
- 🔴 注入事件回环（自己 `SendInput` 的事件又进自己的钩子）⇒ 输入风暴。必须 `dwExtraInfo` 签名 + `LLMHF_INJECTED` 双判据。
- 🔴 钩子回调阻塞 ⇒ 全系统输入卡顿（既有铁律：钩子线程严禁阻塞 I/O，Program.cs:5）。
- 🟠 `LowLevelHooksTimeout` 会**静默摘钩**且不通知 ⇒ 需心跳自检 + 自动重挂。
- 🟠 若采用"写回选区"形态（降级方案 B）⇒ 写回会再触发 `set` 通知 ⇒ **二次填充**，需"自写抑制令牌"。

### 推荐方案形态
主路径 = 输入层滤波（标准/拉绳/追笔三档）；降级兜底 = 提交时轮廓精修（平板用户）；远期备选 = 原生覆盖层自绘 + 提交时路径化（工作量最大，历史记录会缺"套索"步）。

### 分阶段
P0 可行性探针（**决策门**，不产生可见功能）→ P1 布防通路 → P2 滤波算法（离线对拍驱动）→ P3 参数 UI/持久化 → P4 兼容性安全收口 → P5 可选质量增强。

### 待用户确认的开放问题
Q1 输入设备范围 / Q2 是否接受光标被拖后 / Q3 参数面精简度 / Q4 默认值与默认开关 / Q5 布防范围 / **Q6「锚点调整机制」具体所指（三种解读已分别给结论）** / Q7 与「选区改造」是否联动禁用 / Q8 决策门失败是否接受降级交付 / Q9 发布形态（需重编分发 daemon）/ Q10 是否需要临时加强键。

### 新认知（值得写进铁律）
1. ⛔ **`.row-between.disabled .range-slider` 对传了自定义 `className` 的 `RangeSlider` 不生效**：`RangeSlider` 根节点是 `className={className || 'range-slider'}`，调用方一旦传 `slider-track`（行内滑块标准写法），根节点上就**没有** `.range-slider`；且组件自身的 `disabled` **只改 tabIndex、不改视觉**。⇒ 只写 `.range-slider` 会让禁用态毫无视觉反馈。已在 `common.css` 把 `.slider-track` 列入选择器。（这是仓库既有规则里的潜在缺陷，非本次引入。）
2. ✅ 仓库已有的「行级禁用」规范可直接复用：TSX 给行挂 `.disabled`、给控件传 `disabled`，`common.css` 里 `.row-between.disabled [class^="label-"]` 负责标签置灰、`.row-between.disabled input / .slider-track` 负责控件置灰。**自绘控件（ToggleSwitch / RadioGroup / Select）各自还有 `*-disabled` 类**，不需要额外处理。
3. ⛔ **平滑布防必须复用 300ms 工具巡检，不能另起定时器**：`readCurrentToolId()` 每轮是一次模态作用域内的 batchPlay get，两条 300ms 轮询 = 双倍宿主往返（本仓交互延迟的主因）。做法：`syncToolWatch()` 的启停条件由「主开关 && 自动关」扩为「|| 平滑总开关」，`pollToolChange()` 里把「自动关」分支改为按需执行，并在更新 `lastKnownTool` 后**立即** `syncLassoSmoothingArm(tool)`（必须排在「首轮只记基准就 return」之前，否则打开平滑后若工具一直没变，布防永远等不到机会）。
4. ⛔ **`smoothStatus` 必须列入「参数复位」的保持项**：它由守护进程回报（是否装上钩子 / 是否在拖拽），不是用户参数。被 `...initialState` 打回 `connected:false` 后，状态行会一直谎报「未连接快捷键服务」，而状态广播只在布防/撤防/连接变化时才发 ⇒ 不会自愈。
5. **设计决定（可推翻）**：总开关关闭时**不禁用**任何参数（参数是预置值，可先调好再开；与「选区改造」滑块恒可编辑一致）；只有「参数不适用于当前滤波族」才整行禁用（张力↔拉绳、追笔↔追笔、拐角/速度适应↔标准）。另：复位时**保留** `smoothEnabled`（与 `strokeEnabled` 同理，功能开关不算参数），但 `smoothParams` 复位，且复位回调里要**重新下发**参数（否则面板显示默认值、daemon 仍用旧值）。
6. ⛔ **改 `Program.cs` 后必须「先 `dotnet publish`、再 `yarn build`」两步**：`webpack.config.js` 只是把 `native/HotkeyDaemon/publish/JWautofillHotkeyDaemon.exe` 拷进 dist。本次发现 publish/ 里的 exe 还是 10-10 的旧产物（不含鼠标钩子），漏了这步就会"代码改了、插件包里还是旧 exe"。
7. ⛔ **状态广播的时序**：`SetSmoothArm` 返回时钩子还没装上（`SetWindowsHookEx` 由钩子线程异步执行）⇒ 在那里广播会让面板每次启用都闪一下红色「启动失败」。改为 `SetSmoothArm` **不广播**，由 `SmoothWatchdog`（120ms 采样、2s 健康检查）在「连续两轮读数一致且与上次上报不同」时上报。拖拽开始/结束也走这条 —— 钩子线程严禁 I/O，只能由旁路线程补播。副作用是「生效中」变成可用指标，而它是数位板场景（钩子装上了但收不到事件）唯一的 UI 判据。

# 第二轮（同日）：双钩子解耦 + 两个真机缺陷（plan v3 第 10 节）

## 需求
平滑钩子与热键钩子必须**完全独立**（禁用/卸载任一侧不影响另一侧）；并修两个真机问题：
① 套索工具下开启功能，状态行误显示「待命」；② 绘制选区后显示「启动失败（被安全软件拦截）」，关掉电脑管家也不行。

## 根因（均已用证据锁定，非猜测）
1. **「待命」误报 = 布防镜像不在 state**。`lassoArmed` 是实例字段，而状态行文案/配色全靠它；
   布防在 300ms 工具巡检里**异步**完成 ⇒ 那一刻没有 state 变化 ⇒ **不重渲染** ⇒ 状态行停在
   布防前算出的「待命（当前不是套索工具）」，直到别的原因触发重渲染才跳成真实文案。
   （与用户观察到的「开启时显示待命、绘制后才变」完全吻合。）
2. **「启动失败」误报 = 跑的是旧版守护进程**。三条证据：
   - 独立探针用与守护进程**完全相同**的 P/Invoke 写法安装 `WH_MOUSE_LL`/`WH_KEYBOARD_LL`，
     16 种组合（有无显式 `EntryPoint`、`A`/`W`、`hMod` 用不用 `GetModuleHandle(NULL)`）**全部 OK**
     ⇒ 系统策略与写法都没问题，先证伪「安全软件拦截」。
   - 活体守护进程 `getState` 回 `"version":"2026-09-06.1"`，响应里**根本没有**平滑字段。
   - 安装目录 `%LOCALAPPDATA%\JWautofill\daemon\` 的 exe 是 **9 月 7 日**产物，`daemon.log` 首行同版本。
   旧进程不认识 `smoothArm`（未知 type **静默丢弃**）⇒ 面板永远收不到 `smoothState` ⇒
   `hookInstalled` 恒 false ⇒ 被文案判成「被安全软件拦截」，把排查带偏。

## 改动
**原生（Program.cs）**：两套钩子改成结构对称、状态零共享的子系统。
- 新增 `hotkeyArm`（运行期独立装卸键盘钩子，此前只能进程级） + `WM_HOOK_UNINSTALL(0x8008)`。
- 新增 `HotkeyWatchdog`（此前只有平滑侧有看护）与 `SmoothWatchdog` 对称：**线程存活探针**
  （`Thread.IsAlive`，线程死了重建并由线程体自行装配）+ **熔断自愈**（`*SafeModeSince` +
  `SafeModeCooldownMs=30s`，此前是单向闩锁 ⇒ 一次抖动永久废掉该侧）+ 句柄重挂。
- 两条钩子线程消息循环**逐轮 try/catch**（未捕获异常会让整条线程消失、钩子被连带摘除、
  `_threadId` 变死地址，PostThreadMessage 不报错但消息进死队列 ⇒ 该侧永久失效）。
- `HandleClient` finally 的三段清理各自 try/catch；`WatchPhotoshop` 整轮 try/catch（其 `_psPids`
  是两个钩子共用的前置条件，线程一死两侧同时「莫名失效」）。
- 能力协商：`protocol:"2.0"` + `features[]`，新增 `hotkeyState`；版本 `2026-10-12.2`。
- `PostThreadMessage` 的消息参数是 `uint`：三元表达式**不是常量表达式**，拿不到 C# 常量隐式转换，
  必须显式 `(uint)`；`MSG.message` 是 `uint`，取出来要转 `int` 才能和 `WM_*` 常量比较。

**UXP**：
- `state.smoothArmed` 取代实例字段 `lassoArmed`；新增 `smoothToolId`/`smoothToolErr`，
  状态行区分「工具读不到」（`待命（无法读取当前工具）`）与「读到了但不是套索」
  （`待命（当前工具：多边形套索）`，未知 ID 原样显示枚举名）。
- `LassoSmoothing` 增加 `unsupported` 能力探测：建连后主动发 `smoothStatus`，
  `PROBE_TIMEOUT_MS=2500` 内无任何 `smoothState` ⇒ 状态行显示「守护进程版本过旧，请重启守护进程」。

## 边界（必须对用户讲清楚）
**子系统级**（`smoothArm`/`hotkeyArm`、各自熔断/看护/状态）= 互不影响；
**进程级**（面板「守护进程」开关、卸载、开机自启）= 两者同时停 —— 进程没了两个钩子都不存在。
要「关掉服务开关但平滑继续工作」只能拆成**两个独立进程**（各自 exe/自启项/安装目录），本次未做。

## 诊断手法（可复用）
- **活体守护进程探针**：`analysis/ws-raw-probe.cjs` —— **必须手写 WS 帧**，因为
  `HandleClient` 用**大小写敏感**正则匹配 `Sec-WebSocket-Key:`，Node 的 undici WebSocket
  发小写首部会被拒（非 101）。
- **钩子安装探针**：`analysis/hookprobe/`（dotnet 控制台，隔离进程，装完立刻卸、不泵消息 ⇒ 零回调）。
- **守护进程日志**：`%LOCALAPPDATA%\JWautofill\daemon\daemon.log`（FileMode.Create，每次启动重写）。
- **更新已装守护进程**：面板服务开关「先关 → 再开」（拉起插件包内新 exe，它自比对哈希、停旧副本、
  拷到安装目录并重新拉起）；或手动结束进程后双击 `<插件目录>/native/HotkeyDaemon/publish/JWautofillHotkeyDaemon.exe`。
- ⛔ 本会话 PowerShell 工具**无任何输出**（连 `Write-Output` 都没有），改走 dotnet 控制台 + Bash。

## 校验
`dotnet build` 0 警告 0 错误；`tsc` 仍 131 条且新增标识符未出现在任何报错中；三个契约守卫通过；
`publish + webpack` 成功。守护进程已更新到 `2026-10-12.2` 并重启。

## 四项改动
1. `MouseHookBudgetMs` 30 → **120ms**（Windows `LowLevelHooksTimeout` 默认 300ms，留 2.5× 余量）。
2. 新增 `SafeModeStrikes = 2`：**连续**两次超预算才熔断；任一回落到预算内即清零计数（键盘侧同样适用）。
3. **钩子回调内不再有任何日志**：拖拽汇总 / 熔断告警改由两个看护线程代打
   （`_smoothPendingDragLog` / `_smoothPendingBreakLog` / `_hotkeyPendingBreakLog`，看护线程 120ms 一轮）。
   `LogFromHook` 注释收紧为「仅限录制/解绑这类低频路径」。
4. **零 I/O 耗时拆解**：钩子里只累加 Stopwatch tick（`_mouseCbInjectTicks`，回调开头清零），
   落进内存字段后经 `smoothState` 上报：`budgetMs / strikes / overBudget / lastCbMs / lastCbInjectMs /
   maxCbMs / maxCbInjectMs / worstOverCbMs / worstOverInjectMs`。
   其中 `worstOver*` **永不重置**（`maxCb*` 随每笔清零，事后去看常已被覆盖）。

## 实测（v.4 运行期 smoothState 读数 —— 这一条直接给出了答案）
```
budgetMs=120 strikes=0 overBudget=4 maxCbMs=2 maxCbInjectMs=2 callbacks=8190 injected=1531
```
- `overBudget=4` ⇒ 确有超 120ms 的帧，但**从未连续** ⇒ `strikes` 恒 0，正是「抖动不再毁会话」的预期；
- **`maxCbInjectMs == maxCbMs`（2/2）⇒ 慢帧耗时 100% 来自 `SendInput` 回注**，与滤波算法无关。

### ⛔ 三个坑（均已固化进工具与文档）
1. **`GetExitCodeThread` 只回传 32 位** ⇒ 用它取远程 `LoadLibraryW` 的 HMODULE 会**静默截断高位**，
   拿截断值 `FreeLibrary` 必然返回 FALSE 且**无任何报错**（现象 = 卸载失败但 PS 完好）。
   ⇒ 注入是否成功改用**证据文件**判定；卸载基址改用 `EnumProcessModulesEx`（见 `inject.py --eject`）。
2. **十六进制地址不要手算** —— 第一次换算错了，白多花一轮排查。
3. **`kernel32.dll` 是共享映像** ⇒ 本进程 `GetProcAddress` 的地址在目标进程同样有效，无需远程解析。
