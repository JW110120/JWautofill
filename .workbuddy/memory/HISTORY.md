## 立项（2026-08）

- Photoshop UXP 插件，React 19 + TypeScript + webpack 5，目标平台 **Windows**。两块面板：**选区填充（APP）** 与 **绘画工具箱（adjustment）**，同一 HTML 文档、同一 bundle。
- 架构：UXP 面板 + 原生 companion 进程（C#/.NET8 `HotkeyDaemon`）承载全局快捷键与键盘设备修复，绕过 UXP 无全局热键 API 的限制。
- 主题：自绘 flat 风格，四套 `darkest/dark/light/lightest`（`theme.ts` 令牌驱动）。
- 分发：B 站主页售激活码；`docs/*.html` 使用手册 + README。

## 前端规范期（2026-09-04 ~ 09-10）

- 把面板 CSS 逐类收口到 `common.css`（**单一来源**），确立「状态类只写差异、盒模型写进共享选择器列表」的写法；确立 `index.tsx` 的 CSS 引入链与「严禁 `@import`」。
- 踩定并沉淀一批 UXP 渲染坑：原生可编辑控件永远在最上层（只能隐藏）、`:has()` 静默失效、flex `gap` 不可靠、`scrollbar-gutter:stable` 导致「中间态」右侧裁切、`var()` 在弹层子树解析不稳定、`<Provider>` 会插 `height:auto` 层断掉高度链 → 汇总进技能 `uxp-frontend-spec`。
- 原生控件全面自绘：`RangeSlider`（PS 27.9.1 起原生 range 的 step 失效）、`Select`（`sp-picker` 弹层背景无法覆盖）、`RadioGroup`（`sp-radio-group` 不可控、带 15px 内边距）、`ToggleSwitch`。
- 新增「专注模式」「紧凑模式（后拆成 6 个作用域）」，并确立「紧凑模式改完要在普通模式复测、反之亦然」。
- 立 spot check 手法：**改版式前用像素脚本量用户截图**（本仓截图恒 1.5×、内容盒 230px），不目测。

## 边缘平滑算法期（2026-09-18 ~ 09-19）

- 分块平均「对比减弱」定稿（`s = 强度×0.07`、`p=1` 严格单调 —— 用户的硬条件「压缩后大小关系不变」直接砍掉了 `p>1` 的方向）。**教训：先问清质量约束，比事后调参便宜得多。**
- `lineSmoothProcessor`「仅主线条」：细线（<5px）整段消失的根因定位（半径开运算按结构元宽度筛 + σ 与细线半宽同量级 + 连通域连坐）→ 改**面积开运算 + 逐像素自适应 σ**。
- 宽度拉平 `flattenRadius` 落地：确立「SDF 高斯拉不平粗细波浪（算子尺度不匹配）」的判断，改用偏置式方案 + 中轴跟随分侧修正。三次修复收敛，沉淀「限幅对称 / 双侧邻域参照 / 重分配封顶为 |Δ|」等铁律。
- `aliasSmoothProcessor`（消除锯齿）四条不变量确立，细线走几何重建。
- 结论性认知：**距离场平滑只作用于宽度 ≳2.5σ 的结构，≤4px 线在数学上无法被距离场平滑**，该类细化应交给消除锯齿的细线重建路径。
- V7 中轴重建把「逐遍墨量单向漂移（棘轮）」根治 → 两条保墨铁律（密度源用保墨平均、未覆盖像素掩码归一）。

## alpha 对齐期（2026-09-23）

- `alphaAlignProcessor` 语义经 v6→v10 五轮反复，最终定稿 **v10 三档整片归一**：三个按钮 = 同一选区直方图的三个统计量（max/min/众数），动作都是整片归一。
- **明确否掉**：v7「平台保护」、v8「单侧写回」、v9「规模门槛」—— 前者把候选吃光、中者在不匹配的稿上空转、后者用户不要。
- 新增「极值微调」两个按钮（`processExtremeAlign`）= 旧 v5 环带参照复活，作用通道由 alpha 扩展到 RGBA（线条污渍专用）。
- **方法论收获**：从用户截图恢复真实素材（block-center 采样 + 中值）以复现 console 直方图；台架必须报「作用量 vs 原图」而非只看「看起来还行」。

## 弹框治理 + 性能（2026-10-06 ~ 10-08）

- 起因：切文档 / 快速删图层 / 删完立刻填充必弹宿主原生「命令"获取"当前不可用」。
- 定位：UXP 每次都同步 IPC 往返（属性读也算）⇒ 填充 0.5s 里大半是固定等待 + 同步 IPC；「命令中途派发通知」导致收到即读必撞忙碌窗口。
- 两次「我以为修好了」的教训：① 缩短全局闸门窗口 → 4 类新问题（共享闸门的 9 处消费者提前放闸）；② 「逐项核对后断言无影响」也只核对了填充路径。**结论：共享闸门改动必须先 grep 出全部消费者。**
- 终态：全局闸门（粗筛）与填充私有冷却 `fillReadyRemain()` **解耦**；不变量 `fillReadyRemain() ≤ psBusyRemain()`。
- 确立「合并 batchPlay 只在全部命令都必然成功时才安全」「省 IPC 必须来自读一次复用、不能来自不读」等铁律。

## 模态作用域真机定性（2026-10-08 晚 ~ 10-09）

- 用户真机「单次删除图层即弹框」→ 定位到一个结构性支点：`psAccess.psTryRead()` 的直读分支最终判据是 `core.isModal()`。
- 真机探针定性：**`core.isModal()` 会采信宿主的模态态**（PS 打开大文档/存储为时它也返回 true）。
- 修复：新增 `psAccess.runAsModal()` 作**唯一模态入口**并维护 `ownModalDepth`；判据改为 `getOwnModalDepth() > 0`；同步接口**永不遍历**；结构类事件分级 + 作废宿主租约。
- 同日再修 `runAsModal` 三缺陷（opts 分岔 / 通知包装器 WeakMap 记忆化 / 置入图层事件注册）+ 描边色板拾色器灰态初值缺陷 → 沉淀为 `scripts/` 下的两个契约守卫。

## 套索实时平滑：从鼠标钩子到 .8li（2026-10-11 ~ 10-14）

- **可行性定案（10-12）**：UXP 无画布指针 API ⇒ 实时平滑唯一入口是「PS 收到输入之前」。P0 探针证实**数位板不走 `WH_MOUSE_LL`** ⇒ 鼠标钩子路线对平板用户无效，转向 **Wintab**（`WTPacketsGet` 是笔通路唯一咽喉，实测钩上即计数、停笔即冻结）。
- **P0–P4 落地**（当时在 HotkeyDaemon）：标准/拉绳/追笔三档、防回环双判据（`LLMHF_INJECTED` + `dwExtraInfo` 签名）、看门狗自愈；面板侧「平滑选项」折叠分区 + 90ms 节流 + 线格式签名去重。用户明确 **P5（提交时轮廓精修）不做**。
- **架构转向（10-14，M1–M3）**：注入 DLL 的整类故障面（state=4 须重启 / DLL 锁自安装 / 跨进程状态撕裂）驱动迁移到 **PS 进程内 .8li**。逆向标本 `MouseHookPro64.8li`（实为 Lazy Nezumi Pro）拿到 PiPL 格式与 SP 消息协议；三颗排障定案：① PiPL 头是 **10 字节**（误写 12 字节 ⇒ PS 静默拒载）；② `'8664'` 入口名属性是 **C 字符串**（误写 Pascal 串 ⇒ attach 后 1ms 秒卸）；③ 对照实验（逐字节拷贝改名探针）证明加载器**认内容不认路径**。引擎 + WS 合入进程内，daemon 链路退役。
- 同期真机迭代沉淀（均已入 `refs/lasso-smoothing.md`）：拉绳必须定长、工具闸门 fail-closed、包布局 stride=52/offX=20/offY=24、断流判读 = `[stall]` 与 `[dead]` 差集。

## 真机几何根因与断流治理（2026-10-15 ~ 10-16）

- **3440 带鱼屏定案**：`px` 权威 = **屏幕坐标 / lcOutExt**（122 样本回归，纠正此前所有「圆心分离」轮次的共同底层误差）；断流看门狗改「自冻结起点累计位移」（慢速一笔也能 ~1s 判出）；HUD 断流态改红圈钉光标而非一律隐藏。
- **0x0106–0x010B 六轮判决**：`WTOverlap` 自愈被证伪（120 次请求一包未回 ⇒ 驱动侧不往 PS 上下文排队）；HUD 偶发不显示 = 跨线程**无符号下溢**（日志 `t=4294967280` 铁证）；断流呈「断级式恶化」且 **>5s 断流对看门狗隐身**（penDown 锁存超时清零）；HUD 恒不显示真因 = **UpdateLayeredWindow 不碰 z 序**（改 `CreateWindowExW` 的 `WS_EX_TOPMOST` 才对）。
- **部署纪律（事故）**：`build.sh` 不产出 `.ready.8li`，手工残留件导致「旧二进制复测」空跑一轮 ⇒ 部署只认 `build/` 下唯一产物，日志头 `ver=` 是部署核验依据。
- **推送纪律（用户 10-16 明确）**：只在「用户去睡觉/下班、让助理跑代码」时推送；用户盯着项目时**不推**。已入铁律。

## 容易被反复问到的历史决策（速查）

- 为什么不给用户自动切换笔刷做类型检测？—— 会逐支切换用户当前笔刷，只在手动刷新时做。
- 为什么 `location._enum` 一律 `strokeLength`、但 `width` 保留两种写法？—— 现场监听证据优先；通道上下文的裸数字是 PS 自身形状，非通航。
- 为什么像素处理器都「自包含、零 import」？—— 便于把「只改一个常量的副本」放到任意目录做单常量敏感性扫描。
- 为什么 `analysis/`、`outputs/` 被 gitignore？—— 只是本地开发草稿；因此**记忆与技能不得依赖其中的文件**（跨机不同步）。2026-10-17 大整理已把记忆里悬空的文件引用清成结论，并确立分工：**沉淀后的诊断工具进 `scripts/`（git 跟踪），`analysis/` 只放临时报告与未复核工具**。
- 为什么平滑最终搬进 .8li、不停在「守护进程 + 注入 DLL」？—— 注入有整类故障面（state=4 须重启 / DLL 锁 / 跨进程撕裂）；进程内合法插件（LN 同路线）从类别上消灭它们。
- 为什么先做鼠标钩子又改 Wintab？—— P0 探针证实数位板不走 `WH_MOUSE_LL`，鼠标路线对平板用户恒不生效。
- 为什么 HUD 要问 Windows 要焦点？—— Wintab 系统上下文与焦点无关：面板/弹窗抢前台时笔包照常进，但 HUD 必须只属于「焦点在画布且已落笔」。
- 什么时候允许推送远端？—— 仅用户去睡觉/下班让助理跑代码时；用户盯着项目时不推（用户 10-16 明确）。
