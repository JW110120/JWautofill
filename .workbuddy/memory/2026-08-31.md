## LicenseDialog / 绘画工具箱遮罩 第五轮修正（4 条需求）
- **输入框「内层变黑 + 溢出」根因与定稿结构**：
  - ① `background-color: transparent` 在 UXP 的 `<input>` 上会被绘制成 **纯黑 rgb(0,0,0)**（四主题皆然）→ 内层 input 必须与外层 wrap **同色**，一律写 `background-color: var(--dropdown-bg-color)`，**禁止 transparent**。
  - ② 原生 input 的绘制区高于 CSS 盒，且 **`overflow:hidden` 裁不掉**（与官方 Known Issues「text field 永远画在最上层」同源）→ 不能让 input 撑满 wrap。定稿：`wrap 34px 固定高 + display:flex + align-items:center`，`input 26px`（上下各留 4px 缓冲，原生区高到 34px 也能包住）。
- **UXP 下 flex `gap` 不可靠**：实测标签/输入框/按钮会紧贴在一起。纵向间距一律改 **margin**（标签→输入框 8px、输入框→按钮 12px、试用说明→按钮 12px、组间/分割线 14px）。
- **深色主题下链接下划线偏暗根因**：`.license-contact` 容器上的 `opacity:0.8` 会连同子元素 `<a>` 的 `color` 与 `border-bottom` 一起压暗（深底 0.8 混合后明显发暗，浅底混合后偏亮所以「看着没事」）。修法：容器 opacity 取消，改给普通文字加 `.license-contact-dim{opacity:0.7}`，链接保持不透明。
- **绘画工具箱遮罩两处修复**：
  - 激活提示卡片被遮罩盖住：UXP 下 `position:fixed` 元素绘制在普通内容之上，**卡片 z-index 再高也没用**。修法：锁定态时把卡片节点**渲染进 `.adjustment-lock-overlay` 内部**（遮罩加 `padding:10px` 与容器对齐）。
  - number input 浮在遮罩上方：沿用主面板 `body.license-dialog-open` 的做法 → AdjustmentPanel 在锁定态给 body 加 `.adjustment-lock-open`，`adjustment-input.css` 里 `body.adjustment-lock-open #pixeladjustment input/textarea{visibility:hidden!important;opacity:0!important;pointer-events:none!important}`（必须带 `!important` 压过 `.adjust-expand-content.expanded` 的 `visibility:visible`）。
  - 顺手修掉 `adjustment-input.css` 顶部一处**未闭合的块注释**（第 1 行 `/* …` 一直吃到第 8 行的 `*/`，导致首条 `body.visibility-panel-open` 规则整段失效，靠下面重复的第二条规则才生效）。
- **激活/注销后弹窗残留旧激活码与提示**：LicenseDialog 加 `useEffect(..., [isOpen])` 清空 `licenseKey/message/messageType/isVerifying/inputFocused`。⚠️ 依赖数组**只能放 isOpen**，放 isLicensed/isTrial 会在激活成功瞬间把「激活成功」提示清掉。

- **激活提示卡片右边被滚动条压住的根因**：`.adjustment-lock-overlay` 是 `position:fixed`，铺满**整个面板宽度**（不扣滚动条），而普通内容是按「内容区宽度」（已扣滚动条 10px）排布的 → 遮罩内的卡片比正常内容多向右伸 10px，正好压在滚动条下。

## 激活提示/链接 第七轮修正（2 条需求）
- **「联系作者」下划线消失 + darkest/dark 仍偏暗**：第六轮给链接上了 `var(--link-color, fallback)`。但 UXP 对动态注入组件 `<style>` 里的 `var()`（尤其两参 fallback 写法）解析不稳，整条 `color`/`border-bottom` 声明会被丢弃 → 下划线消失、文字回退成默认暗蓝。

## 激活提示/链接/同步 第八轮修正（3 条需求）

### 1. 锁定态横幅右缘被滚动条压住（结构性定稿）
- 用户关键实测：遮罩未渲染时横幅在文档流顶部、右边距正确；遮罩渲染后横幅右缘右移被滚动条压住；50% 宽度测试右缘也异常右移。
- **根因**：横幅此前渲染进 `position:fixed` 遮罩内部——fixed 遮罩的包含块比普通内容区宽（不扣右侧滚动条），卡片一旦进遮罩整体右移，`margin-right:10px`/`width` 都补不回来。
- **修法（结构性）**：横幅永远留在普通文档流（AdjustmentPanel JSX 顶层 `{bannerNode}`）；遮罩改为从卡片下方开始——内联样式 `top:46px`（容器 padding-top 10 + 卡片 30 + 下边距 6）、`height:calc(100% - 46px)`；无卡片的边缘情形用 `top:10px`。`.adjustment-lock-overlay` 基础 CSS 只留 left/right/bottom/width/z-index（top/height 由 JSX 内联给）。删除 `.adjustment-lock-banner` 包装。遮罩不再装任何内容→无需任何滚动条宽度补偿。

### 2. darkest/dark 下「联系作者」文字比下划线深一截
- **根因**：UXP 会强制用自带链接色渲染 `<a>` 文字，作者 `color` 被忽略（深色主题回退默认暗蓝）；`border-bottom` 是纯 CSS 所以正常——文字与下划线颜色脱钩。
- **修法**：`<a>` 改成可点击 `<span role="button" tabIndex={0}>`（反正 UXP `<a href>` 也不唤起浏览器，走 `shell.openExternal`），颜色完全由 CSS 控制；`.license-link` 仍按四主题字面色 + `@media` 写死（不用 var()）。

### 3. 主面板弹窗与工具箱锁定遮罩不同步
- 晚出现：两面板各自独立读存储、先后完成 → 改 `LicenseManager.getLicenseState()` **记忆化**（`stateCache` 静态 Promise，同 bundle 共享 JS 上下文，并发调用共享同一次读取）；app.tsx `checkLicenseStatus` 完成后 dispatch `license-updated`。
- 早消失：激活/试用成功时 `saveLicenseInfo` 原本立即广播 → 工具箱比弹窗早 800ms 解锁。改为 **`saveLicenseInfo` 不广播**（只失效缓存），广播移到 app.tsx `handleLicenseVerified`/`handleTrialStarted`（弹窗关闭同刻）。注销走 `clearLicense` 仍立即广播（弹窗同 tick 打开，天然同步）。

- 验证：`webpack --mode=production` 通过（仅体积警告）。
