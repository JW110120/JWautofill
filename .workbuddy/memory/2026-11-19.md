## 渐变 / 图案填充「剪贴关系」收尾重做（用户 8 组矩阵实测驱动）

用户用 A（剪贴基底）/ B（A 的剪贴蒙版副本）跑 8 组矩阵，暴露 4 个真问题。根因不是分支写错，
而是**收尾用的 `mergeLayersNew` / `groupEvent` 与 PS 的剪贴关系冲突**，而旧实现只能事后撞报错。

### 根因（三条，全部实证/推得）

1. **目标是剪贴基底（A）时，新建的内容图层会被 PS 自动塞进剪贴组**
   ⇒ `mergeLayersNew` 成功但继承裁剪语义 ⇒ 「没开特殊剪贴却像开了」（用户情况 1）。
   判据：建完内容层立刻读 `layer.isClippingMask === true`。
2. **目标是最上层剪贴蒙版（B）时，新建层不会自动剪贴** ⇒ `mergeLayersNew` 报「合并图层不可用」，
   整次填充丢失（情况 5/6）。用户处方正确：合并前先 `groupEvent`。
3. **`rasterizeLayer` 有可能换掉内容图层 id** ⇒ 用旧 id 读像素 / 删层会静默白跑
   （情况 7 表现为「栅格化+应用蒙版后没有后续合成」，层留在原地）。⇒ 每次栅格化后重读 id。

附带：`_obj:'set'` 的「还原上一个选区」在无上一个选区时被拒，会弹「设置不可用」并绕过 catch
⇒ 独立 try/catch + `dialogOptions:'silent'`。

## 第 5 轮（12:40）——两条真因：`Document.bounds` 不存在 + `ungroup` 是整组释放

用户 8 组复测：1/3/7 都「没有特殊剪贴效果」，1/2/3/4 还「上方所有剪贴蒙版被解除」，
2/4/8 在「静默失败 / 弹合并报错」之间摇摆。

### 真因 1（决定性）：`Document` 在 UXP 里**没有 `bounds`**

`getDocPixelSize()` 原来读 `doc.bounds` ⇒ `undefined` ⇒ 宽高 NaN ⇒ 返回 `{0,0}`
⇒ `blendTopIntoBase` / `compositeTopIntoBase` / `multiplyTopAlphaByBase` **第一行就
静默 `return false`**（只有 console.warn）⇒ 所有特殊剪贴都退回 `mergeIntoBase`
⇒ 于是我上一轮加的「合并 + 纠偏」全部成了唯一路径，才有了那些报错和摇摆。

✅ 正解：`Document.width` / `Document.height` 官方文档写明**就是像素**（Number）。
⛔ 不要用 `width._value`（那是标尺单位，得 × resolution/72，单位一变就算错）。

### 真因 2：`ungroup` / `isClippingMask=false` 会释放**整组**

UXP `Layer.isClippingMask` 是 R W，但文档原话：*Releasing a clipping mask will also
release the layers above*。PS 里**不存在「只释放某一层」** ⇒ 一次 `ungroup` 把 A 上方
3 个剪贴箭头全干掉（用户实测）。ExtendScript 圈传的 `setd → Lyr → UsrM:false`
其实是**图层蒙版开关**（`userMaskEnabled`），与剪贴无关，别用。

### 落地（收尾彻底与剪贴解耦）

- `SpecialClipMask.getDocPixelSize` → `doc.width/height`。
- 删 `releaseClippingMask` / `unclipActiveLayer`；`mergeIntoBase` 遇到
  「目标非剪贴层 + 内容层被塞进剪贴组」→ **不合并**，直接像素并集写回。
- 新增 `selectFrontLayer` / `selectLayerById` / `moveActiveLayerAbove` /
  `resolveActiveLayerId`（batchPlay `get _property:'layerID'`，避开 DOM 一帧滞后）。
- `GradientFill`：**「不新建图层」一律先 `selectFrontLayer()` 再建内容层** ⇒ 内容层一出生
  就没有剪贴关系 ⇒ 收尾统一为「栅格化 → 严格 applyMask → 写回目标层（特殊剪贴=乘基底
  alpha / 普通=并集）→ 删内容层 → 选回目标层」。三种目标（空层 / 有像素 / 剪贴基底或剪贴层）
  共用一条路；`applyMask` 失败则放弃像素写回、退回「移到目标层上方 + 合并」。
- 空图层分支不再依赖「PS 把空图层顶替成填充层」⇒ 混合模式不会被盖掉，`baseBlendMode`
  记录/还原整段删掉。
- `compositeTopIntoBase` 允许基底为空（读不到像素 ⇒ 按全透明 4 分量算）。
- `PatternFill`：同样先 `selectFrontLayer()`，收尾同一套（blend / union + 删临时层）。
- `app.tsx`：建新层后**不再释放剪贴**，只把真实 `isClippingMask` 写进 layerInfo。

### 代价 / 已知边界

- 每次「不新建图层」填充多一次整图 `getPixels`(基底+内容层) + `putPixels`(基底)。
- 情况 1/2 的观感会与上一轮略有不同：剪贴层不再被解除 ⇒ A 的 alpha 变大后，
  上方剪贴层会跟着显示到新区域（这正是 PS 对剪贴层的原生行为）。

## 第 7 轮（14:30）——特殊剪贴 + alpha=0 区域会乱填：写回需要三态

用户实测：特殊剪贴开启时，对某个剪贴蒙版的 alpha=0 区域画选区 ——
渐变会填到**最上方的剪贴蒙版**上；对最上方剪贴蒙版这么做还会弹「合并图层不可用」
并在其上新建成一个剪贴蒙版；图案则一律糊到最上层同位置。

### 根因

`blendTopIntoBase` 里 `if (baseA === 0) continue` 让 `touched === 0`，旧实现返回
`false` → 调用方当「写回失败」→ 降级 `moveActiveLayerAbove` + `mergeIntoBase` →
`mergeLayersNew` / `groupEvent` 只认**紧邻那一层**（此时内容层在最顶层，紧邻的
往往就是最上方那个剪贴蒙版）⇒ 上述三种乱象。

### 修复：`PixelWriteResult = 'written' | 'nothing' | 'failed'`

- `'nothing'`：基底在选区处 alpha 全 0 / 填充层全透明 / 读不到图层像素 ⇒ 语义上
  就**不该填**，属于成功；调用方只删内容层，**不许降级合并**。
- `'failed'`：仅 `putPixels` 抛错（锁定背景层 / 权限）——才允许走合并降级。
- `mergeIntoBase` 内部把 `'nothing'` 当「无内容可写」：同样删层后返回 `'composited'`。
- `GradientFill` / `PatternFill` 收尾改成 `writeResult !== 'failed'` 即删层。
