## alpha对齐"置入像素但无现象"——加跳过原因诊断（第十一轮）

**背景**：用户再次反馈同样症状（30px 笔刷、50% 不透明度画 X、圈选交叉点、点 alpha 对齐后有"置入像素"历史但无变化）。前几轮已确认：算法离线验证正确（Node 仿真交叉 225→150、changed=961），I/O 已对齐 handlePixelTransition 范式。第十轮加了 changedCount/validCount/alpha 分布日志，但只能判断"是否修改"，不能判断"为什么不修改"。

**改动**（`src/adjustments/alphaAlignProcessor.ts` 第 4 步）：在修改循环里统计每个候选像素的跳过原因：
- `skipLowAlpha`：a < minAlpha(32)
- `skipNoRef`：refMin >= 65535（所有尺度的环都找不到 alpha≥32 的参照——X 太短或选区孤立）
- `skipSmallPeak`：peak < peakThresh(10)（最可能：alpha 饱和到 255，单线和交叉点都 255 → peak=0；或选区只圈到单线没圈到交叉凸起）
- `maxPeak` + `maxPeakInfo`：候选像素里最大的 peak 及其位置/alpha/ref，用来判断是否阈值卡太严
- alpha 直方图（<64 / 64-128 / 129-220 / 221-255）：直接看笔刷实际 alpha 分布

**判读指引**（一条日志即可定位）：
- `221-255` 占绝大多数 + `maxPeak≈0` → 笔刷实际 alpha 饱和（流量/喷枪/多次描边），单线=交叉=255，无凸起可拉。让用户改用纯不透明度（流量 100、关喷枪、单笔）重画。
- `无参照` 大 + `maxPeak` 未知 → X 太短，所有尺度的环够不到单线；或选区把整条线都圈进去了。降低选区范围或加更大 scale。
- `peak过小` 大 + `maxPeak` 在 1~9 → 凸起很弱（笔刷不透明度叠加不明显），peakThresh=10 卡掉。可降阈值或让用户用更低不透明度。
- `候选=0` → 选区没覆盖任何 alpha>0 像素（选区检测/坐标系问题）。

**关键认知**：算法对干净的单次 50% 不透明度 X 必然生效（交叉 191、单线 128、k=22 环跳出凸包取 128、peak=63>10）。所以"无现象"必然是 changedCount=0，而 changedCount=0 的根因只能在"实际 alpha 不是 128/191"或"选区没圈到交叉凸起"或"环找不到参照"三者之一——新日志能直接区分。

**待办**：等用户跑一次回报 `🔍 [alpha对齐] 候选=… 跳过[… ] alpha直方图[… ] 最大peak=…` 这条日志。

## 第十二轮：环 MAX→MIN + 加大 scale + 阈值降到 5（修"只改中心一小块"和"粗线不支持"）

**用户反馈**（带截图）：
1. 30px X：算法只改了交叉中心一小块矩形，**菱形边框（凸包边缘）仍在**——"仿佛在菱形的中间填充了一个内接矩形"。
2. 50px X：算法完全没效果（粗线不支持）。
3. 多根粗细/不透明度不同的线：粗线改不掉；**细线有时需要多次点击**才能完全统一。

**根因（关键发现）**：
- 旧算法环上取 `MAX(alpha)`。对于**凸包边缘像素**，其环在所有尺度都包含凸包中心的高 alpha 像素（因为凸包是 2D 区域，环向内必然包含凸包中心），所以 `refMin = 凸包内的高 alpha`，`peak ≤ 0`，永远不修改。这就是"只改中心一小块"的根因。
- 旧 `maxK=32`，对 50px 线（凸包半径 35px）来说环根本逃不出凸包，`refMin` 全是高 alpha，所有尺度都失败。
- 细线"多次点击"：第一次点击只改了中心（凸包中心），边缘没改；用户觉得没改完再点，但第二次也改不了（同样的逻辑），所以永远改不完。

**修法（核心改动）**：
1. **环上取 `MIN(alpha≥MIN_ALPHA)`**（不再是 MAX）：
   - 凸包中心：环向外/垂直方向必有像素落在单线/透明外侧，MIN 就是单线水平 → peak>0 修改 ✓
   - 凸包边缘：同理，环向外侧落在单线，MIN=单线水平 → peak>0 修改 ✓（**关键修复**）
   - 单线像素：环上只有 1~2 个点在线上（其余透明），MIN=线水平 → peak=0 不改 ✓
   - 孤立像素：环内无有效参照，MIN=65535 → skip ✓
   - 大面积均匀填充：环 MIN=填充水平 → peak=0 不改 ✓
2. **`SCALES = [4, 8, 14, 22, 32, 50, 70]`**：覆盖 2px 细线到 80px 粗线的凸包。`ALPHA_ALIGN_HALO` 同步从 37 升到 75。
3. **`PEAK_THRESH` 从 10 降到 5**：捕捉更弱的凸起（低不透明度笔刷）。

**离线仿真验证**（Node 脚本，201×201 合成 X 对角线 30px/50px/80px + 3px 细线 + 纯单线段）：
| 场景 | OLD(MAX) 改像素数 | NEW(MIN) 改像素数 | 结论 |
|---|---|---|---|
| 30px X | 441 | 925 | 修了边缘（2x+ 覆盖） |
| 50px X | **0**（完全失效） | 2521 | 粗线支持 |
| 80px X | **0** | 5361 | 极粗线支持 |
| 3px 细线 X | 13 | 13 | 都不变（凸包本来就小） |
| 纯单线段（远离交叉） | — | **0** | 无误伤 |

**经验**：
- "环 max 取 min"是**为了逃出凸包**，但前提是凸包内有"自我高 alpha 主导"——对于边缘像素不成立。**环 min 取 min**直接拿"凸包外侧的低 alpha"作底线，对中心和边缘都成立，是更鲁棒的参照。
- 多尺度 + min 的组合，其作用从"找能逃出去的尺度"变成"在每个尺度都试一次取最低"，对凸包大小不敏感，所以加 50/70 两个大尺度只是兜底（80px 线），核心修法是 MIN 本身。
- 涉及"局部凸起消除/平滑"的算法，**参照应取邻域的极端值而非典型值**——典型值（中位数/均值）会被凸起自身污染，极端低值（MIN）/极端高值（MAX）才能定位"非凸起的环境水平"。具体取 MIN 还是 MAX 取决于语义：找"应有底线"用 MIN，找"应有上限"用 MAX。

## 第十三轮：alpha对齐"侵蚀/边界生硬"修复 + 像素过渡新增强力模式（中间值自动半径）

### Part A：alpha对齐两个新问题

**用户反馈**（带截图）：
1. 原本线条的不透明度被侵蚀。原因可能是：选区内含很多 alpha=0，或线段两端因压感导致 alpha 偏低，整体圈选时算法把"低不透明度区域"的值给所有线条。
2. 粗线 + 选区相对较小时，圈内归一化效果好但**边缘生硬**——"选区内突然被统一了"。

**根因 1（侵蚀）**：上一轮环 MIN 用了 `MIN_ALPHA=32` 门槛，把压感/渐变边缘（alpha 30-100）也当作"线条应有水平"参照。线条中心 128，环 MIN 取到渐变边缘的 80，于是中心 128→80 被错误"拉低"。

**修法**：把环参考门槛从 `MIN_ALPHA=32` 提到 **`MIN_REF_ALPHA=100`**，排除压感/渐变边缘的污染。100 是经验值：50% 不透明度笔刷的中心 alpha=128 在门槛之上，渐变边缘（<100）被排除。

**根因 2（边缘生硬）**：`applyProcessedPixels` 按 `selectionCoefficients` 硬切混合，selection 边界处 mask 0→255 的阶跃直接映射到 alpha 改动上。

**修法**（参考 specialSharpen 的 support 思路）：
- 新增 `support[]` 数组：用分离高斯（半径 10）对 `selectionMask` 做模糊，得到每个像素被选中区域"包围"的程度（0-1）。
- 在 step 4 输出 alpha 时，用 `smootherstep01(smootherstep01((s01-0.22)/0.775))` 把 support 映射成 fade 系数。
- 最终 alpha = `origA + (targetA - origA) * fade`——选区中心 fade≈1（完全改），边缘 fade≈0（不改），过渡平滑。

### Part B：像素过渡强力模式

**用户要求**：在 局部对比→像素过渡 旁边加 sp-switch 标签"强力模式"（样式参考分块平均的加权模式），开启后隐藏下方半径/强度滑块，效果类似 PS 中间值滤镜，自动估算等效半径（如 15px 笔触 → 半径 18）。

**实现**（`src/adjustments/powerfulTransitionProcessor.ts`，新文件）：
1. **Chamfer 3-4 距离变换**（两遍扫描）：对选区内 alpha>0 像素算到最近 alpha=0 像素的距离
2. 取最大距离 = 最粗笔触的"半宽"
3. **经验公式**：`medianRadius = max(3, min(35, round(maxDist * 2.4)))`
   - 15px 笔触：maxDist=7.5 → 半径=18 ✓
   - 5px 笔触：maxDist=2.5 → 半径=6
   - 35px 笔触：maxDist=17.5 → 半径=35（上限）
4. **条件中间值滤波器**：对每个通道 R/G/B/A 分别取中位数
   - 邻域只统计 alpha>0 的像素（避免透明像素把中位数拉到 0）
   - 用 256 桶直方图（O(boxSize+256) 每像素），比排序快
   - 背景图层 alpha 恒为 255 不参与中位数
5. 状态持久化：`usePowerfulMode` 接入 PanelStateManager 的 `toggles`

**UI 改动**（`AdjustmentPanel.tsx`）：
- 把 像素过渡 按钮包进 `adjustment-double-buttons`（与分块平均的 双按钮+开关 布局一致）
- 右侧加 sp-switch 标签"强力模式"
- `{!usePowerfulMode && (... 滑块 ...)}` 条件渲染
- `handlePixelTransition` 根据 `usePowerfulMode` 分派到 `processPixelTransitionPowerful` 或 `processPixelTransition`

### 经验
- **参考门槛分层**：环扫描里"参与计算"（如 MIN_ALPHA=32 防噪点）和"作为参照"（如 MIN_REF_ALPHA=100 排除压感渐变）是两个语义，不应该用同一个门槛。修复"侵蚀"问题的关键就是把这两个分开。
- **Support 羽化是普适技法**：任何"按选区 mask 改像素"的功能都会面临边界生硬，support 高斯模糊 + smootherstep 双层是干净的解法。specialSharpen 用过，alpha对齐也适用。
- **中间值半径 = 笔触半宽 × 2.4**：15px → 18 的经验公式（半宽 7.5 × 2.4 = 18）。对粗线用距离变换找最厚笔触，避免用户手动调参——强力模式核心思想。
- **条件中位数必须排除透明像素**：否则笔触会被自身的稀疏性（box 里大部分是透明）拉到 0。`if (nA === 0) continue` 是关键。

## 第十四轮：70px X "右下区域暗块"修复（环 MIN 阈值 100→125 + support 越界修复 + 安全 clamp）

**用户反馈**（带截图）：70px 粗线 X 圈选全部后，右下臂出现一块明显比周围暗的矩形斑块——"异常的不透明度提高"。

**根因分析**（关键）：
- 70px 粗线在 50% 不透明度下，渐变边缘（alpha 100-128）距离中心 2-7px
- 旧阈值 `MIN_REF_ALPHA=100` 允许渐变边缘参与"环 MIN"作为参照
- 对于右下臂的"单线中心"像素(alpha=128)，环 k=70 沿对角线指回交叉方向，环外侧 150-153px 处已无单线，但**环垂直方向 70-73px 处仍在线条渐变边缘内**（15-20px 宽的渐变带），环 MIN 拿到 100-120
- peak = 128 - 100 = 28 >= 5 → 被错误地"拉低"到 100
- 但**恰好在中心 ±1px 的像素**，环垂直方向只有 128 的中心像素（其他都在渐变边缘），环 MIN = 128，peak = 0 → 不修改
- 结果：渐变边缘被改成 100，中心保留 128 → **中心反衬下"亮"不起来，看起来像暗块**

**修复**（`alphaAlignProcessor.ts`）：

1. **`MIN_REF_ALPHA 100 → 125`**：只有中心 ±1px 内 (alpha 125-128) 算参照，渐变边缘 (100-120) 全部排除
   - 离线仿真 70px/50px/30px X 都验证：单线中心和渐变边 alpha 差 = 0，暗块消失
   - 5px 极细线也正常（凸包本来就小，13 像素被改）

2. **支持计算垂直 pass 越界修复**（`supportH` 读取 `undefined` → NaN → fade=NaN → alpha=0）：
   - 旧：`if (sy < 0 || sy >= height) continue;`——只检查文档边界，没检查区域边界 `sy - y0 ∈ [0, rh-1]`
   - 当 `y0 > 0`（区域不紧贴文档顶）时，垂直 kernel 上端 (`sy = y0 + ry + i - 20 < y0`) 读 `supportH[-20*rw+rx]` = undefined
   - 新：先累加 `weightSum += k`（保持归一化分母），再检查 `ryOffset ∈ [0, rh-1]`，越界则跳过但不漏算 kernel weight

3. **`FEATHER_RADIUS 10 → 20`**：羽化半径太小（10px）会让过渡在 70px 粗线上看起来像硬边；提到 20 让选区边缘更柔

4. **安全 clamp `na = min(na, a)`**：算法语义是"拉低"，永远不会升高 alpha；这里 clamp 防止任何数值异常（NaN 等）导致 alpha 反升

**离线验证**（70px X 仿真）：

| 位置 | 旧阈值(100) | 新阈值(125) |
|---|---|---|
| 交叉中心 | 192→128 ✓ | 192→128 ✓ |
| 单线中心 | 128→100 ✗ 暗块 | 128→128 ✓ |
| 单线渐变边 | 128→100 ✗ 暗块 | 128→128 ✓ |
| 中心-边 alpha 差 | +28（暗块）| **0** ✓ |

**经验**：
- **"环 MIN 阈值"对粗线特别敏感**：粗线渐变带宽（70px 线有 35px 渐变），低阈值会把渐变边缘当作"线条水平"参照，让中心像素被错误地参照到渐变边缘。粗线场景阈值必须 ≥ 中心 alpha - 5（对于 50% 不透明度笔刷是 123 以上）。
- **支持计算的归一化要分母完整**：kernel 越界时不能 `continue` 跳过 weightsum 累加，否则靠近边界的像素 support 计算会偏大（看起来"更被包围"），导致边缘羽化不连续。
- **算法语义保护**：始终明确算法的核心不变量（"拉低，不升高"），代码里加 clamp 防止任何数值异常破坏这个不变量。比依赖"理论上不会出问题"更可靠。

## 第十五轮：细线（<30px）无现象修复——环 MIN 阈值方案回退为无阈值 MAX + 大尺度

**用户反馈**：粗线（70px）支持好，但**小于 30px 的线交叉没有现象**。要求算法自动识别粗细，适配不同尺度。

**离线诊断（关键发现）**：
1. 固定阈值 `MIN_REF_ALPHA=125` 对低不透明度线完全失效：30% 不透明度线中心 alpha=77 < 125，环找不到参照 → 全部不处理
2. 即使 50% 不透明度（中心 128），8px 细线软笔刷只改 25 像素，4px 只改 9 像素——交叉凸包本来就只有这么点像素，效果微弱
3. **环形 MAX（无阈值）+ 大尺度（k=50/70）方案**：Chebyshev 方形环的"角"沿对角线方向探到交叉凸包外侧的单线像素（alpha = 线中心水平，与线宽/软硬/不透明度无关）
   - 70px 线交叉中心：k=4/8/14/22 的 MAX 被凸包主导（181/171/156/135），k=32/50/70 的"角"探到单线 → MAX=128 → min=128 ✓
   - 交叉边缘像素（曾导致"菱形边框"）：k=50/70 探到单线 → MAX=128 → 修改 ✓
   - 单线像素：任意尺度 MAX=自身线中心 → peak=0 不误伤 ✓

**修法**（`alphaAlignProcessor.ts`）：
1. **环计算从 MIN 回退到 MAX**（去掉 MIN_REF_ALPHA 固定阈值）
2. 保留大尺度 `SCALES=[4,8,14,22,32,50,70]`（k≥50 的"角"探到单线是 MAX 方案可行的关键）
3. 保留 support 羽化（FEATHER_RADIUS=20）和 `na=min(na,a)` 安全 clamp

**离线验证**（MAX 方案，软笔刷）：

| 线宽 | 交叉 | 改像素 | 结论 |
|---|---|---|---|
| 4px | 192→128 | 9 | 微弱（凸包物理上就 9 像素） |
| 8px | 192→128 | 25 | 微弱 |
| 12px | 192→128 | 49 | ✓ |
| 16-30px | 192→128 | 85-309 | ✓ |
| 50/70px | 192→128 | 829/1665 | ✓ |

| 不透明度(20px线) | 交叉→单线 | 结论 |
|---|---|---|
| 30% | 131→77 | ✓ 自动适配 |
| 40% | 163→102 | ✓ |
| 50% | 192→128 | ✓ |
| 60% | 214→153 | ✓ |
| 70% | 232→179 | ✓ |

**关键教训**：
- **先做"度量分析"再选算法**：写了几版方案（MIN+阈值、中位数）都不理想后，先 dump 交叉像素在各尺度环的 MAX/MEDIAN/MODE，立刻看出"环 MAX 在大尺度 = 线中心水平"这个规律，方案自然浮出。不要盲试参数。
- **Chebyshev 环的几何特性被低估了**：方形环的"角"比"边"探得更远（对角线方向 k√2 vs k），这恰恰让大尺度环能探到交叉凸包外的单线——MAX 方案成立的根本原因。
- **固定阈值是脆弱的抽象**：阈值把"什么是线条"硬编码成 alpha 数值，但线条 alpha 随不透明度变化。MAX（或更一般的"局部极值/分位数"）不需要知道 alpha 的具体数值，只利用"交叉凸起比单线高"这个拓扑事实，天然自适应。
- **MAX 方案的适用上限**：环的"角"探到单线需要 k√2 > 半宽×√2 即 k > 线宽。SCALES 到 70 支持 ~198px 线；更粗需加更大尺度。

## 第十六轮：粗线（50px+）交叉"只改中心小矩形"——加粗线模式开关（环 MIN 方案）

**用户反馈**：第15轮 MAX 方案对 <30px 线很好，但 **50px+ 线交叉的菱形区域只能统一一个小矩形**，不能完全统一。

**根因（通过仿真定位，非推算）**：
- 交叉凸包是菱形，沿**对角方向**顶点距中心 = 半宽，沿**轴方向**顶点距中心 = 半宽×√2
- MAX 方案靠环"角"（对角方向）探到凸包外单线 → 只覆盖凸包**对角方向**部分
- 凸包**轴方向**像素（如 100px 线 (100,30)，到两线垂直距离都 ~49.5px ≈ 半宽）：
  - 环小→全在凸包内（MAX=192）
  - 环大到出凸包→同时出两条线（垂直距离都 > 半宽，全透明 MAX=0）
  - **不存在"只在线1上的单线过渡带"→ 任意尺度都探不到参照 → 永不修改**
- 仿真确认：50px 线凸包 2521 改 2517 ✓；**70px 线 4901 只改 1681**；100px 改 0！

**尝试过的方案（均失败）**：
- 动态加大 SCALES（k 到 400）：轴方向像素无解（环出凸包即出线），100px 仍只改 76%
- MIN 方案：硬笔刷完美（单线 128→128 不侵蚀，凸包 192→128 全改），但**软笔刷单线中心 128→37 严重侵蚀**（环 MIN 探到渐变边缘）
- MAX/MIN 差判定（差 ≥ 阈值用 MIN）：软笔刷渐变边缘（差 68）与硬凸包轴方向（差 64）差值太接近，无法区分

**结论**：单像素局部信息**无法同时兼顾**"粗线硬凸包轴方向"与"软笔刷渐变边缘"——两者局部特征相同（自身=环内最高，环内有更低值）。采纳用户提议：**加"粗线模式"开关**。

**改动**：
1. `alphaAlignProcessor.ts`：
   - `AlphaAlignParams` 加 `mode?: 'standard' | 'thick'`
   - 环统计按模式分支：standard=MAX（默认，现有行为），thick=MIN
   - thick 的 MIN 方案：硬笔刷粗线凸包（含轴方向）完整统一（环 MIN 探到附近单线，小尺度即可）
2. `AdjustmentPanel.tsx`：

   - alpha对齐 右侧加"粗线模式" sp-switch（参考像素过渡强力模式的 double-buttons 布局）
   - handleAlphaAlign 传 `{ mode: useThickMode ? 'thick' : 'standard' }`

**使用指引**：普通模式=细线/软笔刷友好（默认）；粗线模式=硬笔刷/高硬度粗线线稿（软笔刷渐变边缘会被轻微拉低）。

**经验**：
- **几何分析要算"轴方向"而不只是"对角方向"**：菱形凸包的轴方向延伸（半宽×√2）超出线半宽，导致"环出凸包即出线"——这是 MAX 方案对粗线的根本局限，仿真一跑就暴露。
- **"环出凸包即出线"的检测**：对未修改像素 dump 各尺度环 MAX/MIN，看到 MAX 从 192 直接跳到 0（无中间 128），立刻确认无单线过渡带。
- **两个局部特征相同的区域（硬凸包轴方向 vs 软渐变边缘）无法用单像素信息区分**——这时与其堆算法，不如给用户一个模式开关，把选择权交还。开关语义要写清楚（什么时候用哪个）。
- **webpack 用 babel 转译，TS 类型错误不阻塞构建**：PanelStateManager 的 toggles/values 类型是固定的，新增 state 不更新类型会报 TS 错但构建仍成功。长期应把类型改成 index signature 或宽松类型。
