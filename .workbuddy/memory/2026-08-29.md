# 2026-08-29 工作日志

## 第四轮：快捷键「按了完全没反应」的真正根因（提交 19a181e）

1. **根因（实证）**：`RegisterHotKey(hwnd=HWND_MESSAGE, ...)` 返回 true、无冲突，日志里确实打印了
   `已注册热键 id=1 Ctrl+Alt+Shift+K`，但合成按键后守护进程**收不到任何 WM_HOTKEY**——
   WM_HOTKEY 不会派发到 message-only window。于是「录制成功、保存成功、按下无反应」。
   **排查方法**（可脱离用户手工复现，强烈推荐保留）：给 RegisterAll/WndProc 加注册与命中日志 →
   用 `analysis/hotkey/hotkey_trigger_test.mjs`（ws 建连 → 推测试映射 Ctrl+Alt+Shift+F12 →
   开空白 Notepad 并激活 → SendKeys 合成按键 → 看是否收到 `{type:'hotkey'}` 广播）。
2. **修法**：删掉 RegisterHotKey，改用一个**常驻 WH_KEYBOARD_LL 低层键盘钩子**，组合键在内存
   Dictionary 里匹配。附带收益：命中后 `return (IntPtr)1` 吞掉按键，PS 不会再抢走该组合键
   （Ctrl+Alt+Shift+K 在 PS 里是「键盘快捷键」对话框，RegisterHotKey 方案下会同时触发）；
   同时消灭了「RegisterHotKey 失败 err=1409 → 快捷键静默失效」这一类问题。
3. **踩坑**：常驻钩子必须由**承载线程自己**安装。改成主线程 `PostThreadMessage(recThreadId,
   WM_HOOK_INSTALL)` 会失败——线程消息队列在 GetMessage 之前尚未创建。日志表现为
   「钩子线程已启动」但没有「常驻键盘钩子已安装」。录制指令仍用 PostThreadMessage（那时已进入消息循环）。
4. **线程消息不进 WndProc**：PostThreadMessage 的消息必须在 GetMessage 循环里显式判断
   `msg.hwnd == IntPtr.Zero && msg.message == WM_HOTKEY_HIT`，DispatchMessage 不会派发它。
5. **JSON 转义误导**：System.Text.Json 默认把中文/'+' 转义成 `\u96C6\u4E2D`、`\u002B`，用户以为是乱码。
   改用 `Encoder = JavaScriptEncoder.UnsafeRelaxedJsonEscaping`，落盘直接是可读中文。
6. **配置路径统一**：UXP 连上后发 `{type:'setConfigPath', path}`（getDataFolder().nativePath +
   hotkeys.json），daemon 持久化到 `%LOCALAPPDATA%\JWautofill\configpath.txt` 供开机自启时沿用，
   并自动迁移旧配置。实测落到 `...PHSP\27\External\com.listen2me.jwautofill\PluginData\hotkeys.json`
   （与 license.json / mask-sync-state.json 同目录）。
7. **卸载脚本三个真 bug**：① `$p.Stop()` —— System.Diagnostics.Process 没有 Stop() 方法
   （那是 ServiceController 的），调用即抛「不包含名为 Stop 的方法」，进程停不掉 →
   daemon.err.log 锁死 → 目录删不掉。必须 `Stop-Process -Id`。
   ② `Read-Host` 在非交互/管道下抛异常，会把可选的「是否删配置」询问变成整流程失败。
   ③ 目录删除需重试（文件句柄释放有延迟）。
8. **Start-Process 崩溃**：环境里同时存在 `Path` 与 `PATH` 键时 `Start-Process` 报「已添加项。
   字典中的关键字:"Path"」。已改三级回退（带日志重定向 → 不带重定向 → `cmd /c start`）。
9. **ps1 必须纯 ASCII**：WinPS 5.1 按 GBK 读无 BOM 的 .ps1，中文注释直接造成语法错误
   （`[Parser]::ParseFile` 报「表达式或语句中包含意外的标记"}"」）。用它可做提交前语法门禁。
10. **UI 调整**：守护进程状态条复用蒙版同步的 `.mask-sync-status-bar` 样式，同行右侧放
    「加载/断开守护进程」；加载=静默运行随插件分发的 install.bat（不再弹文件框）；
    断开=WS 发 `{type:'shutdown'}` 让 daemon 优雅退出（卸载前必须先断，否则 exe 锁文件）；
    卸载移到面板右上角菜单（alpha 采样后加分割线），成功 5 秒倒计时关窗、失败保留窗口。

## 2026-08-29 第二轮：快捷键从未注册的根因 + 卸载按钮无反应（提交于 aeafe1b 之后）

1. **根因（最重大）**：Program.cs `_configPath` 初始值是 `""`，`DefaultConfigPath` 定义了却从未赋值使用 → SaveConfig 抛 `The value cannot be an empty string (Parameter 'path')` → hotkeys.json 从未落盘 → 快捷键从未注册过。定位方法：前台运行 daemon 重定向 stdout，跑 analysis/hotkey/ws_raw_test.mjs（手写原始 TCP WebSocket 客户端），日志直接暴露错误。修复：无有效路径参数时回落 DefaultConfigPath。
2. **叠加 bug**：System.Text.Json 默认大小写敏感，UXP 推 `{id,combo,action,brush}` 小写键反序列化到 PascalCase 属性全部为空 → 快捷键即使落盘也注册不上。修复：统一 JsonOpts（CamelCase + PropertyNameCaseInsensitive=true）用于 config 的序列化/反序列化/广播；UXP 端 normalizeEntry 双向兜底。
3. **Broadcast 帧长度 bug**：原来硬编码单字节长度（假设消息<126B），改用 SendToClient 的完整长度编码。hotkey 广播新增 combo 字段。
4. **卸载按钮无反应**：用户从 dist 加载插件，dist 里没有 native/HotkeyDaemon/uninstall.bat → getPluginFolder 定位失败 → openBundled 抛异常 → uninstallDaemon 无 try/catch 全部吞掉。修复：整体 try/catch + 找不到脚本时退化为文件选择；webpack 拷贝 bat/ps1/exe 进 dist（glob 模式 to 必须带 [name][ext]，否则保留源路径）。
5. **面板热键触发反馈**：onHotkeyTriggered 回调 → 面板显示「热键触发 ✓/✗」，用户可直接观测事件是否到达（无显示=事件没到；✗=batchPlay 失败）。
6. 新 daemon exe 已编译部署到 %LOCALAPPDATA%\JWautofill\daemon（md5 417E…）+ dist；端到端验证通过（推送→落盘→回读全链路 OK，中文 \u 转义正常）。
7. **环境限制**：本会话沙箱会回收所有后台子进程（Start-Process/setsid/schtasks 均无法持久拉起 daemon，schtasks 还被安全策略黑名单禁），daemon 启动需用户点面板「安装守护进程」选 install.bat 或重启电脑（HKCU Run 自启）。
8. 之前录制的快捷键实际从未保存成功，需用户重新录制；hotkeys.json 里留了一条 Ctrl+Alt+K→多线混合 的测试条目可直接验证。

## 2026-08-29 第五轮：标点/小键盘快捷键可录制验证（请求 #7）+ 钩子回调 I/O 冻结修复

1. **请求 #7 结论：分号 `;`、单引号 `'` 等标点键 + 小键盘键现在都可作录制快捷键**。本轮实证验证通过：
   `Ctrl+Alt+;` `Ctrl+Alt+'` `Ctrl+Alt+[` `Ctrl+Alt+]` `Ctrl+Alt+\` `Ctrl+Alt+/`
   `Ctrl+Alt+`` ` `` `Ctrl+Alt+,` `Ctrl+Alt+.` `Ctrl+Alt+-` `Ctrl+Alt+=` `Ctrl+Alt+NumPlus` `Ctrl+Alt+Num3`
   共 14 个组合键全部 `热键命中` 并被 WS 广播收到（监听端 `hit_listener.mjs` 解析到 `{type:'hotkey'}`）。
2. **验证方法论（关键）**：`WScript.Shell.SendKeys` 走 `VK_PACKET`（Unicode 注入），低层钩子的 `KeyToToken`
   对 OEM 标点返回不到 VK → 之前所有 SendKeys 标点测试都是假 MISS。改用自编译 .NET 注入器
   `analysis/hotkey/KeyInjector`（真实 `keybd_event` 虚拟键）才测准。另写了 `analysis/hotkey/KeyMapTest`
   做 `KeyToToken`/`ParseCombo` 往返一致性自检（标点+小键盘全过）。
3. **我的测试脚本曾掩盖真相**：`hit_listener.mjs` 握手分支结束后漏了 `return`，导致同一帧被重复拼接、
   帧解析错位 → 明明守护进程已 `热键命中` 监听端却报 MISS。修正握手分支后复测才确认 daemon 一直正常。
4. **修了一个真实 daemon 缺陷（2026-08-29.5）**：低层键盘钩子回调里直接 `Console.WriteLine` 写日志
   （同步文件 I/O）。一旦写入卡顿会冻结整个钩子，表现就是「日志停更 + 按键全无反应」。
   改为回调只 `Enqueue` + `PostThreadMessage` 通知主线程，主线程出队后做日志与广播。
