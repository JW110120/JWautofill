## 2. 新增【笔刷大小预设】开关（Shift+[ / Shift+] 三档跳笔尖直径）

用户口径：开关在 APP 面板「自定义快捷键」里；开启后，当前工具是**能改笔尖大小**的工具时，
Shift+[ 立刻减小、Shift+] 立刻增大，步长远大于 PS 原生 `[ / ]`；三档按用途分（画线/铺块面/涂背景），
以 A4 为基准 4/50/100 px，系数下限 0.5× ⇒ 2/25/50，上限 4× ⇒ 16/200/400，横竖文档不作区分
⇒ 用文档**像素数**算系数。

### 关键决策：**本次没有改 .8li**

`.8li` 对除 `blendHotkey` 外的 action 一律只透传、热键表按配置逐条注册 ⇒ 只要把 combo 写成
`Shift+[` / `Shift+]`，原生会自动注册（MOD_SHIFT + VK_OEM_4/0xDD）并广播回来，
`action='brushSizeStep'`、`brush='down'/'up'` 原样带回。代价：开关期间这两条键被插件独占
（PS 原生「Shift+[ = 减硬度」让位），名单外工具按下无动作。**收益：不需要重编 .8li / 不需要重启 PS。**

### 档位公式（三锚点全部精确命中，已用 node 验算）

`P_a=2480*3508(A4@300,8.70MP)`、`P_min=1MP`、`P_max=8000*5000(40MP)`，`k` 分段对数插值：
- px ≤ 1MP ⇒ 0.5×（2/25/50）
- 1MP…A4 ⇒ 0.5→1.0 对数插值
- A4…40MP ⇒ 1.0→4.0 对数插值（斜率 ×2）
- ≥40MP ⇒ 4×（16/200/400）

实测：A4⇒4/50/100；A3(17.4MP)⇒8/94/188；12MP⇒5/67/134；24MP⇒10/126/251。

### 为什么改直径绕：只用「整份 cto + 只改 brush.diameter」

`set brush to {直径}` 会把笔尖换成 computedBrush（铁律 49/60）。三种 set 写法按验证通过顺序记忆：
① `set {_ref: 当前工具id}` ② `set property.currentToolOptions + application` ③ `set brush targetEnum`。
判据 = 回读直径到位 **且** `sampledData` 没变。

### 两个面板同时收到热键 ⇒ 两道闸

原生广播给所有客户端（`#app` / `#pixeladjustment` 各一条 WS），同一次按键两个 JS 上下文都跑
`handleHotkey`。① `settings/brush-size-step.lock` 用 `createFile(overwrite:false)` 当互斥量（1.5s 残留可抢）；
② 状态文件存 `{token, tier}`，token = 原生 `seq`，后到者只会把**同一目标档位**再写一次（幂等）。
另加 180ms 重复抑制挡键盘自动重复。

## 3. 用户复测：按 Shift+[ / Shift+] 全无反应 —— 根因是工具读数为空（已修）

日志（`debug/special-mask.log`）133 行全是同一句：`笔刷大小·跳过 | {"reason":"当前工具不能改笔尖大小","tool":"未知"}`，
`dir` 有 ±1、`token` 是原生 seq ⇒ **热键链路完全正常**，死在执行体第 ② 步工具闸门。

根因：`readToolId()` 当时只读 `app.currentTool`（同步直读）——**PS 27 上这个 UXP 属性是空/不可用**
（`get currentTool` 那条 batchPlay 更是报 -25920，`brushstudio/psMixer.ts` 早有注释）。
⇒ 每次返回 null ⇒ 闸门永远判「未知」⇒ 功能整体不动作。

修法（`src/utils/BrushSizePreset.ts`）：
- `readToolId()` 改 `async`，主路走 `get application.tool._enum`（`HotkeyBridge.getSelectedBrushToolEnum`
  同款 descriptor），经 `psRead(..., {retries:0})` 进模态作用域（热键常落在落笔/抬笔那一拍，裸 get 会弹宿主框）；
- 形态归一后**只接受 `/Tool$/i`** 的串（`d.tool` 取不到时退到 `d` 本身），`app.currentTool` 降为最后兜底；
- `readCto` 失败不再静默：新增 `笔刷大小·读工具状态失败`（带 errs 与 cto 的 keys 前 6 个）。

## 4. Shift+E 改为「置开启」（不再循环翻转）

用户口径：连按 Shift+E 必须一直保持清除模式开启。旧实现是 toggle（连按两次就关）。

- `ClearModeBus`：事件加 `want: boolean`；`requestClearModeToggle(token)` → `requestClearModeSet(token, want)`；
  订阅回调签名变 `(want) => void`。
- `app.tsx`：新增幂等的 `setClearMode(next)`（`prevState.clearMode === next` 直接不改），
  `toggleClearMode()` 收成一行调用它；Shift+E 那条订阅改调 `setClearMode(want)`。
  面板上的勾选/开关仍走 toggle（人的主动操作才允许关）。
- **订阅时刻闸**：`subscribeAt` — 只执行 `ev.ts + 200 >= subscribeAt` 的命令，
  否则面板重载时会把上一次按键的旧命令当新命令执行（置位版会出现「面板一开清除模式自己亮」）。

## 5. 第二次复测：工具读数已通，卡在 `set` 不在模态作用域（已修）

新日志（重启后）证明第 ③ 步已好：`笔刷大小·读工具状态形态 {form:0}` +
`判据 {tool:"pencilTool(铅笔)", from:15, target:50, tiers:[4,50,100], docKey:"62:2480x3508"}`。
新报错三种 set 写法**完全同一句**：

```
Event: set may modify the state of Photoshop.
Such events are only allowed from inside a modal scope.
```

⇒ 裸 `batchPlay` 的 `set` 被宿主一口拒。修法（`src/utils/BrushSizePreset.ts` 的 `applyDiameter`）：
set + 回读**一起**塞进 `runAsModal(() => { await bp(desc); return await readCto(toolRef); },
{ commandName: '笔刷大小档位' })`。
回读留在模态内的两个理由：① 刚写完的一瞬 `psRead` 的宿主忙粗筛常判真，会把成功误判成「回读 0px」；
② 模态内 `psRead` 自动降级直读（`ownModalDepth`），不会嵌套模态（UXP 禁止嵌套）。

**教训归类**：`get` 可以裸发，`set` 一切写操作必须 `runAsModal`（本仓 psAccess 头部早有此条，
写功能前先搜一遍 `psMixer.setTipDiameter` 这种同动作的已验证实现，能省一整轮真机试错）。

## 6. 清除模式加「退出快捷键」：H / Shift+H 关闭清除模式

背景：第 4 轮把 Shift+E 改成「只开不关」后，清除模式失去了用键盘退出的路（用户报）。
用户口径：「按 H 以及 Shift+H 会关闭清除模式」。

配置实况（`PluginsStorage/.../PluginData/hotkeys.json`）：
`main_toggle` = **H**（=「选区填充」行）、`fill_tool_cycle` = **Shift+H**（=「切换选区填充」）。

实现（`src/hotkey/HotkeyBridge.ts`）：
- 新增 `requestClearModeOff(token)` → `requestClearModeSet('clearOff|' + token, false)`；
- `toggleMain` 分支（H）与 `fillToolCycle` 分支（Shift+H）各调一次，**放在守护/切工具之前**；
- ⛔ token 必须带独立前缀 `clearOff|`，否则与 `focusClear` 的开启命令撞 token，
  ClearModeBus 会当成「同一次命中已处理」直接跳过。
- 帮助文案：`funcHotkey.mainRow` / `fillToolCycleRow` / `clearRow`（clearRow 同时纠正了
  「切换开/关」的旧说法，改成「只开不关 + 出口是 H / Shift+H」）。

⛔ 未加：L（套索工具）/ M / Shift+M 目前**不**关清除模式 —— 用户只点名 H 与 Shift+H。
要扩就照 `requestClearModeOff` 同一行加，别再改 ClearModeBus。
