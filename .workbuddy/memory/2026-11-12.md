## 0x0230（10:19）｜「Shift+E 后第一笔被吞」真凶 = **断流期僵持 tip=1**（0x022F 面板改动无效）

**① 用户复测 0x022F（jwwh-27164 / 10:06–10:09）**：仍吞笔，并给出决定性规律——
「正常模式按 Shift+E **切为清除模式**时，我特意让笔远离数位板，第一笔照样被吞；
再按一次 Shift+E **关闭**清除模式、笔拿回来画的第一笔**反而不吞**」。

**② 关键判读**：这条规律同时否掉两条旧假设——不是「工具切换」（0x022F 已删仍吞），
也不是「笔没抬起」（笔刻意移开仍吞）。而「让笔远离数位板」恰恰**制造了断流**：
驱动停包 ⇒ 走合成包通路 ⇒ 吞笔就发生在合成包上。

**③ 铁证（jwwh-27164 `[catchup]`，笔已离开板面）**
- `10:07:34.944 断流=2750ms tip=1 hold=0 btn=0 idle=2750ms keep=0 grace=0`
- `10:07:39.160 断流=1344ms tip=1 hold=0 btn=0 idle=1344ms keep=0 grace=0`
四条独立证据（无 MSE 推断 / 左键电平没按下 / 光标静止 2.7s / 输出已收敛）都在说
「笔走了」，**只有 tip 还在硬撑 1**。同一时刻 `[raw] 现值=(...,p=0,tip=1,in=1)` =
合成包正以 tip=1 喂 PS。

**④ 根因**：`cursamp_thread` tip 链里 `if (!tip && g_lastRealTip == 1) tip = 1;`
（0x0126 为「断流期补流要有非零压力」而写）**无任何阳性证据**，最长撑
`SYNTH_TIP_MAX_MS`(6s)。0x0126 当时的结论是「抬笔后光标不动 ⇒ 合成包坐标不变 ⇒
PS 画不出新东西，**无害**」——真机证伪：**「没画出东西」≠「无害」**。
合成包持续宣称 buttons 按下 ⇒ PS 始终认为这一笔没结束 ⇒ 用户回来落第一笔时真实包
tip 从 1 开始（中间没有 0 的包）⇒ **收不到 pen-down 边沿** ⇒ 新一笔根本不开始 ⇒
整笔吞掉（套索＝「画了个圈，PS 里毫无现象」），抬笔再落才恢复。

**⑤ 改动**（`native/JWautofillHost/smooth_engine.c`，只加不改）
- 常量段：`SYNTH_TIP_HOLD_MS 400` / `SYNTH_TIP_STILL_MS 400` / `SYNTH_TIP_HARD_MS 2000`
  + `g_catTipDrop` 计数。
- `cursamp_thread` 在**所有 tip 来源之后**（g_penDown / g_lastRealTip / MSE 推断 /
  长停摆续命）加最后一道守卫：`tip && realAge>400 && !btnHeld &&
  (realAge>2000 || !grace) && idleMs>400` ⇒ `tip=0`（同时清 `s_hold`）。
  ⛔ 四条缺一不可：`!grace` 保「停笔等线追上来」继续喂（0x022D/0x012B 核心场景）；
  `btnHeld` 读 1 即手还按着不放弃；`HARD_MS` 防 `grace` 在断流期被冻在 1。
- `[catchup]` 追加 `tipDrop=`；清零时另打 `[raw] ★僵持 tip 清零：…`。
- `plugin_main.c`：`jw8li_version` → **0x0230** + 完整复盘。
- ⛔ 未动：`g_lastRealTip` 本身、MSE 包外证据链、长停摆续命、喂入冻结、代投节流、
  `canvas_hit_ok`、HUD、面板；`CFG_NLONGS` 仍 61；`jwwh_version` 仍 0x013A。

**⑥ 验证与部署**：`build.sh` 零告警；PiPL 往返一致；导出表 5 项；
`jw8li_version` 字节 `b8 30 02 00 00` ✅；379904 B。PS 未运行 ⇒ 已覆盖部署到
`C:/Program Files\Adobe\Adobe Photoshop 2026\Plug-ins\JWautofillHost.8li`（10:19）。

**⑦ 复测要点**：① 首行 `插件版本(.8li)=0x0230`；② 笔移开 + 按 Shift+E + 回来画第一笔
应**不再吞**；③ 日志应出现 `[raw] ★僵持 tip 清零` 且 `tipDrop` 递增；
④ **不能出现**「停笔等线追上来时线冻住 / 笔画被折断」——若出现，说明 `!grace`
判据被绕过，要看 `[catchup]` 的 `grace/lagAx`。

## 0x0231（10:46）｜多边形吸附的两条边缘条件：Alt 期间「笔有没有抬起过」

**① 用户报的两条（同一根因两面）**
- 「按住 Alt，但笔并没有抬起过」⇒ 套索仍是套索（没临时切多边形）⇒ 吸附不要生效、不要 HUD。
- 「按住 Alt，笔尖没立刻抬，而是继续画了一段曲线才抬」⇒ HUD 起点落在**按 Alt 处**，
  应在**抬笔处**（截图：红圈=按 Alt、蓝圈=抬笔，青色参考线却从红圈拉出）。

**② 根因**：整条吸附链**从不知道笔抬没抬**。锚点在「Alt 第一拍」就建立
（`g_strokeGate==1 && s_gpOn` ⇒ 取圆心），而 PS 的多边形套索**只在笔悬空后**才成立。
0x021B 只为「解冻补线」搬过锚，**抬笔本身从未被当成搬锚时机** —— 可对 PS 来说，
抬笔才是套索→多边形的切换点，折线起点就落在抬笔那一点上。

**③ 改动**（`native/JWautofillHost/smooth_engine.c`）
- 新增 `g_polyLift`（1 = 本轮 Alt 已见抬笔）+ `g_polyLiftEvt/N` + `poly_touch_track()`
  （包路径**无条件**记「最近 buttons=1 的包」到 `g_pktTchMs`，该槽定义前移）。
- `poly_snap_gcp` 开头（工具闸门之前）跑状态机：Alt 按下时笔还压着 ⇒ lift=0 + `exit(4)`；
  之后每拍 `poly_pen_pressing()`，抬笔那一刻置 1 **并 `poly_anchor_push()`**
  （取真实光标 = 抬笔位置，置位与搬锚必须同一处）。会话建立新增 `moved` 支（放在
  `btn` 之后），以该点为锚点，本拍原样放行。
- 接触电平（`g_pgTouch`）维护**前移**到会话建立之前 —— 否则「会话不建 ⇒ 电平不更新
  ⇒ 判不出抬笔 ⇒ 会话永远不建」死循环。
- 三个入口加 `!g_polyLift` 门：`poly_snap_run`（包吸附）/ `poly_pkt_click`（接触钉住）/
  `poly_hint_live`（参考线）。
- `poly_snap_gcp_exit` 开头清 `g_polyLift`（早于 `!s_pgOn` 早退）；why 新增 **4 = 笔还没抬起**。
- 诊断：`[alt] 本轮吸附结束` 加 `｜抬笔定锚 N 次` + 收摊原因第 5 项；定锚时另打 `★抬笔定锚`。
- ⛔ 不动：冻结（0x0214）、角度吸附算法/容差、三通道钉点、锚点推进 owner 规则、
  `canvas_hit_ok`、HUD 显隐闸门、面板。`CFG_NLONGS` 仍 61；`jwwh_version` 仍 0x013A。

**④ 验证**：`build.sh` 零告警；PiPL 往返一致；导出表 5 项；
`jw8li_version` 字节 `b8 31 02 00 00` ✅；381440 B（10:46）。
⚠️ **PS 正在运行（PID 19440）⇒ 尚未部署**，退出 PS 后才能覆盖
`C:/Program Files\Adobe\Adobe Photoshop 2026\Plug-ins\JWautofillHost.8li`。

**⑤ 复测要点**：① 首行 `插件版本(.8li)=0x0231`；② 按住 Alt 一直画（不抬笔）⇒
**无吸附、无参考线**；③ 按住 Alt 继续画一段再抬 ⇒ 参考线起点在**抬笔处**（蓝圈），
日志有 `★抬笔定锚`；④ 正常逐点画多边形（悬空按 Alt）行为不变；⑤ 收摊原因不应长期

## 11:05–11:15（0x0232）抬笔点错位 + 按住笔拖动＝又变回套索

**用户报**：① 0x0231 生效（Alt 期间不抬笔已无吸附/HUD）；② 但「第一次抬起」时 HUD 起点
错位（截图：青线在折线末端而不是起点）；③ 画两段折线后一直按住笔不放（PS 变回普通
套索），吸附与 HUD 仍错误生效。

**取证（逐像素解码截图，不靠肉眼）**：青线 x≡436、y 454→621（1px 竖线）⇒ 锚点
(436,454)；黑线抬笔点 ≈ (450,385)（PS 自己的橡皮筋细线从那里起）；光标 ≈ (436,615)。
锚点落在「抬笔点 → 光标」的**路径中间** ⇒ 结论：锚点是在**抬笔之后**才读的光标。

**根因**：`poly_pen_pressing()` 靠 `POLY_TOUCH_FRESH_MS`(120ms) 超时判抬笔，而
`poly_anchor_push()` 现读光标 ⇒ 手已滑走 69px。且「笔压着吗」的判据被**手写了两份**
（`poly_snap_gcp` 内 pktFresh 150ms + `poly_pen_pressing()`），必然漂移。

**改动**（`native/JWautofillHost/smooth_engine.c`）：
- `poly_touch_track()` 另记最新一包 buttons 电平（`g_pktLvl`/`g_pktLvlMs`，定义提前）。
- `poly_touch_step(btnHw)` 取代 `poly_pen_pressing()`，成为 `g_pgTouch` **唯一**写者：
  硬件btn → 「buttons=0 且 `POLY_TOUCH_UP_QUIET_MS`(40ms) 内无按钮包」立刻抬笔 →
  按钮包新鲜(120ms) → 硬件镜像 → 兜底抬着。
- `s_liftX/Y`：`!g_polyLift` 且压着时逐拍记录；抬笔那拍用 `poly_anchor_push_at()`
  发布它（新增函数，`poly_anchor_push()` 变成它的薄封装）。
- 采样刹车：`poly_pkt_says_up()` 一为真就停止记录（`pressing` 还要再等 40ms 才变 0）；
  `poly_msg_apply` 的 `WM_LBUTTONUP` 把 `m->pt`（= 抬笔点）直接写进 `s_lift*`（最准的一路）。
- 消息路径只做「按下即置位」，**不做**电平清除（8ms 空档会把 `g_pgTouch` 打成 0）。
- 多边形支新增拖动判定：接触起点 `s_dragX/Y`，位移 > `POLY_CLICK_HOLD_PX` ⇒
  `poly_snap_gcp_exit(5)` + `g_polyLift=0`（抬笔自动复位）。
- ⛔ **试过又撤回**：给 `poly_hold_run()`（冻结）加 `!g_polyLift` 门。冻结不是吸附而是
  平滑交接 —— 关掉它，「画到一半按 Alt」的笔画里会多出一条 20~60px 长直线（新瑕疵）。
  保留冻结，但抬笔那拍先作废 `g_polyAnchorReset`（冻结解冻推的中途锚点更错）。
- `g_polyLift` 定义前移到 `poly_hold_run()` 之前（保留，供日后判断）；`kWhy` 扩到 6 项；
  `jw8li_version` → 0x0232。

**验证**：`build.sh` 零告警、PiPL 往返一致、导出表 5 项、`b8 32 02 00 00`、382464 B（11:16）。
⚠️ **PS 正在运行（PID 22516）⇒ 未部署**（`Plug-ins\JWautofillHost.8li` 仍 0x0231 / 381440 B）。

**复测要点**：① 首行 0x0232；② 按住 Alt 画一段再抬 ⇒ 青线起点与 PS 橡皮筋**同点**；
③ 画两段折线后按住笔拖 ⇒ 无吸附无 HUD，日志收摊原因「按下拖动→套索」；抬笔后恢复；
④ 正常逐点画多边形行为不变（点选时不误判拖动）。
