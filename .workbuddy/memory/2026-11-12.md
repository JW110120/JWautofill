## 0x0230（10:19）｜「Shift+E 后第一笔被吞」真凶 = **断流期僵持 tip=1**（0x022F 面板改动无效）

**① 用户复测 0x022F（jwwh-27164 / 10:06–10:09）**：仍吞笔，并给出决定性规律——
「正常模式按 Shift+E **切为清除模式**时，我特意让笔远离数位板，第一笔照样被吞；
再按一次 Shift+E **关闭**清除模式、笔拿回来画的第一笔**反而不吞**」。

**② 关键判读**：这条规律同时否掉两条旧假设——不是「工具切换」（0x022F 已删仍吞），
也不是「笔没抬起」（笔刻意移开仍吞）。而「让笔远离数位板」恰恰**制造了断流**：
驱动停包 ⇒ 走合成包通路 ⇒ 吞笔就发生在合成包上。

**③ 铁证（jwwh-27164 `[catchup]`，笔已离开板面）**
- `10:07:34.944 断流=2750ms tip=1 hold=0 btn=0 idle=2750ms keep=0 grace=0`
- `10:07:39.160 断流=1344ms tip=1 hold=0 btn=0 idle=1344ms keep=0 grace=0`
四条独立证据（无 MSE 推断 / 左键电平没按下 / 光标静止 2.7s / 输出已收敛）都在说
「笔走了」，**只有 tip 还在硬撑 1**。同一时刻 `[raw] 现值=(...,p=0,tip=1,in=1)` =
合成包正以 tip=1 喂 PS。

**④ 根因**：`cursamp_thread` tip 链里 `if (!tip && g_lastRealTip == 1) tip = 1;`
（0x0126 为「断流期补流要有非零压力」而写）**无任何阳性证据**，最长撑
`SYNTH_TIP_MAX_MS`(6s)。0x0126 当时的结论是「抬笔后光标不动 ⇒ 合成包坐标不变 ⇒
PS 画不出新东西，**无害**」——真机证伪：**「没画出东西」≠「无害」**。
合成包持续宣称 buttons 按下 ⇒ PS 始终认为这一笔没结束 ⇒ 用户回来落第一笔时真实包
tip 从 1 开始（中间没有 0 的包）⇒ **收不到 pen-down 边沿** ⇒ 新一笔根本不开始 ⇒
整笔吞掉（套索＝「画了个圈，PS 里毫无现象」），抬笔再落才恢复。

  `btnHeld` 读 1 即手还按着不放弃；`HARD_MS` 防 `grace` 在断流期被冻在 1。
