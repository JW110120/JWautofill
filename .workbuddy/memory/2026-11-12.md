## 0x0230（10:19）｜「Shift+E 后第一笔被吞」真凶 = **断流期僵持 tip=1**（0x022F 面板改动无效）

**① 用户复测 0x022F（jwwh-27164 / 10:06–10:09）**：仍吞笔，并给出决定性规律——
「正常模式按 Shift+E **切为清除模式**时，我特意让笔远离数位板，第一笔照样被吞；
再按一次 Shift+E **关闭**清除模式、笔拿回来画的第一笔**反而不吞**」。

**② 关键判读**：这条规律同时否掉两条旧假设——不是「工具切换」（0x022F 已删仍吞），
也不是「笔没抬起」（笔刻意移开仍吞）。而「让笔远离数位板」恰恰**制造了断流**：
驱动停包 ⇒ 走合成包通路 ⇒ 吞笔就发生在合成包上。

**③ 铁证（jwwh-27164 `[catchup]`，笔已离开板面）**
- `10:07:34.944 断流=2750ms tip=1 hold=0 btn=0 idle=2750ms keep=0 grace=0`
- `10:07:39.160 断流=1344ms tip=1 hold=0 btn=0 idle=1344ms keep=0 grace=0`
四条独立证据（无 MSE 推断 / 左键电平没按下 / 光标静止 2.7s / 输出已收敛）都在说
「笔走了」，**只有 tip 还在硬撑 1**。同一时刻 `[raw] 现值=(...,p=0,tip=1,in=1)` =
合成包正以 tip=1 喂 PS。

**④ 根因**：`cursamp_thread` tip 链里 `if (!tip && g_lastRealTip == 1) tip = 1;`
（0x0126 为「断流期补流要有非零压力」而写）**无任何阳性证据**，最长撑
`SYNTH_TIP_MAX_MS`(6s)。0x0126 当时的结论是「抬笔后光标不动 ⇒ 合成包坐标不变 ⇒
PS 画不出新东西，**无害**」——真机证伪：**「没画出东西」≠「无害」**。
合成包持续宣称 buttons 按下 ⇒ PS 始终认为这一笔没结束 ⇒ 用户回来落第一笔时真实包
tip 从 1 开始（中间没有 0 的包）⇒ **收不到 pen-down 边沿** ⇒ 新一笔根本不开始 ⇒
整笔吞掉（套索＝「画了个圈，PS 里毫无现象」），抬笔再落才恢复。

**⑤ 改动**（`native/JWautofillHost/smooth_engine.c`，只加不改）
- 常量段：`SYNTH_TIP_HOLD_MS 400` / `SYNTH_TIP_STILL_MS 400` / `SYNTH_TIP_HARD_MS 2000`
  + `g_catTipDrop` 计数。
- `cursamp_thread` 在**所有 tip 来源之后**（g_penDown / g_lastRealTip / MSE 推断 /
  长停摆续命）加最后一道守卫：`tip && realAge>400 && !btnHeld &&
  (realAge>2000 || !grace) && idleMs>400` ⇒ `tip=0`（同时清 `s_hold`）。
  ⛔ 四条缺一不可：`!grace` 保「停笔等线追上来」继续喂（0x022D/0x012B 核心场景）；
  `btnHeld` 读 1 即手还按着不放弃；`HARD_MS` 防 `grace` 在断流期被冻在 1。
- `[catchup]` 追加 `tipDrop=`；清零时另打 `[raw] ★僵持 tip 清零：…`。
- `plugin_main.c`：`jw8li_version` → **0x0230** + 完整复盘。
- ⛔ 未动：`g_lastRealTip` 本身、MSE 包外证据链、长停摆续命、喂入冻结、代投节流、
  `canvas_hit_ok`、HUD、面板；`CFG_NLONGS` 仍 61；`jwwh_version` 仍 0x013A。

**⑥ 验证与部署**：`build.sh` 零告警；PiPL 往返一致；导出表 5 项；
`jw8li_version` 字节 `b8 30 02 00 00` ✅；379904 B。PS 未运行 ⇒ 已覆盖部署到

**⑦ 复测要点**：① 首行 `插件版本(.8li)=0x0230`；② 笔移开 + 按 Shift+E + 回来画第一笔

## 0x0231（10:46）｜多边形吸附的两条边缘条件：Alt 期间「笔有没有抬起过」

**① 用户报的两条（同一根因两面）**

  ⇒ 判不出抬笔 ⇒ 会话永远不建」死循环。
- 三个入口加 `!g_polyLift` 门：`poly_snap_run`（包吸附）/ `poly_pkt_click`（接触钉住）/
  `poly_hint_live`（参考线）。
- `poly_snap_gcp_exit` 开头清 `g_polyLift`（早于 `!s_pgOn` 早退）；why 新增 **4 = 笔还没抬起**。
- 诊断：`[alt] 本轮吸附结束` 加 `｜抬笔定锚 N 次` + 收摊原因第 5 项；定锚时另打 `★抬笔定锚`。

  `canvas_hit_ok`、HUD 显隐闸门、面板。`CFG_NLONGS` 仍 61；`jwwh_version` 仍 0x013A。

**④ 验证**：`build.sh` 零告警；PiPL 往返一致；导出表 5 项；

  硬件btn → 「buttons=0 且 `POLY_TOUCH_UP_QUIET_MS`(40ms) 内无按钮包」立刻抬笔 →
  按钮包新鲜(120ms) → 硬件镜像 → 兜底抬着。

- 采样刹车：`poly_pkt_says_up()` 一为真就停止记录（`pressing` 还要再等 40ms 才变 0）；

- 消息路径只做「按下即置位」，**不做**电平清除（8ms 空档会把 `g_pgTouch` 打成 0）。
- 多边形支新增拖动判定：接触起点 `s_dragX/Y`，位移 > `POLY_CLICK_HOLD_PX` ⇒
  `poly_snap_gcp_exit(5)` + `g_polyLift=0`（抬笔自动复位）。
- ⛔ **试过又撤回**：给 `poly_hold_run()`（冻结）加 `!g_polyLift` 门。冻结不是吸附而是
  平滑交接 —— 关掉它，「画到一半按 Alt」的笔画里会多出一条 20~60px 长直线（新瑕疵）。
