### 5. alpha 上下对齐 v7：推倒重写成「全局平台基准」（用户要求 1）
用户判断「上下对齐逻辑过于复杂导致始终有遗漏，可以采取众对齐的算法设计」→ 确认走**全局平台基准**。

- **根因**：v1~v6 是"逐像素环带搜索 → 找到参照才写、找不到就 `continue`"，链上有 **5 处** continue/return 65535
  （平坦拦截、高端簇无达标、簇≈自身、中位数回退被禁、flatAll 二遍跳过）⇒ **结构性漏网**，v6 只补掉一处（92%）。
- **新算法**（`processAlphaAlign` 全量替换，约 240 行 → 判据全为"计数 + 区间填充"）：
  1. 参照域 = 选区包围盒 + `ALPHA_ALIGN_HALO(117)`（与旧环带可达范围同口径）→ 一次直方图（`a ≥ MIN_ALPHA`）；
  2. **平台** = 直方图上计数达标的连续水平段（代表值取段内计数最大），阈值 `max(PLATFORM_MIN_ABS 8, maxHist×0.15)`；
     无平台时退化到众数（= 众对齐取法）；
  3. `downT/upT[256]` 预计算表 → 目标 = 同侧最近平台（落差 ≥ `PEAK_THRESH`）；
  4. 三条判据：**平台保护** / **方向归属**（只动偏离"主体水平"——计数最多的平台——的那一侧）/
     **渐变带保护**（与目标平台之间填充 ≥ `hist[a]×2` 且 > 4）。
- **⚠️ 方向归属是加出来的**：第一版没有它，实测硬边素材上对齐把交叉凸起 173→195（更深的层），
  粗糙度 0.539→0.710 —— 方向做反。加上后上对齐在该素材 = **0 改动**。
- **实测**：硬边合成 420×300 下对齐 173→110、221→195，**5760/5760 全处理、零遗漏**，
  粗糙度 0.539→**0.000**（v5 0.615 / v6 0.200）；软笔刷 300×200 回归：core 150 与羽化 38/75/112
  **逐档 100% 不变**（`150:3318→3423` 恰为改动数），仅 105 个"交叉区偶然值"归位，粗糙度 7.181→7.224。
  `_p_orig`（截图恢复的面板图，167 个 alpha 值）→ 0 改动（全被渐变带保护拦下，属抗锯齿饱和素材）。
- **取舍（已写进 refs）**：整片偏高内容占到 ~15% 以上会自成平台被保护（语义上它是"另一层"）→ 归**众对齐**；
  要让它被上下对齐吃掉就调低 `PLATFORM_MIN_RATIO`。

  排除办法：缩小选区 / 先清理那些像素。（v9 的规模门槛本可拦住，但那是被否掉的方向。）
- ⚠️ **最小值必须从 `a ≥ 32` 起算**：否则 AA 尘埃会当"最浅档"，下对齐把整片压成近乎全透明。
  实测 `_real` 的 min=32 只有 116px 就足以让整片 mean 74.2→29.5。用户自己的稿 AA 全在 32 以下（域内全 ≥82）⇒ 无副作用。
- ⚠️ **恢复素材不是用户真实稿的极值代理**：它是 AA 饱和的（137 个不同档），真实画稿只有 4~8 档。
  只可用来对齐 console 的平台列表与计数（候选/域内像素数）。判断"真实稿会不会被孤立极值带走"不能靠它。
- 面板/调用链无需改动：`handleAlphaAlign(direction)` → `processAlphaAlign(..., direction)` 签名未变。
- `ALPHA_ALIGN_HALO` 删前已确认全仓无引用（`Grep` 只命中本文件的注释/常量本身）；面板传**全文档** buffer ⇒ 无分块接缝。
- `tsc -p outputs/tsconfig.tc.json` **exit=0**；webpack `compiled with 3 warnings`（既存）、**0 error**。
- ⚠️ 「计数最多的单档」在连片涂抹的稿子上会落在基准的裙边（+6 档、效果弱）—— 深色群体被拆成多个低计数档时尤其明显。
  备选策略（按簇合并 / 取最深档 / 取最近档）只需改第 5 步那段循环，已写进 refs。
- ⚠️ 工具链：PowerShell 管道里 `Select-String` 过滤 webpack 输出**这次回空**，必须再跑一次不过滤、看尾部
  `compiled with N warnings` 才能确认构建结果 —— 别把空结果当成通过。


## 续 5：用户反馈「v10 对线条上的污渍太激进」→ 新增「极值微调」两个按钮（`processExtremeAlign`）

用户原话：v10 三档整片归一"对色块不透明度统一帮助很大，但对线条上的污渍处理感觉有点激进"，

并且"不仅仅只针对 alpha 通道，还需要对 RGB 通道同样生效"。

### 10. 落地（`alphaAlignProcessor.ts` 新增 `processExtremeAlign`，约 470 行）
- **按钮 ↔ 旧算法映射**：提升下极值 `raiseLow` = v5「上对齐」（只增不减，修偏低/偏淡的斑）；
  削弱上极值 `weakenHigh` = v5「下对齐」（只减不增，修偏高/叠画的斑）。放在
  `renderEdgeProcessingContent` **最下方**（柔化宽度之后，`.divider` + 两颗 `.action-button-5`），与
  「快捷操作」里那三个整片归一按钮**分区**隔开（用户明确要求"边缘处理分区的最下方"）。
- **作用通道 alpha → RGBA**：四通道同一套算法各跑一遍；"属于线条"的闸门恒为 `alpha ≥ 32`；
  每通道用自己的直方图/参照簇/平坦拦截/共识/补判/写回，写回各带方向闸门 ⇒ 一处污渍的颜色与不透明度一起回线色。

  （RGB 没有"层"语义，通道落差本身就是污渍）；② 参照高端区间下界由 `minAlpha` 改 **0**
  （否则深色线条 RGB=30 整个找不到参照）。另加 console 诊断 `护栏拦下=N`。
- **不需要动面板状态链**（无新参数/无持久化）：`handleExtremeAlign(direction)` 直接调处理器，参数传 `{}`。

### 本轮踩坑 / 结论
- ⚠️ **`analysis/line_vis/tsconfig.tc.json` 已不存在**（analysis/ 被清过）⇒ 临时在 `outputs/` 建
