## 蒙版同步（MaskSync）下拉与板块可见性优化

- **板块可见性（初次加载）**：旧 panel-state.json（升级前）缺 maskSync 分区，PanelStateManager.deepMerge 对数组整体替换 → `setSections(ap.sections)` 把默认分区整体覆盖，导致安装/升级后「蒙版同步」板块消失，必须点参数复位才出现。修复：新增 `mergeSections(defaults, loaded)`，在 AdjustmentPanel 加载逻辑里合并默认分区（maskSync 等新增分区默认可见，已保存分区沿用用户可见性/顺序）。
- **样本下拉可选带蒙版图层组**：`renderMaskSyncContent` 样本选项 `selectable` 现包含 `kind==='group' && hasUserMask`；`handleMaskSyncSampleChange` 放宽校验；选中带蒙版组时 `getMaskSyncChannelsForEntry` 仅返回 `['mask']` 并强制 `patch.channel='mask'`。
- **引擎 reconcileTasks 同步放宽**：样本有效类型判定加入 `(group && hasUserMask)`，避免文档切换/重开时把带蒙版组样本引用清掉。
- **层级缩进**：`buildLayerTree` 去掉 label 内联全角空格缩进；改为下拉选项按 `depth` 用 `padding-left: 8 + depth*16` 体现嵌套层级（样本+目标下拉均传 `depth`）。
- 验证：`tsc --noEmit` 改动文件无类型错误；`webpack --mode=production` 构建通过（仅体积警告）。

## 修复：样本/目标选组时报 sample-pixels-failed:Unsupported layer type

- **现象**：样本图层与目标蒙版都选「带蒙版的图层组」时，面板报 `smaple-pixels-failed:Unsupported layer type`（"smaple" 是该 reason 字符串本身的拼写，源首行 491）。
- **根因**：`runSync` step3 对非调整图层都调用 `imaging.getPixels({layerID: groupId})`，而 UXP imaging API 不支持组图层的 getPixels → 抛 "Unsupported layer type"。组样本通道被锁为 `mask`，其来源本就该走 step5 的 `getSampleMaskChannel`（读组蒙版），step3 的像素读取既多余又致命。
- **修复**：`getLayerMeta` 新增返回 `isGroup`（kind==='group'）；`runSync` step3 读取条件加 `&& !sampleMeta.isGroup`，组样本跳过 getPixels，由 step5 的 mask 通道读取组蒙版。诊断日志追加「（组图层·按蒙版通道同步）」。
- 目标为组时仍走 `getLayerMask/putLayerMask`（按 layerID，组也可挂用户蒙版），不受本次改动影响，未触发 getPixels。
- 验证：`tsc --noEmit` 无类型错误；`webpack --mode=production` 构建通过。

## 蒙版同步：目标上锁提示 + 反相功能修复

- **需求1 目标上锁提示**：`getLayerMeta` 新增 `locked`（读 UXP DOM `layer.allLocked || layer.pixelsLocked`，已确认是有效属性）。`runSync` 在读目标蒙版前（新 step6）先取目标 meta，若 `locked` 则返回 `reason:'target-locked'`；`AdjustmentPanel.formatSyncState` 的 reasons 增加 `'target-locked': '目标蒙版上锁，无法同步'`。
- **需求2 反相修复**：原 `runSync` step5 仅对非 mask 通道应用反相（`channel[i]=255-v`），mask 通道（组样本强制 mask）从未反相 → 反相无效。改为 mask 通道读完后也按 `task.invert` 整体取反。差异检测（step8）比较 `channel vs maskRaw`，因 channel 已含反相，开启反相时「无需写入」自然等价于「样本通道 == 蒙版的反相」（满足用户要求的特殊对待）；`unchanged` 结果在反相时附带 `detail:'已按反相匹配'`，reasons 里 `unchanged` 文案改中性「通道内容已匹配目标蒙版，无需写入」。
- 验证：`tsc --noEmit` 无类型错误；`webpack --mode=production` 构建通过。
