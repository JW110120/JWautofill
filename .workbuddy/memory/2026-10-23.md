# 2026-10-23（0x0205：键盘钩子「插件本体在位」闸）

## 背景（用户报）
开发期没通过 UDT 加载插件本体，但 `.8li` 随 PS 装上后照旧默认布防 ⇒ 之前录的
热键（套索 L、NUM1 等）把按键吞掉且无人消费广播（广播无处可送）。用户要求：
**钩子需要插件本体就位才能正常工作**。

## 修（keyhook.c / ws_core.c / plugin_main.c，jw8li_version 0x0204 → 0x0205）
- 新全局 `g_khPlug`（与 `g_khArmed` 正交：布防=用户开关偏好，在位=插件本体生死）。
- 三条键路全部加闸：① 钩子线程安装意图 `want`；② `kh_poll_step` 的 `armed`
  （轮询虽吞不了键，但触发了没人执行=噪声）；③ `kh_hk_sync` 的 RegisterHotKey
  （这一路是真·系统级吞键，NUM1 类裸组合键走它）。`kh_install_hook` 内部也查
  （双保险）。
- 在位判据 = WS 18923 有活客户端（`kh_plug_recompute` 扫客户端表）；建连/断连
  都重算。最后一个客户端断开 ⇒ 钩子线程 ≤10ms 卸钩、≤100ms 撤注册，按键放行。
- ⛔ 不做粘住：面板卸载/崩溃后必须熄火（0x013E unload 哑火同族纪律）。
- **多开 PS 坑（自查发现并修）**：bind 失败的实例每 10s 当"迁移探测"客户端连上
  持有端 ⇒ 会被计成在位，持有端周期性假布防。修：探测走 `path=/jw-migrate`
  （`kh_try_migrate`），服务端 `wc_handshake_path` 抽请求行 path，非 `/` 记
  `KhCli.notPlugin` 不计在位。旧 daemon 不校验 path，迁移链路无损。
- 日志新增：`插件本体不在位（18923 无客户端），不装键盘钩子` /
  `插件本体不在位 ⇒ 卸键盘钩子 + 撤热键注册，按键全部放行` 等，pi8li.log 可判读。
- KH_VERSION "2026-10-17.1" → "2026-10-23.1"（迁移探测只认 2026-10-12 前缀，无碍）。

## 验证
`bash native/JWautofillHost/build.sh` 零告警；PiPL 162 字节往返一致；导出表 5 项
（AutoPluginMain / jw8li_version / jwwh_version / jwwh_set_engine_off / jwwh_unhook）。
真机验收待用户：不加载插件时 L/NUM1 透传；加载后面板开着热键正常、关面板即放行。

## 行为变化（须知会用户）
「在位」= 有面板连着（WS 客户端）。插件加载但面板全关 ⇒ 与旧版相同地收不到广播，
但新版改为放行按键而非吞掉——严格不劣于旧行为。若将来要「面板关着也能用热键」，
正解是把 WS 连接从面板生命周期挪到插件容器生命周期（UXP `entrypoints.setup` 的
`plugin.create/destroy` 钩子），C 侧闸不用动。

## 部署
关 PS → `native/JWautofillHost/build/JWautofillHost.8li` 覆盖进
`PluginsStorage/PHSP/27/External/` → 重启 PS。（未代拷：PS 运行锁文件 + 用户自验惯例）

## UI 四修（同日第四轮）：下拉上翻崩溃 + 开关反差/投影 + 两处折叠区间距

**1. 混合模式下拉上翻「样式崩溃」（用户截图：首项被裁半截 + 右侧 16px 滚动条 + 菜单浮空 45px）**
- 同一根因两副面孔：① UXP `height:auto` 按未取整行盒（≈21.4px/行）算总高、绘制按整像素落行
  ⇒ 内容比盒高几像素 ⇒ 原生滚动条 + 首行被裁；② 「量实测高度再校正 top」读到的是**上一帧**高度
  （151 vs 真实 116），两次迭代同值即判稳定 ⇒ top 停在按 151 算的位置 = 浮空 45px。
- 解法 = 掐掉不确定性：`.select-opt` 改 `height:22px / padding:0 8px / box-sizing:border-box`；
  popOverlay 新增 `POP_ROW_H=22 / POP_DIVIDER_H=5 / POP_CHROME_H=6 / POP_MAX_H=200` + `popContentHeight()`；
  `Select.tsx` 用它在 `reposition()` 算 top、上翻时把高度写进 inline style、够装时 `overflowY:hidden`；
  **删掉整段实测校正 useLayoutEffect**，遮挡判定带也改为纯 pos 推导（不再读弹层矩形）。
- ⚠️ 已写入铁律级的双向同步约束：改行高/padding/max-height 必须同步 popOverlay 常量。

**2. 自绘开关：关闭态反差收敛到 ≈2:1 + 胶囊/手柄各加投影**
- `--control-handle-off-color`：darkest 136 / dark 176（新增，否则继承 :root 掉到 1.2:1）/ light 112 / lightest 138。
- 胶囊从 `:before` 伪元素改真实子元素 `.toggle-switch-track`（UXP 伪元素 box-shadow 未验证），
  投影 胶囊 0.35 / 手柄 0.45。

**3+4. 折叠分区「标题 → 首元素」间距**
- `#app .smooth-mode-trio { margin-top:5px }` 让非紧凑的三列 radio 跟上紧凑模式的 15px。

## UI 一修（同日第六轮）：选区平滑标题行比另两个分区厚

- 根因：`.collapse-header` 的 padding 三者相同（10px 0），差别来自**行内最高子元素**——
  选区平滑标题行塞了 ToggleSwitch，占位盒 24px（为与滑块/数字输入同基线）；
  选区改造/填充选项只有 icon + 13px label（行盒 ≈16~20px）⇒ header 被顶高 4~8px。
- 解法：`.collapse-header-control .toggle-switch { height: 16px }`（= 胶囊本身高度）。
  胶囊 top:50% + margin-top:-8px 相对 16px 盒仍严丝合缝，视觉零变化，只是不再撑高行。
  ⛔ 不要改 padding 硬凑：label 行盒随字号变，压占位盒才是「跟 label 对齐」。
- 验证：guard 通过；tsc 143 = 基线；yarn build 通过。
